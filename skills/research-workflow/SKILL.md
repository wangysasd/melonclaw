# Research Workflow

## Overview

这个 Skill 把研究任务拆成可观察的流程：界定问题、选择最小工具集合、收集证据、整理中间材料，再输出带来源和不确定性说明的中文结论。它只补充研究工作流，不替代工具本身的参数 schema，也不改变项目的安全边界。

## When to Use

- 用户说“研究、调研、查资料、对比、分析”或要求阅读网页、文档和近期信息。
- 问题涉及会变化的版本、价格、政策、市场数据、产品能力或事件。
- 任务需要多次搜索、多个数据接口，或需要把较长材料先放入文件再总结。

简单且稳定的常识问答不必为了使用 Skill 而调用工具。

## Instructions

### 1. 界定研究问题

1. 用一句话明确要回答的核心问题。
2. 拆成 2–5 个可验证的子问题；优先覆盖定义、关键差异、限制条件和用户真正关心的结论。
3. 判断时间范围、地区、数据口径和对象是否明确。缺少会显著改变答案的条件时，先向用户确认；不要用猜测填补关键参数。

### 2. 选择工具

- `internet_search`：搜索公开网页、官方文档、新闻和研究资料。搜索词要短而具体；一个搜索词只解决一个子问题。
- 已启用的 MCP 工具：需要结构化、可复现或领域数据时优先使用。先看工具名称、描述和输入 schema，再调用；不得凭记忆创造工具名或参数。
- 内置文件工具：搜索结果或原始材料较长时，写入运行时目录下的临时文件，后续用 `read_file`、`grep` 或 `glob` 定位，不要把整批原文持续堆在对话里。

只使用完成当前子问题所需的最少工具。实时问题至少获取一条近期且相关的来源；关键结论尽量用官方或一手来源交叉验证。

### 3. 收集和整理证据

1. 记录每条证据支持的具体结论、来源标题或 URL、发布日期（若有）以及可能的适用范围。
2. 区分“来源明确说了什么”和“基于多个来源做出的推断”。推断必须明确标注为推断。
3. 如果来源冲突，保留冲突并解释可能原因；不要挑选看起来方便的结果来制造确定性。
4. 工具返回空结果、权限不足、网络失败或字段缺失时如实记录，不要补造数据。

### 4. 输出研究结果

默认用中文，先给直接结论，再给必要的依据。推荐结构：

1. 结论摘要：2–5 条最重要的回答。
2. 关键分析：按子问题组织，给出比较维度、数据口径和限制。
3. 来源：在相关段落附近给出标题和 URL；不要声称访问了实际上没有读取的页面。
4. 不确定性与下一步：说明时效性、缺口、冲突和可继续验证的方向。

回答长度应服务于问题。不要复制大段受版权保护的原文；使用自己的话概括，必要时只引用很短的片段。

## Guardrails

- 不在回答、日志、临时文件或工具参数中输出 API Key、token、Authorization header 或 `.env` 内容。
- 不把搜索摘要或模型记忆当成已验证事实；没有证据时明确说不知道或需要进一步查询。
- 不把研究中间文件写入仓库的学习笔记、Skill 源目录或其他永久项目文件；使用当前 Agent 配置的临时 runtime。
- Tushare 等金融 MCP 返回的数据必须带上日期和数据口径；不提供投资建议，也不把空结果解释成“没有发生”。
