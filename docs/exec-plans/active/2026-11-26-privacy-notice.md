# 隐私说明与个人信息申请

状态：进行中
开始日期：2026-11-26

## 目标

未登录用户在第一次获取验证码前能打开隐私说明；登录后从「意见反馈」列表下方进入同一申请区。四种申请生成邮件链接。不新增表，不发送真实邮件或短信。

## 背景

短信注册、登录和绑号已经把完整手机号交给阿里云，本地只保存摘要、尾号和短期发码记录。投诉页已有公开邮箱，没有运营主体名称，也没有个人信息申请入口。相关契约：[隐私说明](../../design-docs/privacy-notice.md)、[短信注册与登录](../../design-docs/sms-registration-login.md)。

## 步骤

- [x] 发码前说明、公开页面和登录后的申请入口
- [x] 复用投诉邮箱，只新增运营主体配置
- [x] 文档和测试
- [ ] 运行 `scripts/check.sh` 并记录通过、失败、跳过

## 验收标准

- 未登录时，注册和短信登录在点击「获取验证码」前能看到说明；打开 `/privacy` 不调用发码接口。
- 「意见反馈」列表下方的链接指向 `/privacy#requests`。四种主题正确编码。邮箱缺失时页面没有 `mailto`。
- `GET /api/auth/config` 只返回主体名称和投诉页邮箱，不返回短信凭据。
- 页面写明验证码默认 5 分钟，发码记录在下次发送时清理 48 小时前的行。没有实现的清理期限不写天数。

## 风险与依赖

真实收件需要部署里已经配置并有人值守的投诉邮箱。本次测试不发送邮件或短信。阿里云侧号码保存期限、备份保留期限仍待运营方确定。
