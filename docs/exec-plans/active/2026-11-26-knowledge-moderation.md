# 管理员按知识库停用、恢复和删除

状态：进行中
开始日期：2026-11-26

## 目标

system/admin 能停用整库、从已停用列表恢复或直接逻辑删除，并按库标识核对处置记录。停用后通用访问全部失效，其他库不受影响。

## 背景

知识库已有 active、suspended、deleted、逻辑删除、共享权限查询和同事务事件。见 [知识库设计](../../design-docs/knowledge-base.md)。本次不新增文档级开关、自动审核或发布前审批，也不放宽通用可见性查询。

## 验收标准

- 停用 A 后，同一普通用户不能列出、检索、打开旧引用或下载 A；B 仍可使用。
- 所有者、编辑者、普通用户和非 system 租户调用停用、恢复、已停用列表均被拒绝。所有者不能绕过停用后的读取。
- 管理员能在已停用列表恢复 A；恢复后按当前授权判断。再次停用可直接删除，删除后不能恢复，事件仍可按库标识查询。
- 重复提交和并发处置只留下一条一致的状态与事件。停用会取消该库排队或执行中的作业；发布前复验拒绝停用后的发布。其他库的作业保持原状态。
- `scripts/check.sh` 的结果按通过、失败、跳过分别记录。隔离库用例依赖 `MELONCLAW_TEST_DATABASE_URL`，跳过不计为通过。

## 风险与依赖

真实 SQL 依赖名称含 test 的隔离库和 pgvector。不能把业务库当作测试库。页面交互先用组件测试覆盖；浏览器验收取决于本机 Web 是否可打开。
