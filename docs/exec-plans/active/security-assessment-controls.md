# 安全评估所需控制措施

状态：进行中
开始日期：2026-11-26

## 目标

补齐《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》自评估表点名的六类措施。每项在生产环境实际生效后，才能写入评估报告。空转的开关、未接入的核验接口和未上线的页面不能写成已具备。

## 背景

当前系统由管理员创建账号，用用户 ID 和口令登录，口令保存 scrypt 哈希，删除账号只改状态。对话消息随会话保留。没有手机号或证件核验，没有独立安全审计日志，应用日志约保留 14 天，没有内容安全拦截、投诉工单和按文书导出。`profile=dev` 还提供免密登录和切换用户。网站入口文案仍写“向指定少数好友开放”。

相关契约：[用户管理与登录](../../design-docs/user-management-login.md)、[JWT 登录](../../design-docs/jwt-login.md)、[架构](../../ARCHITECTURE.md)。

## 步骤

- [ ] 确认生产评估环境关闭 `profile=dev`，并改正入口文案，使其与实际开放范围一致
- [ ] 账号增加真实身份资料和核验记录；未核验通过的账号不能登录
- [x] 安全审计写入数据目录下的日志文件，不新增表、不改字段。留存账号、时间、操作类型、源地址、源端口、目标地址、目标端口、客户端特征，至少 180 天。用户发布内容继续用现有消息记录。2026-11-26 已实现；生产 Nginx 需按仓库配置重载后，来源才是访问者地址
- [ ] 账号名称、用户输入和模型输出走内容安全处置，并保存处置记录；维持不提供评论、转发和群组
- [ ] 身份信息加密和脱敏，且不进入模型、Checkpoint 和追踪
- [ ] 增加投诉举报入口、受理记录和结果
- [ ] 增加凭法律文书导出账号、日志和内容的管理功能，导出本身写入审计日志
- [ ] 用已上线行为回填评估表，不提前填写

## 验收标准

- 未核验账号调用 `POST /api/auth/login` 被拒绝；核验通过后可以登录，响应和页面都不回显完整证件号
- `profile` 不是 `dev` 时，免密登录和切换用户接口返回 403
- 登录、发消息、管理操作各在审计文件追加一行，含操作时间、操作类型、源地址和源端口；不出现新表或新字段。180 天内的文件仍在
- 用户删除会话后，六个月内仍能按账号查出原消息
- 内容安全判定为拦截时，消息不进入正常回复，处置表有对应记录
- 已登录用户提交投诉后，管理列表能看到待处理工单，处理后状态和结果仍在
- 管理员导出必须填写文书编号，并留下导出审计；普通用户调用导出接口返回 403
- `uv run melonclaw-db-update` 可重复执行；`scripts/check.sh` 中本次改动对应的后端测试通过

| 2026-11-26 | 身份核验先做“登记并留存核验记录”，供应商在线核验作为同一记录上的回执 | 系统没有自助注册，账号由管理员开设；没有回执号时不得写成已对接公安或运营商 |
| 2026-11-26 | 客户端特征记录 User-Agent、服务端签发的设备标识和浏览器上报的平台，不采集 MAC | 浏览器拿不到网卡地址；评估文字按实际采集项填写 |
| 2026-11-26 | 审计留存以数据库 180 天为准 | 现有应用日志轮转 14 天，且部署说明不把它当审计存储 |
| 2026-11-26 | 审计改写数据目录中的独立日志文件，不改表结构 | 用户要求保存日志且不动表。现有 `backend.log` 只留约 14 天，不能当作这份审计 |

## 风险与依赖

- 证件号和手机号属于敏感个人信息，密钥只走 `core/config.py` 的环境变量，不能写入仓库、日志、模型和追踪。
- 在线实名和内容安全都要外部服务。未配置时，生产评估环境应拒绝放行对应功能，而不是静默跳过。
- 投诉联系方式和执法协助时限是管理制度，代码只负责入口、记录和导出。
- 六个月留存会保留对话正文。清理任务不能按“节省空间”提前物理删除。
- 审计文件和 14 天应用日志分开轮转。站点在 Nginx 后面时，要由 Nginx 传入真实源地址和源端口，否则应用只能看到本机回环地址。
