# 安全评估所需控制措施

状态：进行中
开始日期：2026-11-26

## 目标

补齐《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》自评估表点名的六类措施。每项在生产环境实际生效后，才能写入评估报告。空转的开关、未接入的核验接口和未上线的页面不能写成已具备。

## 背景

立项时系统由管理员创建账号，用用户 ID 和口令登录，口令保存 scrypt 哈希，删除账号只改状态。对话消息随会话保留。彼时没有手机号核验、独立安全审计日志、内容安全拦截、投诉工单和按文书导出。当前实现以[短信注册](../../design-docs/sms-registration-login.md)、[审计日志](../../design-docs/security-audit-log.md)和[投诉举报](../../design-docs/reports.md)为准。`profile=dev` 还提供免密登录和切换用户。网站入口文案仍写“向指定少数好友开放”。

相关契约：[用户管理与登录](../../design-docs/user-management-login.md)、[JWT 登录](../../design-docs/jwt-login.md)、[架构](../../ARCHITECTURE.md)。

## 总体验收标准

以下包含原计划中仍待实施或待验证的事项。本轮补齐的项目以有日期的验证记录为准。

- 未核验账号调用 `POST /api/auth/login` 被拒绝；核验通过后可以登录，响应和页面都不回显完整证件号
- `profile` 不是 `dev` 时，免密登录和切换用户接口返回 403
- 登录、发消息、管理操作各在审计文件追加一行，含操作时间、操作类型、源地址和源端口；不出现新表或新字段。第 184 天的日期文件仍在，更早的日期文件清理
- 用户删除会话后，六个月内仍能按账号查出原消息
- 内容安全判定为拦截时，消息不进入正常回复，处置表有对应记录
- 已登录用户提交投诉后，管理列表能看到待处理工单，处理后状态和结果仍在
- 管理员导出必须填写文书编号，并留下导出审计；普通用户调用导出接口返回 403
- `uv run melonclaw-db-update` 可重复执行；`scripts/check.sh` 中本次改动对应的后端测试通过

## 风险与依赖

- 证件号和手机号属于敏感个人信息，密钥只走 `core/config.py` 的环境变量，不能写入仓库、日志、模型和追踪。
- 在线实名和内容安全都要外部服务。未配置时，生产评估环境应拒绝放行对应功能，而不是静默跳过。
- 投诉联系方式、值守和协助时限由运营方落实。当前协查由授权人员查询和复核，专用导出仍是本计划的后续项。
- 184 天策略针对独立安全审计文件。对话正文的留存与调取要按实际业务数据和正式环境验收记录评估。
- 审计文件和 14 天应用日志分开轮转。站点在 Nginx 后面时，要由 Nginx 传入真实源地址和源端口，否则应用只能看到本机回环地址。
