# MCP 配置一致性与编辑体验优化

状态：已完成
开始日期：2026-10-01

## 目标

工具发现与 Agent 白名单选择一致；健康探测不会把排队当作连接故障；保存、启用与工具可用状态明确。

## 背景

见 [MCP 两层设计](../../design-docs/mcp-two-layer.md)。当前白名单缺失项会使整个服务无法装配，页面却显示正常；探测同时发起且排队计入连接超时。编辑体验和关键状态测试不足。

## 步骤

- [x] 统一工具选择规则，返回缺失项、描述和分类诊断；探测限流、合并和短期缓存。
- [x] 提取健康检测 Hook 与工具详情，稳定卡片顺序，明确使用状态和启用入口。
- [x] 保留已保存白名单，仅连接变化使结果失效；空名单确认与快捷密钥替换。
- [x] 补回归测试，更新说明与设计，运行 scripts/check.sh。

## 验收标准

- 白名单部分缺失时仍只暴露存在的允许工具，页面返回缺失项。
- 排队繁忙与连接超时可区分；并发发现合并，最后订阅者取消时资源释放。
- 前端覆盖保存与启用分离、白名单保留、密钥替换、探测并发和取消。
- 完整检查通过，真实外部服务未验证项明确记录。

## 决策日志

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-10-01 | 白名单取发现目录交集，缺失项警告 | 不扩大授权，不因单个工具移除影响仍存在的工具 |
| 2026-10-01 | 缓存只用于已保存 HTTP/SSE 发现，草稿与 stdio 不缓存 | 不保留草稿秘密，不跳过显式进程启动 |

## 风险与依赖

不新增数据库结构、工具或权限。所有 MCP 业务调用仍审批；发现不调用业务工具。缓存只保存脱敏目录结果，按 id/version 隔离且每次请求先校验权限。真实 PostgreSQL 测试需独立测试连接。
