# Langfuse tracing

状态：已完成
开始日期：2026-10-17

## 目标

通过统一监控入口追踪普通聊天、审批恢复和后台任务，保留现有流式行为和权限边界。

## 步骤

- [x] 复用已安装 Skill，核实官方集成、隐私和最佳实践文档；锁定 Langfuse 5.0.2。
- [x] 实现配置、统一追踪与脱敏；接入聊天、后台任务及历史摘要；停服后排空。
- [x] 补充回归测试、README、架构和设计文档。
- [x] 运行 scripts/check.sh；产生并回读真实 trace，审查层级、标识、用量和脱敏。

## 验收标准

关闭追踪不创建客户端；回调并发隔离；SDK 异常不改变业务结果；凭据与媒体不外发；检查脚本通过。
真实外部验证依赖本地配置的 Langfuse 项目、数据库及可用模型，区分真实模型验收与受控模型验收。

## 决策日志

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-10-17 | 采用官方 LangChain CallbackHandler，不给每个工具手写埋点 | 保留自动层级、用量和错误信息，减少重复观测 |
| 2026-10-17 | 独立 OTel provider，仅导出 Langfuse SDK spans | 避免把 HTTP、数据库或其他仪器收集的内容意外外发 |

## 风险与依赖

开启内容采集会将脱敏后的文本上下文发送到所选区域；规则无法识别全部业务敏感内容，提供只采集结构和用量的开关。
