# 持久数据与代码发布分离

状态：已完成
开始日期：2026-10-07

## 目标
代码发布目录可整体替换，用户文件、Skill、数据库和部署配置独立保留。

## 步骤
- [x] 检查文件落点与数据库路径字段，明确迁移边界。
- [x] 补齐模板安装／目录迁移命令和服务器部署配置。
- [x] 停服核对并清理本机仓库旧运行数据，保留内置模板。
- [x] 更新 README、架构、设计文档和 note，执行全量检查。

## 验收标准
`scripts/check.sh` 通过；复制冲突不覆盖目标；数据库路径审计无宿主机绝对路径；仓库 .data 只保留版本化模板及空占位；生产配置明确外部数据根。

## 决策日志
| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-10-07 | Linux 服务器使用 /var/lib/melonclaw；本地保持 ~/.melonclaw | 不把 Linux 系统目录强加给本地开发 |
| 2026-10-07 | 保留数据库相对路径，不新增升级步骤 | 更换根目录无需修改业务索引 |

## 风险与依赖
真实数据库审计需本地 PostgreSQL；本机服务需短暂停止迁移后恢复。Linux systemd/nginx 配置在本机无法实际运行。LocalShellBackend 仍非安全沙箱，数据目录独立不等于多用户安全隔离。

## 验证结果

全量 scripts/check.sh 通过；8 项部署路径／复制回归覆盖。真实数据库 Skill 22 条均为相对路径且正文存在，Project 和产物索引当前为空，MCP 仓库运行路径引用为 0。本机停服迁移校验后删除仓库旧运行文件 66 个，保留模板和占位；服务恢复，/api/ready 就绪。Linux 配置待目标服务器实测，不对本机安装 systemd 或写入 /etc。
