# 聊天实时输出可见性

状态：已完成
开始日期：2026-10-03
完成日期：2026-10-03

## 目标

模型正文或可读思考到达 SSE 后，下一次前端渲染即可在助手消息主体看见；工具前文字不冒充最终答复，终态仍以数据库快照对账。区分准备、工具选择、模型首段和浏览器展示的等待。

## 背景

当前后端已经投影 `assistant_text_delta` 的正文和 reasoning，前端却只在 `completed` 后把最终正文显示在聊天气泡。运行中的正文位于执行过程，完成后的思考还藏在双层折叠里。工具目录超过 16 项时，主模型前另有一次最多 10 秒的隐藏选工具模型调用。

## 步骤

- [x] 从现有 `assistant_steps` 派生实时正文和思考展示，保持单一来源和终态对账。
- [x] 将实时正文放入聊天主体、可读思考放入独立的可见区域，并覆盖工具、失败、恢复和刷新情况。
- [x] 取得真实时间线，并行读取独立的准备快照，明确工具选择和外部模型等待边界。
- [x] 同步 README、前端/设计文档和 `note/note.md`，运行完整检查。

## 验收标准

- 正文增量到达后，不等 `completed` 就在聊天主体显示；同一段文字不在执行时间线重复出现。
- 工具调用前的文本在工具出现后保留为过程，最终正文只采用服务端终态快照。
- 可读思考增量在生成时可见，终态可直接找到并展开；没有可读思考时不虚构内容。
- 失败、取消、审批恢复及历史刷新不丢已收到的安全展示文本。
- `scripts/check.sh` 通过；真实供应商速度若不可验证，说明依赖与观察点。
