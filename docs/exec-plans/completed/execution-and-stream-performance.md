# 执行与流式展示去重

状态：已完成
开始日期：2026-09-25

## 目标

减少幂等回放、消息准备、流式步骤归约和历史加载中的重复工作，同时保持会话锁、Checkpoint、HITL 与 SSE 终态契约。

## 背景

现有执行服务在抢锁前构建 Agent，终态幂等请求仍构建 Agent；前端每个流事件同步和 React 各跑一次聊天 reducer。消息对有两套写入路径。`docs/ARCHITECTURE.md` 和 `docs/FRONTEND.md` 定义了不可破坏的归属与恢复约束。

## 步骤

- [x] 幂等终态回放跳过 Agent 构建；新请求拿到会话锁后再构建 Agent。
- [x] assistant steps 增量计数并保持原有总量上限。
- [x] 前端按帧合并文本事件，消除可见态 reducer 的重复执行。
- [x] 合并有附件与无附件的消息对事务，避免提交后重读。
- [x] 历史查询只在可能存在待处理交互时构建 Agent，合并独立查询。
- [x] 复用 v3 steps 投影器，并按持有者与等待者清理 Agent 构建锁。
- [x] 验证检查脚本和相关行为，记录剩余性能边界。

## 验收标准

- 终态幂等重试不调用 `agent_for_conversation`，抢锁失败不调用它。
- 幂等回放、锁冲突与取消、步骤快照、历史恢复和前端文本冲刷的隔离测试通过；真实数据库事务测试记录在 D2。
- `scripts/check.sh` 通过，`git diff --check` 通过。

## 决策日志

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-09-25 | 暂保留跨整个 Agent 流的会话锁 | 单独的 assistant 状态 CAS 无法保护 Checkpoint 的并发推进。 |
| 2026-09-25 | 不先引入虚拟列表、Memory TTL 和新锁协议 | 这些改动需要运行时基线或额外一致性设计。 |
| 2026-09-25 | 构建 Agent 时捕获取消并释放会话锁 | 持锁构建增加了准备阶段被取消的窗口。 |

## 风险与依赖

`scripts/check.sh` 与前端生产构建通过。当前 PostgreSQL 的回滚事务已核对无附件和单附件消息对；外部模型和真实并发负载未运行，连接池吞吐仍需量测。稳定设计说明见 `../../design-docs/execution-stream-performance.md`。
