# 短信验证注册与登录

状态：已完成
开始日期：2026-11-26

## 目标

在现有账户、JWT 和租户链路上增加中国大陆手机号的注册、短信登录和首次绑定。成功注册的两条登录路径进入同一个用户、租户和工作区；短信关闭或云服务失败时，原密码登录仍可用。

## 背景

登录原来只有用户 ID 和密码。设计要求用号码认证服务核验手机号，并由服务端把核验结果绑定到一次注册、登录或绑号。换绑、解绑和找回密码不在本次范围。

现行契约见[短信注册与登录](../../design-docs/sms-registration-login.md)。

## 验收标准

- `GET /api/auth/config` 在短信关闭时仍返回 200，并包含 `registration: false` 与 `sms_login: false`。
- 注册成功后，密码登录和短信登录的 `sub` 相同；未注册手机号短信核验通过后不签发令牌。
- 错误码、发送超时、核验 `UNKNOWN`、旧码、跨用途、频控和并发提交都不能多创建一个用户或租户。
- 老用户可首次绑号；重复手机号和已删除用户的号码不能再次绑定；停用租户后的令牌规则与现有密码登录一致。
- 已有用户、密码和租户在升级后保留。`scripts/check.sh` 的通过、失败、跳过和未运行项分开记录。

## 决策日志

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-11-26 | 使用号码认证 SendSmsVerifyCode / CheckSmsVerifyCode，不自建验证码 | 设计指定系统赠送签名和模板，验证码由云端生成并关闭回传 |
| 2026-11-26 | 短信总开关默认关闭，自助注册另有开关且依赖短信 | 未配置云服务时现有部署仍可启动，密码登录不受影响 |
| 2026-11-26 | 只保存手机号 HMAC 和 4 位尾号 | 登录查找不需要明文号码，日志和审计也不保存完整号码 |
| 2026-11-26 | 核验 `UNKNOWN` 视为未通过并允许剩余次数内重试；超时和缺字段结束本次请求 | 官方说明 `UNKNOWN` 是核验失败；超时不能判断验证码是否已消耗 |
