# 环境变量管理与聊天准备性能优化设计

状态：实现完成，2026-10-18 验收；未变更现有部署数据库或运行配置。
本计划保留原始讨论背景；当前事实与协议以[现行设计](../../design-docs/environment-and-preparation.md)为准。
日期：2026-10-17
范围：新增环境变量资源及聊天维护；优化普通聊天 Agent 缓存判断和请求准备。

## 1. 目标与已经确定的取舍

本方案包含两个相关但可以分阶段实施的目标：

1. 用户能够像维护 Skill、MCP 一样维护环境变量，使自己的 Skill 脚本获得所需配置；管理员维护共享变量，个人启用配置覆盖共享配置。
2. 保留 Agent 实例缓存，将配置新鲜度检查从每条消息的数据库／文件扫描改为内存版本比较，并消除同一次请求准备过程中的重复身份与归属查询。

已经确定的规则：

| 事项 | 决定 |
|---|---|
| 环境变量作用域 | 管理员管理 global 共享变量，用户管理自己的 user 变量；管理员不能通过管理接口查看或修改他人的个人变量 |
| 环境变量同名优先级 | 已启用个人值优先；个人项停用或删除后自动使用已启用的同名共享值 |
| 个人使用偏好 | 环境变量不增加 MCP 式的个人偏好层 |
| 基础环境 | HOME、LANG、TZ、LC_* 与系统构造的 PATH 不进入资源管理，不允许页面／聊天覆盖 |
| 值的展示 | 全部按敏感值处理，只写不回显；不提供旧值读取或复制接口 |
| 前端 | 拓展页在技能 TAB 后增加环境变量 TAB，表格管理，正文以 14px 为主 |
| 聊天维护 | 新增／替换必须由用户完整提供 KEY=value；入口先提取和脱敏，再经 HITL 提交；审批卡不填写值 |
| 聊天作用域 | 管理员通过聊天创建 global 系统共享变量，普通用户创建自己的 user 变量；范围由服务端当前身份决定，均须 HITL 审批 |
| 旧透传机制 | 业务变量改为数据库唯一来源，移除默认凭据名单和 MELONCLAW_SHELL_ENV_ALLOWLIST 运行时透传，不增加旧配置回退 |
| MCP 业务规则 | 保持现状：同名来源、个人偏好、停用不回退、工具白名单及审批规则均不改变 |
| Agent 缓存 | 保留，改用内存全局版本与用户版本判断资源是否变化 |
| 身份与归属 | 每个请求实时校验一次，同一次准备过程中复用；跨请求、审批恢复、问答恢复重新校验 |
| 代码状态 | 已完成实现与隔离测试；现有部署升级及管理员录入由部署流程执行 |

MCP 业务规则不变不意味着缓存实现不能优化：MCP 的版本检查纳入新的 Agent 缓存机制，来源选择逻辑继续复用现有实现。

## 2. 当前实现与问题定位

### 2.1 环境变量现状

- `src/melonclaw/__init__.py` 加载部署环境文件。
- `core/defaults.py` 的 `resolve_agent_env()` 从进程环境筛选基础变量、代码默认凭据名及部署白名单，最后剔除硬黑名单。
- `backend/factory.py` 的 `_build_shell_env()` 补充 PATH，构建 LocalShellBackend 时通过 env 注入。
- 当前所有用户共享部署者的业务变量，没有接入用户级配置；函数虽预留 overrides，实际构建未传用户值。

问题是用户上传自己的 Skill 后，需要自己的服务地址、Key 或路径；部署者的固定名单无法支持按用户维护、同名覆盖和页面管理。

### 2.2 Agent 缓存现状

`services/runtime.py:agent_for_conversation()` 在 Web 进程内缓存已组装的 Agent 实例。缓存保存模型客户端、工具、中间件、Backend 和执行图；对话状态由数据库 Checkpoint 按 conversation_id 隔离，业务消息另存业务表。重建 Agent 不会清空对话。

普通会话的工作区键包含 user_id 和 conversation_id；项目会话包含 user_id 和 project_id。因此新建普通会话会构建独立实例，同一用户、同一项目下的新会话可能复用同一实例。不能把所有新会话都假定为必然构建 Agent。

当前键有七项：

| 因子 | 获取方式与成本 |
|---|---|
| 工作区标识 | 从前面已加载的 Conversation／Project 对象在内存拼接 |
| 租户 ID | `get_user_context()` 再查数据库，验证用户及租户有效性 |
| 当前模型标识及版本 | 缓存键属性本身在内存；此前解析模型需要查模型、供应商和有效凭据 |
| 客户端能力 | 请求参数，在内存规范化 |
| Skill 版本标识 | 数据库可见行、目录扫描、SKILL.md 解析、包内文件哈希和文件锁；快照不存在时还会复制 |
| MCP 版本标识 | 查询完整可见配置和个人偏好，再按 ID、version、user_enabled 计算摘要 |
| 模型目录整体版本 | 查询模型与供应商表各自的最大更新时间 |

配置检查发生在准备新消息或恢复执行时，不是每次内部模型／工具调用都发生。当前模型目录、Skill、MCP 三组读取使用 asyncio.gather，但 Skill 中存在同步文件读取及共享文件锁，不能将并行调用理解成没有成本。

缓存命中后无需重新组装模型客户端、发现 MCP 工具或编译 Agent；正常模型调用和 Token 消耗仍然存在。默认缓存容量为 32 个实例，命中提升最近使用顺序，超限淘汰最久未使用实例；同键构建锁避免并发重复构建，MCP 构建失败的实例不缓存。上述语义继续保留。

### 2.3 身份与归属现状

- `api/auth.py` 实时验证 Cookie、Origin、页面身份断言，并把可信 UserContext 放入 request.state.user。
- `services/accounts.py:session()` 分别读取会话、当前身份及租户、原登录身份及租户。
- 聊天服务向下主要传 user_id，`ExecutionService` 和 `ChatRuntime` 又分别解析用户上下文。
- `repository/conversations.py:get_conversation()` 已联查项目并约束项目归属及有效性；服务随后调用 `get_project()` 再取一次项目。

目标是合并与复用这些读取，不取消 Cookie 撤销、租户停用、资源归属及执行互斥的语义。

## 3. 环境变量资源设计

### 3.1 作用域、选择与生效时间

资源以精确变量名匹配，区分大小写。先收集启用的 global 行，再用当前用户启用的 user 行覆盖。

| 个人项 | 同名共享项 | 最终结果 |
|---|---|---|
| 已启用 | 任意状态或不存在 | 个人值 |
| 停用／删除／不存在 | 已启用 | 共享值 |
| 停用／删除／不存在 | 停用／不存在 | 不注入 |

没有个人使用偏好表，也没有阻断共享回退的个人占位。个人配置不继承共享说明或值。管理员关闭共享项只影响依赖共享来源的用户，不影响启用的个人同名项。

配置修改从保存成功后的下一轮新消息生效。已经开始的一轮保留其 Backend 环境；审批或问答恢复属于新的准备请求，按最新可用配置获取 Agent，不保存历史 Key 供重启后恢复。审批中的具体资源写入仍须核对目标版本，不能因恢复而覆盖新配置。

### 3.2 页面展示

采用讨论中的简化展示：普通用户只列出个人资源；共享变量由管理员管理，在运行时自动兜底。个人启用项不再并列展示同名共享记录。管理员保留系统共享管理视图；个人维护入口与共享发布明确区分，页面最终分组随实现评审确认。

表格列建议为变量名、说明、个人启停／实际来源、更新时间和操作。个人项停用且存在可用共享来源时，可显示“个人配置已停用，当前使用系统共享配置”，但不返回共享值。删除前说明是否恢复共享来源。

支持搜索、新增、替换值、修改说明、启停和删除。值统一显示“已配置”；编辑留空代表不替换，不能把遮罩字符串当成真实值提交。变量名创建后固定，改名通过新建和删除完成。新建默认启用状态、说明长度和列表分页参数属于实现前需要固定的表单细节，不能靠隐式推断覆盖旧值。

前端不得把原值放入 localStorage、URL、通知、错误详情或表格数据。刷新／切换用户清除编辑状态。基础环境不占列表行。

### 3.3 校验与运行边界

- 名称满足 `[A-Za-z_][A-Za-z0-9_]*`，同一 global 名称唯一，个人按 owner_user_id + name 唯一。
- 服务端确定 scope、owner 和创建者；客户端不能借字段修改他人或共享资源。
- 保留 HOME、LANG、TZ、LC_*、PATH；平台自身凭据及控制变量同样禁止通过资源注入。复用并集中维护现有硬黑名单，补齐实际平台配置，不把目前列举的少数名字描述成完整凭据隔离。
- 值作为字面字符串处理，不执行 Shell、不展开 `${VAR}`、不允许读取服务器环境。个人值不能引用共享值。变量不是模型凭据配置或 MCP env／headers 的新来源。
- 值、说明和数量有明确上限；环境值拒绝 NUL。空值是否允许必须用显式协议表示，与“未提交值”区分，详见第 11 节。
- 校验错误不回显输入值，包含环境变量请求的 HTTP 验证错误也不能回显原始 body。

最终环境为系统基础环境、启用共享变量、启用个人变量三者合并并经过保留名／禁止名校验。构建 Backend 时显式传入；不得为切换用户修改全局 os.environ。主 Agent 与获准执行 Skill 的子 Agent 使用同一份环境。无人值守 Agent 维持现有受限能力，不因此自动获得 Shell／Skill 或个人凭据；Interpreter/PTC 不扩大能力。

LocalShellBackend 不是安全沙箱。这里实现的是按用户选择性注入，并不保证恶意 Shell 无法访问宿主文件、进程或其他凭据。共享值可被获得它的脚本读取或发送；只写不回显的管理界面不是共享 Key 的保密执行环境。

### 3.4 持久化与接口职责（建议结构）

以下为实施建议，并非本轮已创建的表或 API：

| 数据 | 建议职责 |
|---|---|
| 环境变量资源表 | id、name、description、scope、owner_user_id、created_by、value、enabled、version、created_at、updated_at；作用域约束、唯一约束和版本 CAS |
| 环境变量操作表 | 合并承载聊天暂存、不可变审批清单、预期版本、幂等执行状态及脱敏回执；绑定用户、会话、真实消息／请求、有效期；不复用含 MCP 专有字段的草稿表 |

建议复用 MCP 的凭据存储保护级别：数据库持有真实值，管理 API 不回传。若首版继续明文存储，数据库、转储、备份和暂存操作数据都必须按含凭据数据保护；不声称已经有静态加密。额外引入凭据加密及密钥管理需单独决策，不借本次设计暗中增加部署依赖。

管理接口提供脱敏列表、创建、局部更新、启停和删除。未提供 value 时保留旧值；替换值必须显式提交，所有修改／删除校验 expected_version。普通用户无共享写权限，也没有任意 scope／owner 的写入入口。

运行时读取真实值仅供内部装配，不通过 HTTP 详情、工具结果或可观察字段返回。资源持久化走 repository，权限和合并走 services，Backend 只接收结果，不自行查询数据库。

## 4. 聊天维护与 HITL

### 4.1 简单且明确的输入

新增和替换仅支持用户真实消息中完整的 KEY=value 输入，并且需要明确维护意图。完整赋值先于持久化、模型调用和追踪内容采集进行提取；不把“只要出现赋值就保存”当作意图判断。

建议第一版每次操作一个变量，独立赋值行或明确代码块中按第一个等号切分，值内的后续等号保留，不执行 export、命令替换、Shell 引号求值或环境展开。具体解析语法须固定并测试，不从零散自然语言、附件、Skill 文档、网页或工具输出猜测凭据。

启停、删除或只改说明不需要用户重填旧值，仍须明确指令并经过 HITL。没有完整键值时不能执行新增／替换，只说明需要完整输入；审批卡不另加 value 输入框。

完整赋值但没有维护意图的受支持输入也应先隔离值，再让 Agent 根据脱敏意图判断是否维护，不能为了判断意图先把秘密交给模型。不支持的疑似配置输入采用固定提示并避免原文错误回显；本机制不是任意聊天文本的通用 DLP。

### 4.2 数据与事件流

1. API 入口在请求校验／消息记录／追踪前安全处理配置内容；服务端完成规范化和受控提取。
2. 前端原文只用于本次提交，乐观消息、发送失败回填、会话摘要与后续历史使用脱敏内容；禁止在前端持久化原值。
3. 实时校验用户、会话及项目，确定这是当前用户真实消息。新建范围由当前身份决定：管理员为 global 系统共享，普通用户为自己的 user 资源。暂存记录绑定发起用户、会话和请求，原值只进入受控操作存储；共享资源的 owner 为空，created_by 记录发起管理员。
4. Agent 只看到变量名、用户意图、操作引用及“值已隔离”标记，不获得真实 value。相同 request_id 的不同 value 必须能被识别为请求冲突，不能仅比较脱敏后的正文；不暴露可被穷举的值摘要。
5. 只读 inspect 返回当前身份有权维护的资源元数据、版本及必要的影响，不返回值。准备步骤生成绑定原暂存值、目标、作用域及版本的不可变清单，不改变有效资源；普通用户创建个人同名项时说明覆盖共享，管理员创建共享项时说明全员使用范围。
6. 提交工具在 core/hitl.py 注册，允许 approve／reject；用户确认的是具体操作和影响，审批 args 只含操作引用及脱敏字段。修改目标、值或状态需重新准备与审批。
7. 审批恢复重新校验 Cookie、真实用户、会话、审批批次与助手消息；提交阶段核对草稿归属、有效期、完整清单、目标版本及当前身份对审批范围的权限。身份或权限变化导致原范围不再有效时拒绝旧清单，重新准备，不能自动改为另一作用域后提交。
8. 资源写入及幂等成功回执同事务提交：管理员的共享变更推进全局内存版本，普通用户的个人变更推进对应用户版本，通知完成后再返回“保存成功”。失败或结果不确定时不能宣称已保存。
9. 提交完成后清除暂存明文，保留必要的幂等键与脱敏回执；拒绝、取消、过期草稿有清理流程，不发布有效配置。

操作暂存的 TTL 与回执保留期在实施前固定，建议复用现有聊天配置的有效期量级；幂等键不能在值被清除后立即删除而使旧审批重新执行。可依靠过期绑定拒绝旧操作，不为旧凭据保留无期限恢复能力。

### 4.3 审批卡和工具边界

审批卡展示操作类型、变量名、说明变化、值状态（已提供／保持不变）、启停变化、真实作用域及“下一轮生效”。管理员创建时明确显示“系统共享，所有用户可使用”，共享变更提示依赖该配置的用户将受影响，个人同名启用项仍优先；普通用户创建时显示“仅自己”，并说明覆盖／恢复共享的影响。不显示值、值片段、长度或值哈希，不新增凭据输入框。

只读查询免审批，所有有效配置写入都审批，包括替换值、修改说明、启停和删除。准备只暂存有界数据，不发布资源，因此不进写入审批；正式提交必须经过 HITL。

仅普通聊天主 Agent 获得维护工具，不开放给子 Agent、后台 Agent 或 PTC。模型不能指定用户或任意作用域：新建时服务端按当前身份决定管理员 global、普通用户 user；维护已有项时按资源真实范围及当前权限校验，不能通过聊天修改他人的个人变量。管理员和普通用户的聊天写入都经过 HITL，不因管理员身份跳过。页面由用户直接操作时沿用普通表单权限和删除确认，不额外进入聊天 HITL。

拒绝后 Agent 不得经 Shell、SQL、HTTP 或文件绕过审批。当前 Shell 无沙箱，禁止绕过是工具与应用约定，不声称已经阻断所有宿主执行路径。

## 5. Agent 缓存优化

### 5.1 新的缓存键

保留 Agent 实例缓存、会话 Checkpoint 隔离、构建锁和现有容量淘汰。缓存键改为下列六项：

| 因子 | 正常请求取值来源 |
|---|---|
| 工作区标识（含 user_id） | 本次已校验的 Conversation／Project |
| tenant_id | 本次实时校验的可信 UserContext |
| 模型选择 | 显式模型 ID；没有指定时使用稳定的“默认选择”标记 |
| 客户端能力 | 本次请求；恢复时沿用原消息绑定的能力 |
| 全局资源版本 | Web 进程内存中的递增整数 |
| 当前用户资源版本 | Web 进程内存中的递增整数 |

不把明文凭据或值摘要放入缓存键。默认选择标记必须在类型上与实际模型 ID 区分，不能与用户提交字符串发生碰撞；实际默认模型在缓存未命中后从数据库解析，不更改当前默认模型选择规则。

命中后可从缓存条目取得实际 ResolvedModel，用于本轮模型快照、展示和预算；不能为了这些字段在查缓存之前照旧 resolve_model。显式模型选择、默认变化与个人 Key 更新均受资源版本保护。

旧的当前模型版本、供应商版本、Skill 内容摘要、MCP 配置摘要和模型目录最大更新时间不再逐轮取值。它们对有效性的影响由写操作推进版本来覆盖；配置本身及必要文件校验放到缓存未命中后的加载路径。环境变量也不另建每轮查询摘要。

### 5.2 统一资源版本与失效入口

在 runtime／资源服务边界提供统一进程内通知入口。数据库仍为模型和资源的唯一事实来源，内存版本及配置快照仅是派生缓存，不成为另一套配置来源。它不属于监控模块，也不把 Agent 对象放入 tracing。

| 变更类型 | 推进范围 |
|---|---|
| 共享 Skill／MCP／环境变量新增、更新、删除、全员启停 | 全局版本 |
| 供应商配置、共享 Key、共享模型、全局默认模型变化 | 全局版本 |
| 用户个人 Skill／MCP／环境变量新增、更新、删除、启停 | 该用户版本 |
| Skill／MCP 个人使用偏好 | 该用户版本，保持原业务规则 |
| 用户个人模型、默认选择、个人供应商 Key | 该用户版本 |

这是第一版的粗粒度方案：共享变更可能让实际上未使用该资源的用户也在下一次消息重建 Agent，换取常态判断简单。暂不增加资源依赖图、Redis、数据库版本表、轮询、TTL 或文件监听。

页面、聊天安装、聊天环境变量提交等所有运行时写入口必须覆盖。统一通知应由可审计的服务／事务提交路径承担，不依赖前端刷新。资源导入、清理和修复若会改变运行时有效资源，也属于通知清单。

### 5.3 并发、提交和故障

1. 请求取得当前版本组合后查缓存；未命中才加载资源并构建。
2. 同键沿用现有构建锁；等待后重新检查版本，配置已变化则使用新键。
3. 构建完成前再次核对版本；有变化时不把旧资源实例当成新版本发布，按有界重试重新加载，持续变化则明确失败，不无限构建。
4. 资源事务提交后推进版本，通知完成后才对页面或聊天返回成功。提交与通知的发布顺序需要通过运行时协调边界处理，保证保存成功后开始的新准备请求使用新版本。
5. 若数据库已提交但失效发布失败，应阻止受影响旧缓存继续被选中并返回可核实错误；不得记录警告后仍对外宣称即时生效。提交和失效临界区需处理协程取消，避免中间 await 留下旧缓存。
6. 在配置变更发布前已进入执行的一轮继续持有原实例，不原地修改 env、工具或模型。旧条目按现有 LRU 容量淘汰，不保证立即擦除正在使用实例里的旧凭据。
7. MCP 发现／构建失败实例继续不缓存；按当前故障隔离规则报告，不因为性能优化改变 MCP 失败行为或切换配置来源。

数据库和进程内存不能组成同一个数据库事务，因此实现必须明确上述提交—发布协议并以并发／取消测试验证，而不是假定“commit 后加一”天然无竞态。

### 5.4 部署边界

只承诺当前单 Web 进程。重启后缓存和内存版本重新初始化，首次使用从数据库和运行时 Skill 目录加载，不需要持久化版本号。

运行中不再每轮扫描发现手工 SQL 或文件修改。离线资源安装、升级、数据库维护需按现有停服约定操作后重启；没有明确刷新 API 时不能写成已支持在线刷新。进程外修改、外部数据库会话撤销不靠资源版本传播；身份依然实时查库。

未来多进程需跨进程失效传播与发布协议，不在本次承诺范围。部署环境里的模型共享凭据兜底变化仍通过重启生效，不扩大为业务环境变量透传。

## 6. 每条消息准备阶段优化

### 6.1 身份与归属：一遍逻辑校验、两次主要读取

请求级可信上下文由服务端生成，不允许 API 客户端提交“已验证”标记。API 层将领域数据对象传给服务层，services 不导入 api，也不持有 FastAPI Request。

| 读取 | 合并内容 | 保留语义 |
|---|---|---|
| 第一次主要查询 | auth_sessions + 当前用户／租户 + 原登录用户／租户，原登录身份使用单独 SQL 别名 | Cookie 有效期、撤销、当前身份、原登录身份及其租户有效性；管理权限仍按当前身份 |
| 第二次主要查询 | Conversation + 可选 Project，保留任务会话可见性联查 | 会话 user_id、会话状态、项目 user_id／状态和任务会话可见性；返回完整受控项目工作区信息 |

Cookie、Origin、X-Melonclaw-User 和请求 user_id 身份断言继续验证。既有账户共享／独占锁的边界继续保留，不能为了凑两次 IO 删除锁；管理变更与执行准备的互斥不变。

第二次查询既读取业务对象也检查归属，随后直接复用对象，不再调用 get_project 重复获取；普通无项目会话也仍检查 Conversation 真实归属。

同一次准备阶段，用户、租户、会话与项目上下文传给技能选择、Agent 缓存查找、附件准备和消息创建等需要它们的服务。缓存函数不再自行 get_user_context。只复用校验结果，不跳过附件绑定事务内的权限和状态核对，也不移除副作用提交所需的版本／归属校验。

跨请求、HITL 恢复和 ask_user 恢复重新完成身份与归属读取，不能复用上次 HTTP 的权限结果。普通后台／CLI 或无 Cookie 的内部调用必须经过各自可信服务校验入口，不能凭一个 user_id 构造“已经认证”的上下文。

### 6.2 优化后的消息流程

1. 入口检查来源与输入，按安全顺序提取环境变量／MCP 配置，实时验证身份。
2. 一次联查获得 Conversation 和 Project 及归属结果，生成本次准备上下文。
3. 复用上下文处理待收尾交互；需要实际恢复旧执行时按其单独恢复流程，不把旧权限直接缓存放行。
4. 保留 request_id 首次幂等检查；终态回放直接返回，不获取／构建 Agent。
5. 保留会话执行锁和锁后第二次 request_id 检查；抢锁失败不构建 Agent。
6. 从内存读取版本、规范化模型选择与客户端能力，查找 Agent 缓存。
7. 命中：从缓存取得 Agent、实际模型及 Skill 引用，不查询完整资源、不扫描 Skill 文件。
8. 未命中：解析数据库模型、获取资源、评估 Skill、创建只读快照、合并环境、发现 MCP 工具并构建；版本稳定后缓存。
9. 选择的 Skill 从同版本有效引用验证；若有依赖提示，不额外走旧 resolve_skill 路径重扫全目录。
10. 保留待交互检查、消息对与附件绑定事务、Checkpoint 执行、SSE 和收尾；用真实模型快照落库，不把默认选择标记当作实际模型 ID。

现有 `ChatService._release_stale_user_interaction`、技能选择及恢复入口需要一并审计重复读取，不能只优化 agent_for_conversation 后宣称整条准备路径没有重复 IO。

幂等重试和审批恢复继续沿用原消息绑定的模型选择及客户端能力语义；模型不可用时保持现有显式错误／既定回放处理，不借默认选择标记悄悄换模型。

### 6.3 仍然保留的 IO

“两次主要身份／归属查询”不是每条消息只有两次数据库往返。仍包括账户锁、会话锁、幂等检查、待交互账本、消息写入、附件事务、Checkpoint、Memory、模型及外部工具调用。必要的状态 CAS 和锁后二次检查不是可随意删除的重复工作。

| 情况 | 预期资源准备行为 |
|---|---|
| 缓存命中且资源未变 | Agent 缓存判断自身不增加资源查询、目录扫描、文件哈希或 MCP 发现 |
| 首次使用／容量淘汰／服务重启 | 读取完整配置并构建 |
| 个人资源修改后 | 对应用户下次消息读取新配置并构建 |
| 共享资源修改后 | 各用户下次消息按新全局版本构建 |
| 当前轮执行中修改配置 | 当前轮继续原实例，后续准备请求采用新版本 |
| 终态请求幂等回放 | 保持已有快捷返回，不触发资源加载或 Agent 构建 |

## 7. 模块边界与拟涉及位置

| 层 | 预计调整 | 边界 |
|---|---|---|
| database | schema、校验和顺序升级步骤，环境变量与操作记录约束 | init 建当前完整表；update 保留历史数据；启动不升级 |
| repository | 环境变量 CRUD／CAS／幂等事务；身份联查；会话项目联查 | SQL 只在这里，操作回执和业务写入同事务 |
| services | 环境变量权限／合并／聊天输入处理；准备上下文；资源提交与版本通知；缓存获取 | 不导入 Web 层，模型仍只解析数据库 |
| core | Agent 装配参数、HITL 登记、基础环境和保留规则 | 不自行新增数据库旁路，env 不进入提示词或 tracing |
| backend | 接收明确的运行环境映射 | 不修改 os.environ，不解析用户身份／数据库 |
| api | 认证结果传递、受控表单接口、敏感输入与错误脱敏 | Cookie 为唯一请求身份，客户端字段只是断言 |
| frontend | ResourceView 新 TAB、环境变量表格／编辑、聊天原文脱敏和审批摘要 | 14px、只写不回显、切换身份清空暂存 |

优先扩展现有职责模块；若增加独立包，先更新架构测试依赖规则。无需新项目、独立 Worker 或新的缓存服务。

## 8. 数据库升级与旧机制切换

本轮不执行数据库升级、资源导入或服务启停命令。实施时新增按序升级步骤，事务内创建资源／操作表及约束并记录版本，不重建任务表、不清空其他业务数据。新库由 schema.py 直接创建当前结构。

业务环境变量从旧透传切换前，由管理员盘点实际使用的变量并通过受控管理入口录入共享资源。不得自动导入整个 .env，不打印旧值，不在迁移文件、SQL 示例、终端参数或 Git 中写入凭据。确认必要共享配置已启用后再切换；未录入变量不会从旧名单兜底。

随后移除 DEFAULT_AGENT_ENV_VARS 和 MELONCLAW_SHELL_ENV_ALLOWLIST 的运行时业务透传；保留系统基础环境和禁止注入规则。模型、数据库、监控和现有 MCP 服务器环境引用仍按各自入口工作，不能误删部署环境配置或改变 MCP 全局 `${VAR}` 行为。

实施部署步骤：停止 Web 并按现有约定处理活动运行，备份数据库和外部 Skill 数据；执行 `uv sync --locked`、`uv run melonclaw-db-update`，启动受控管理阶段录入和核对共享变量，再开放使用并验证新轮次。若首次建库则用 `uv run melonclaw-db-init`，不将 init 用作清库或增量升级。

录入与切换的部署顺序需要在实施时固定，避免“新代码已移除兜底但共享配置还未录入”的空档。升级记录须可重入、不重复创建或重复写入资源。新接口、运行行为与升级命令实现时同步 README、ARCHITECTURE、FRONTEND、配置说明及 AGENTS；不主动修改 melonclaw-tutorial Skill。

### 9.1 功能与安全验收

| 范围 | 必须验证 |
|---|---|
| 权限 | 共享仅管理员写；个人仅本人写；管理员不能借接口读他人个人值；伪造 scope／owner 拒绝 |
| 合并 | 个人启用覆盖；个人停用／删除恢复共享；共享停用不影响个人；都停用不注入 |

| 展示 | 表格不含真实值；编辑未提供值保留；普通用户不列出共享资源；来源提示不回显值 |
| 聊天 | 完整格式提取；无意图不提交；缺值不新增／替换；值含等号保留；多个／非法／超限输入安全拒绝 |
| 凭据流 | 乐观 UI、失败回填、消息库、Checkpoint、工具参数／结果、异常、追踪均无受支持输入的原值 |
| HITL | 管理员新建为 global、普通用户新建为 user；审批明确共享／个人影响；approve／reject／过期／取消；清单篡改、跨用户／跨会话引用、版本冲突、身份／权限变化、重复提交及重启恢复 |
| 生效 | 页面和聊天提交都推进版本；当前轮不变，保存成功后开始的新轮采用新配置 |
| MCP 回归 | 来源、偏好、个人停用不回退、故障不切来源、白名单、安装和测试审批全部维持现状 |

### 9.2 缓存与准备阶段验收

- 已预热的同键请求不调用 models_revision、list_visible_mcp_rows、skill_snapshot、content_manifest 或完整环境变量加载。
- 预热命中路径不重新解析完整模型／凭据，不进行 MCP 工具发现；仍返回正确实际模型快照及 Skill 引用。
- 同请求不重复解析用户／租户；归属查询完成后不再单独 get_project；跨请求及恢复重新校验。
- 共享／个人资源、偏好、Key、默认模型变化均失效；无关用户个人变更不失效当前用户；共享粗粒度失效符合约定。
- 会话／项目／用户／租户缓存隔离、模型切换、客户端能力切换、LRU、并发单次构建和失败不缓存保持正确。
- 构建中改配置、事务失败、commit 后取消、失效发布失败均有受控模型及并发测试；不得从旧配置发布新版本缓存。
- 终态回放和抢锁失败不构建；request_id 冲突、附件原子绑定、待交互恢复及 Checkpoint 流程不回归。
- 原登录身份停用／撤销、当前身份切换、密码重置、租户停用、会话删除／移动、项目删除在下一请求正确生效；账户锁和会话锁保护继续有效。

### 9.3 测量方式

使用相同数据规模和受控模型／MCP 比较修改前后；分别记录冷构建、热命中、个人失效、共享失效和并发请求。观察准备总耗时 p50／p95、分阶段耗时、SQL 次数、连接池等待、Skill 扫描及读取字节、文件锁等待、Agent 构建次数和 MCP 发现次数。

现有 preparation_duration_ms 从路由准备计时开始，不包括前面的全局认证依赖。因此认证优化的端到端收益需额外从完整请求边界计时；不能只看既有字段就声称已经测量身份阶段。新增观测只记录计数、耗时和脱敏标识，不写原值、完整配置或缓存对象。

先验证结构目标“热命中不做资源检查 IO”，再用实测决定后续优化。不预设已经达到毫秒级收益，也不把 SQL 数减少直接等同于端到端同比提速。已有状态锁、Checkpoint 与模型网络调用仍可能成为主要耗时。

## 11. 固定的协议与取舍

管理员仅管理共享环境变量，普通用户管理个人项；聊天同样按当前服务端身份决定范围。新建默认启用，允许显式空字符串。名称 128 字符、说明 500 字符、值 8192 UTF-8 字节、每范围 200 项、启用总大小 64 KiB。聊天每次一项，指令在消息开头；赋值支持独立行、行内或完整 env 代码块，保留引号和等号，不做 Shell 展开。含首尾空白或多行值使用管理页。

未决操作 24 小时，拒绝和取消清空敏感暂存，过期每分钟清理；已提交立即擦除 payload，回执 30 天后清空但保留拒重记录。数据库复用 MCP 明文存储保护级别。提交与发布使用进程内锁、shield 与同步版本发布；异常发布使缓存读取失败关闭。

## 12. 实施与验证记录

新增环境变量 schema／增量步骤、仓储、服务、API、拓展表格、聊天入口和 HITL；管理值不回显，主 Agent 显式注入合并环境。现有数据库、.env、用户 Skill 和真实凭据未更改，未调用真实模型／外部 MCP。临时 PostgreSQL 中验证升级、账户联查、权限、同名回退、CAS、幂等、拒绝和过期；实际 Deep Agents 图验证 approve/reject 和 Checkpoint 不含值。

缓存六因子改为工作区、租户、模型选择、能力、全局内存版本、用户内存版本；写入口统一提交／发布。身份一次联查，准备上下文一次会话／项目联查并复用；跨请求和恢复重验。保留账户锁、会话锁、幂等和事务内检查。

受控性能对比使用相同 30 个 Skill（各 SKILL.md 与参考文件）、隔离 PostgreSQL、100 次预热命中，基线从修改前 runtime 读取，模型构建替身不访问网络：

| Agent 获取步骤 | 修改前 | 修改后 |
|---|---:|---:|
| 热获取 p50（ms） | 11.7621 | 0.0010 |
| 热获取 p95（ms） | 14.3271 | 0.0012 |
| 每次热获取 SQL | 7 | 0 |

此计时只覆盖 Agent 获取（基线包含原有提前模型解析），不包含身份、会话、消息写入、Checkpoint、模型调用或外部工具；不将它当作聊天端到端加速比例。身份真实查询计数为一次，带项目会话的准备归属查询计数为一次；热命中不加载环境、不扫描 Skill、不发现 MCP。已有容量、构建并发、版本变更重试、取消／发布故障与失效范围有测试。

验证完成：`scripts/check.sh` 的后端编译、全部测试（含隔离 PostgreSQL）、ruff 与锁文件检查通过；前端补充用例适配现有断言后，`scripts/check.sh frontend` 的 lint、类型检查和全部测试通过。`tests/test_docs_links.py` 与 `git diff --check` 通过。上游流式协议／Interpreter 的 beta 提示和现有 Ant Design／jsdom 提示仍存在，不影响检查结果。

浏览器使用独立临时数据库与临时数据根，验证管理员共享表格、新建默认启用、只更新说明保留旧值、切换普通用户不列出共享项、个人同名覆盖及停用回退，值未出现在表格。首次建库命令在临时库验证成功，保留数据升级步骤在隔离 schema 验证可重入；现有部署未升级。冷构建通过行为测试覆盖，未对真实模型／MCP 冷启动或端到端聊天作性能承诺。
