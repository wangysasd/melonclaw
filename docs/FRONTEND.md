# MelonClaw 前端

前端位于 `frontend/`，是独立的 React + Vite + TypeScript 项目，通过 HTTP 和 SSE 与后端通信。

聊天消息的助手作者名和头像替代文本使用仓库根目录 `.env` 中的 `MELONCLAW_NAME`（默认 `MelonClaw`）。Vite 启动或构建时读取并注入该展示值；修改 `.env` 后按 README 重启前后端。

根目录环境变量 `brand` 为 `rms`（忽略大小写）时，全局导航显示 AMP（A）和 Mindera（M），登录页采用左右分栏布局（左侧浅蓝玻璃环配图、右侧居中 Logo 与精简登录表单，900px 以下隐藏配图），登录页与侧栏字标使用 `melonclaw-word-rms.png`，侧栏字标抵消图片内部左侧留白，使字母 R 位于新建对话按钮左边缘内侧 2px；助手头像改用 `melonclaw-mark-rms.png`，Browser Tab 显示 `RMS · 投研助手` 并使用其 48×48 压缩 favicon。其他值或未设置时隐藏 A/M 并保留现有标题、favicon 和图片。默认 dev profile 读取 `.env`；prod 启动脚本使用 `prod` mode，Vite production build 也会读取 `.env.prod`。启动或构建时显式传入的 `MELONCLAW_NAME`、`brand` 优先于仓库环境文件；Vite 不直接读取后端 `MELONCLAW_ENV_FILE`，只需给构建进程传入这两个公开值，不能把服务端凭据注入前端。改配置后重启前端或重新构建。

## 1. 技术栈与命令

- React 18 + Vite 5 + TypeScript 5.6
- UI：`antd` 6 + `@ant-design/x`（Sender、Bubble 等会话组件）+ `@ant-design/x-markdown`
- 图表渲染：`mermaid`；数据图表：按需加载 ECharts 折线／柱状图与 SVG renderer
- 测试：`vitest` + `@testing-library/react`

```bash
cd frontend
npm install
npm run dev -- --host 127.0.0.1   # 开发模式，Vite 把 /api 代理到后端
npm run lint                      # eslint src
npm run typecheck                 # tsc --noEmit
npm test                          # vitest run
npm run build                     # tsc --noEmit && vite build，产物在 frontend/dist/
```

## 2. 目录职责

| 目录 | 职责 |
|---|---|
| `src/api/` | HTTP 与 SSE 客户端：`client.ts`（JSON 请求封装与错误归一化）、`stream.ts`（fetch + ReadableStream 手动解析 SSE 帧） |
| `src/state/` | 会话级全局状态（`session.tsx`）：用户、Project、Conversation、当前流、`epoch` 失效机制；用户资料含唯一租户信息，不维护独立租户选择状态 |
| `src/hooks/` | 流式消息 reducer 与副作用：`useChatStream.ts` 处理 optimistic 消息、增量文本、审批、断线重同步；`useRunClock.ts` 提供只在运行期开启的运行级计时 |
| `src/components/` | 展示与交互组件（Composer、ChatView、`AgentExecution` 执行过程区域、ToolTimeline 子 Agent 任务卡、审批卡、用户问题卡、技能选择等） |
| `src/types/` | 与后端契约对应的类型：`api.ts` 里的 `Message`、`SendMessageInput`、`StreamEvent` 判别联合 |
| `src/styles/` | 分文件维护的样式：`global.css`、`sidebar.css`、`chat.css` |
| `src/theme/` | antd 主题配置 |
| `src/lib/` | 与框架无关的纯函数工具：`agentRun.ts` 把助手消息归约成 `AgentRun` 展示模型（状态、耗时、有序步骤、最终回答分离） |
| `tests/` | vitest 用例；`setup.ts` 是公共初始化 |

## 3. 与后端的契约

- 请求：`POST /api/conversations/{conversation_id}/messages`，JSON 请求体，字段见 `src/types/api.ts` 的 `SendMessageInput`。
- 响应：`text/event-stream`，由 `src/api/stream.ts` 手动分帧解析（按空行切帧，逐帧解析 `data:` 行）。
- 事件类型以 `src/types/api.ts` 的 `StreamEvent` 判别联合为准。根 Agent 使用 `assistant_step_started`、`assistant_text_delta`、`assistant_tool_call`、`assistant_tool_result`、`assistant_step_completed`，每个事件都带 `message_id`，前端按 `message_id → step_id → call_id` 归约；子 Agent 继续使用任务卡事件。用户问题事件由执行服务直接进入统一 SSE 编码器；如果新增需要从 Agent 原始流投影出的事件，仍必须同步修改后端 `output/events.py`、`api/sse.py` 和前端联合类型。
- 帧序号：服务端每个 SSE 帧都带 `id: N`（单条流内单调递增），`api/stream.ts` 把它作为 `onEvent` 的第二个参数交给 `useChatStream`，用于丢弃重复投递的帧；去重不按文本内容判断。
- 连续的 `assistant_text_delta` 按浏览器动画帧合并后更新可见会话；下一个非文本事件、停止或流结束会先冲刷待提交文本。`completed` 仍立即以服务端完整快照对账。
- 断线重连：不依赖 SSE 缓存，而是靠会话重新同步；`session.tsx` 的 `epoch` 用来丢弃切换会话后迟到的响应。

## 4. UI 约定

以下约定是长期维护的视觉与交互基线，改动前请先确认是否会影响其它页面。

### 侧栏与顶栏

- 展开的聊天侧栏顶部保留字标和收起按钮，顶部内边距 16px、品牌区高 32px；品牌、新建对话、项目、最近会话四块之间统一间距 20px，组内列表保持紧凑；收起后从聊天顶栏左上角展开。Home 只导航，不改变折叠状态；进入拓展隐藏整个聊天侧栏。
- 侧栏「新建对话」采用浅蓝底、蓝色文字和细边框，左侧为对话加号图标，右侧分别显示 ⌘、K 键帽；悬停和按下时蓝色强调加深，键盘聚焦时显示清晰轮廓。
- 欢迎页居中显示品牌字标（RMS 使用 `melonclaw-word-rms.png`，其他品牌使用 `melonclaw-word.png`；图片限制在 240px × 80px 并保持比例），使用 24px / 600 主标题和 12 个快捷提示卡，首张用于了解助手能力；宽屏四列、平板两列、窄屏单列，卡片标题与说明文字均为 14px，不显示额外的品牌问候语与说明文字。提示覆盖研究能力介绍、行业观点、报告检索、A股复盘、财务数据、研究文章、业绩点评、经营假设、盈利预测、个股估值、行业研究和宏观资产分析。
- 会话侧栏固定显示 Projects 与 Recents：打开项目后显示该项目的会话，Recents 只显示未加入项目的普通会话；两个列表各自首次取 10 条并独立分页。滚动条默认隐藏，悬浮或键盘聚焦滚动区域时显示。
- 点击项目行只展开/收起其下的会话，不改变右侧聊天或输入区项目；文件夹图标随展开状态切换。只有会话行有选中状态，选中时只改变背景及文字颜色，不加粗文字。没有项目时，「创建新项目」按钮文字为 13px。项目行右侧“…”后面有新建会话图标，任何项目均可使用；项目内没有会话时，展开区额外显示「在此项目中新建首个对话」。项目和会话行的“…”入口在悬停该行时显示，按钮自身获得键盘焦点或菜单展开期间保持可见，触屏常显；会话时间贴近侧栏右边，悬停时该位置显示“…”入口。菜单文字统一为 14px，可置顶、重命名、删除。普通会话额外提供「移动到项目」级联项，子菜单先列「新建项目」，再列已有项目；项目内会话不显示该项。置顶优先排序，删除需确认，运行中的会话不能删除或移动。
- 输入框上方有一条灰色项目栏，高 32px，项目控件在栏内纵向居中；左右各缩进一个输入框圆角半径，不绘制外层边框，底边与输入框平直的顶部相接。左侧项目控件与灰色栏同色，沿用 13px 次要控件字号和 6px 控件圆角；选中项目时悬停会把左侧文件夹变为叉号，点击叉号退出项目，点击项目名或箭头仍打开选择器。菜单宽 280px，内部文字统一为 13px，可搜索已有项目、新建项目或退出项目。它使用 `session.projectId` 表示当前聊天的项目；侧栏文件夹展开状态独立维护。参考截图中的 Local、main 和 Full access 不属于此功能。
- 「新建项目」弹窗标题统一为 16px，正文和按钮为 14px。
- 模拟用户下拉项只显示用户名，字号 14px，不显示租户数量。
- 切换模拟用户时清理旧会话上下文并使迟到响应失效；模型选择按用户保存在本地。请求只发送 `user_id`，租户归属由后端解析。
- 顶栏靠左显示当前会话名称：项目会话为「项目名称/会话名称」，普通会话只显示会话名称；字号 14px、不加粗、背景色 `#F5F5F7`，最小高度 48px。
- 全局 48px 图标栏的 Home、拓展选中与未选中均使用对称四格图案，选中时黑色填充并以白线分格，未选中时使用线框图标；承载 Home、拓展及底部依次排列的更换用户、系统状态和当前用户头像。更换用户使用独立图标、不显示下箭头；头像菜单向右弹出，顶部显示头像与全名，底部带图标的“登出”撤销服务端登录会话并返回登录页。状态入口显示服务就绪状态，不代表各 MCP 实时连接状态。状态弹窗由 GlobalNav 管理。
- 拓展页顶栏高 49px（32px 内容、上下各 8px 内边距、1px 底边框），与聊天顶栏对齐；左右沿用页面留白，页面标题为 16px / 600、行高 32px。技能、连接器、模型三个 Tab 的图标统一为 18px，视觉高度与文字接近。「技能」标签中的搜索靠左、安装和刷新操作靠右。Skills 与 MCP 卡片标题左侧使用共享的 `AppLogo`：前端按显示名称首字符生成文字标记，并用稳定字符串 hash 选取浅色配色；卡片不增加图标数据字段或静态资源。Skill 卡片左下角继续显示来源与版本。正文预览、文件清单、菜单和范围标题以 14px 为主。列表随页面滚动；全员已停用共享项仅管理员可见，主按钮禁用，需在菜单明确全员启用。
- 模型选择器的下拉选项与选中后展示的模型名称统一为 14px；无可用模型时的说明文字为 12px。下拉按「内置模型 / 自定义模型」分组，每行带供应商 logo（`providerIcons.ts` 映射，`provider_key` 由后端目录条目下发）；底部「添加自定义模型」跳到拓展页模型 TAB；收起态只显示显示名。
- 模型供应商卡片左上角显示公司 logo：`frontend/public/assets/provider-logos/` 下 14 个 SVG（从 Yuxi 引用的 lobehub `icons-static-svg` 下载，映射与背景色/滤镜在 `src/components/providerIcons.ts`，沿用 Yuxi `modelIcon.js` 参数）；`img` 按映射 scale 缩放，单色图标走白色滤镜，彩色 `*-color` 不过滤镜；映射不到的自建供应商回落首字母头像。
- 管理员新增/编辑供应商弹窗左下角提供「测试连接」，按当前表单字段临时请求 Models Endpoint（留空时使用 Base URL + `/models`），只返回发现数量、不保存配置；Key 输入留空会复用已有凭据或指定环境变量。

技能删除确认弹窗标题为 16px，说明文字与取消、删除按钮为 14px。连接器删除确认框居中展示，沿用统一圆角与留白，显示连接器名称、范围和传输类型；按共享、个人及恢复共享场景说明删除影响，取消按钮默认获得焦点。

### 消息区

- 用户消息头像复用导航栏的 `userInitials` 与 `avatarStyle`：显示当前用户的姓名缩写及按用户 ID 生成的配色，不使用固定图片。

- `assistant_step_started` 只建立步骤，不切换为生成回复；正文增量才进入 responding。`waiting_model`、`thinking`、`preparing_tools`、`preparing_file` 分别表示等待模型、已观测到推理、生成工具参数、生成文件内容；参数生成不表示工具已执行。
- 等待首段内容时只显示执行摘要状态和计时，不显示重复的等待占位或空过程区域；收到步骤或工具事件后显示过程。
- 执行过程、工具活动标题、文字正文和代码块使用一致的阅读宽度。
- 可读思考作为执行时间线中的独立条目按生成顺序展示；每段连续思考运行中直接展示，完成后分别折叠。条目与外部使用相同背景、无边框，保留灰色文字。工具前后的思考分居工具两侧，没有可读推理时不显示空条目。
- 完成后有根工具或子 Agent 事件的执行列表默认展开，工具参数和结果仍按条目展开；纯过程文字默认收起。摘要保留阶段与总耗时，不显示单独的耗时明细入口；没有步骤的完成摘要不提供空展开操作。
- 执行步骤和工具活动标题使用 14px 常规字重。
- 用户消息、最终回答和执行过程统一使用 14px；辅助文字（状态、耗时、参数摘要）统一用次要文字色；执行过程的工具条目按类型使用语义图标，具体状态由右侧文字和颜色表达。工具调用与子 Agent 使用统一的摘要行、状态区、箭头和详情排版，所有内容保持左对齐，不额外展示层级线或层级背景。
- 代码块使用系统选中态浅蓝标题底、`#0071E3` 标题文字与中性边框，代码正文为 14px 等宽字体，并与聊天正文保持一致的相对行高。

### 统一视觉规范

基础参数唯一维护在 `src/theme/tokens.ts`，`src/theme/antd.ts` 与 App 内的 CSS 变量共用来源。正文 14px；普通控件 32px / 6px 圆角；卡片 8px 圆角、16px 内边距和间距；Modal 12px 圆角；页面左右留白 24px（窄屏 16px）。完整规则、例外和验证范围见[前端视觉一致性](design-docs/ui-consistency.md)。新增 UI 优先复用这些参数，不重新声明近似尺寸与灰色。

### 设计语言

整体采用 Apple 风格色板：背景 `#F5F5F7`、主文字 `#1D1D1F`、强调色 `#0071E3`；侧栏与顶栏为磨砂效果（backdrop blur）；用户气泡使用 iMessage 蓝；代码块为深色 `#1D1D1F`。

## 5. 行为约定

- **请求标识**：登录通知、消息发送、用户问题回答和附件上传统一调用 `src/lib/requestId.ts`。优先使用 `crypto.randomUUID()`；普通 HTTP 页面缺少该方法时使用 `crypto.getRandomValues()` 生成标准 UUID v4，满足后端 UUID 校验与幂等约束。不使用时间戳或 `Math.random()` 替代。
- 输入区支持 Enter 发送、Shift + Enter 换行；输入 `/` 打开当前 Project 的 Skill 目录，可按 Skill ID、名称、描述过滤，Escape 关闭。
- **Skill 目录**：目录摘要由只读 `GET /api/skills` 提供；选中的 Skill 通过消息请求的 `skill_id` 传给后端，后端会重新校验并让 Agent 按对应的 `SKILL.md` 执行；未选择 Skill 时保持自动发现逻辑。
- **Skill 管理卡片**：使用后端 `effective_enabled/personally_enabled/unavailable_reason/availability`。卡片身份为数据库 `id`，发消息使用 `selection_id`（范围化 ID）。主按钮只负责个人添加或使用；管理员在独立菜单执行「全员启用/全员关闭」，所有用户（含管理员）都可「对我关闭」。菜单还提供下载、上传/远程更新和删除。内容更新先显示正文、文件清单、增删及文本差异、依赖检查，确认时后端重查权限和版本。点击卡片按范围请求完整详情；异常项保留诊断和修复入口。管理员工具栏提供「恢复与检查」。
- **远程安装 Skill**：弹窗不显示右上角关闭按钮；准备下载与校验期间，底部「取消安装」中断浏览器请求并关闭弹窗，中断是正常取消，不显示网络错误。确认安装已提交后不可撤销，弹窗在完成后自动关闭。
- 回复生成中或等待审批时仍可编辑下一条草稿；同会话输出中发送按钮锁定（等待审批时显示“等待确认”，等待问题回答时显示“等待回答”），输出中的会话发送键变为方形「停止生成」按钮，点击显式取消本轮（回车不触发停止）。
- 模型选择从**下一条消息**生效；正在执行的回复和审批恢复仍使用原运行的模型。
- 模型输出期间仍可「新建对话」（⌘/Ctrl + K）。全局入口切到普通会话空白页，项目区域的新建入口切到该项目的空白页；当前已是同作用域空白页时不重复切换。首次发送时才创建持久会话，发送提交后侧栏立即显示临时会话行；首条消息落库后以服务端列表替换，未被接收则撤回临时行；附件暂存可以提前取得会话 ID，但空会话仍不进入列表。左栏切换同一用户下的项目或会话时，原会话的流连接保持不中断，多会话可同时跑；正在跑的会话在左栏显示旋转图标，返回原会话从缓存恢复流式增量继续看输出。切用户仍会中止全部输出。
- 助手文本 content 完整展示：不删除 `<think>…</think>`、未结束的推理片段或形似工具选择 JSON 的正文。流式增量、完成快照、历史加载与 Markdown 使用相同文本；内部工具选择器由服务端在调用源头通过 `TAG_NOSTREAM` 隔离，其 custom 阶段事件沿用 `run_phase` 显示「正在选择工具」和「等待模型响应」。HTML 仍按文本安全渲染，凭据仍脱敏。
- **Markdown 渲染**：使用 Ant Design X Markdown，支持嵌套列表、表格、代码复制、公式和安全 Mermaid 图表。
- **加号二级目录**：加号固定在输入框左下角，模型选择与发送按钮留在右下角。点击加号展开一级目录，含「图片和文件」与「技能」两项；鼠标悬停（或键盘聚焦、方向键）「技能」会在右侧展开二级目录，列出与输入框内输入 `/` 相同的技能列表，选中后直接挂到本轮消息上。目录沿用 `.skill-picker` 的圆角卡片、半透明背景与阴影，没有另起一套样式。点击目录外或按 Escape 关闭。
- 输入框聚焦时外框保持原有中性边框和阴影，不额外出现蓝色描边或光晕。
- **二级目录的收起时机**：只在悬停到另一个一级项、或整个目录关闭（点外部 / Escape / 选中任意一项）时才收起；鼠标离开「技能」这一行**不会**收起，代码里因此不存在任何由 `pointerleave` 触发的收起路径。定位上 `.plus-menu-sub` 是 `position: relative`，二级目录以技能行右边缘为锚点；`padding-left: 16px` 让面板落在一级菜单右边界外 8px（恢复原有间距），同时这段留白属于二级目录自身的盒模型，鼠标途经区域没有无主间隙。
- **附件弹窗入口**：一级目录选「图片和文件」打开「添加附件」弹窗；把文件拖到输入区、或粘贴剪贴板图片时会跳过目录，直接打开同一个弹窗并把文件带进去。
- **添加附件弹窗**：弹窗内可拖拽文件到虚线区域，也可以点击该区域从文件夹多选。普通会话上传到当前会话工作区，项目会话上传到项目工作区；选择后立刻上传并逐项显示文件名、大小与上传状态（失败项显示原因、上传中显示百分比进度），每项都能单独移除；点「确认添加附件」才把附件交给输入区，点「取消」会删掉本次已上传的暂存附件。弹窗里按 `GET /api/attachments/capabilities` 写明支持的类型与大小/数量限制，并在上传前做预校验；服务端仍会重新校验，前端校验只是快速失败。
- **输入区附件卡片**：确认前不占用输入区；确认后显示文件名与解析状态，解析失败或超过轮询上限显示「重新解析」。解析状态按附件 ID 单独轮询并指数退避，最长约 5.5 分钟后停止并标记超时，不会因为每秒回写状态而重建定时器。
- 图片附件在输入区和历史消息里都能点开全屏预览（Esc 或点击空白关闭）；非图片附件显示类型角标（PDF / XLSX / PPTX 等）便于区分。
- **Agent 执行过程**：一次 assistant 消息 = 一次运行，过程文本、可读思考与工具调用聚合在同一个「执行区域」里，不铺成多个聊天气泡。区域是一行状态/耗时摘要 + 一段与正式 AI 回复左边缘对齐的时间线；过程正文保持普通文本，连续思考各有独立的折叠入口，沿用外部背景且不绘制边框，工具调用按因果顺序插在思考之间。尚未收到 step 时只显示真实阶段与计时。运行期间执行过程强制展开；完成后有工具或思考时默认显示时间线，各思考条目默认收起，可分别展开；只有普通过程文字时默认收起。摘要行显示观测阶段与耗时（如 `正在检索资料 · 1.9s`），并发调用另提示数量；终态显示 `完成 · 耗时 4.8s`。已确认的完整根任务清单提供完成数／总数，可展开查看；未获得清单时不从工具数推算总进度。`failed`/`cancelled`/`interrupted` 保留并展开已产生的过程；历史里仍是 `pending` 且当前没有订阅时显示「执行状态待确认」，不无限显示正在执行。助手消息元信息不重复显示“已完成”等状态。执行区展开/收起箭头位于摘要行最右侧，收起朝右、展开朝下。展开状态只是组件内的临时 UI state，不写入历史、localStorage 或全局 store。纯文字回复仍保留耗时入口；旧历史完全没有步骤、事件和计时时不渲染空执行区域。
- **长任务反馈**：阶段来自所属消息公开事件与活动工具，等待时区分确认／回答；用户离开底部后，消息或工具状态变化显示「有新内容 · 回到最新消息」，点击或回到底部清除，换用户／会话和同步历史也清除。停止说明按实际接收情况列出保留内容、工具完成／失败／待确认结果；终态未完成工具停止转圈。停止不撤销副作用，未确认结果提供只读同步入口。详见 [长任务状态与停止反馈](design-docs/long-task-feedback.md)。
- **过程消息与最终回答**：正在生成的最新无工具根步骤正文在聊天主体作临时预览；若后续出现工具调用，同一步文字回到执行过程。只有后端落库的 `is_final` step 才是最终回答，终态正文由外层独立渲染，不进入折叠容器。`completed` 事件携带服务端已提交的完整 `assistant_steps` 快照，前端终态直接采用它对账此前增量，避免漏帧后丢失工具和中间消息。
- **工具条目与工具目录**：同一步（同一条 AIMessage）的工具按因果顺序直接逐行展示，每个实际调用只出现一次，不再额外套一层重复工具名的活动摘要。系统状态按模型、工具、技能、MCP、其他排序；工具内分文件与工作区、命令与计算、联网搜索、长期记忆、协作与提问五组，技能与 MCP 管理工具移入对应主分类。顶部统计与分类使用同一数据来源，技能与 MCP 目录独立并行加载，加载和失败不显示为零，重新打开刷新。MCP 列出启用与未启用配置，不自动连接检测；`ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`、`execute`、`eval`、`internet_search`、五个 Memory 工具、`task`、`ask_user` 和 `list_mcp_tools` 等固定 Agent 工具使用逐工具语义图标（命令类使用终端图标）。MCP 配置的具体工具由运行时发现，目录只列服务名并明确标记“工具运行时发现”，不猜测工具名称。工具行显示友好名称、一行参数摘要（JSON 取最具代表性的标量，最多占工具行可用宽度的一半，过长时用省略号截断）、状态与耗时（服务端给出单调时钟 `duration_ms` 才显示本次执行耗时，缺失可靠时间时不编造），行尾是展开/收起箭头，收起朝右、展开朝下，整行可点击也支持键盘操作。参数、结果与错误放在展开区里，使用统一的左对齐详情排版和限高滚动。子 Agent 继续由 `ToolTimeline` 负责嵌套归约，但与普通工具共享 `ExecutionNode` 渲染；子 Agent 的输出和子工具按需展开，完成状态统一显示为“完成”，不再使用层级线或独立的大卡片。
- **审批确认卡**：与问题卡共用中性背景、边框和 14px 正文；选项及底部按钮统一桌面 32px 高、8px 圆角，窄屏最小高度 44px；标题明确请求授权，等待徽标说明仅限本次。已知文件操作展示对象和内容／修改前后预览，Shell 完整展示命令与工作目录；这些操作和安装清单的原始参数默认收起，未知操作默认展开。单项允许／拒绝直接提交，编辑／提供结果仍经校验提交，多项逐项选择后统一提交，无默认授权。只有服务端 `message_started(resuming=true)` 确认恢复后，助手消息才保留接收决定的简短记录；记录仅存在当前页面会话缓存，刷新仍以服务端工具历史为准。详见 [聊天确认与问题卡](design-docs/chat-interaction-cards.md)。
- **用户问题卡**：标题为「需要你补充信息」，徽标为「等待回答」；当 Agent 通过 `ask_user` 等待关键决策时，页面显示一张可包含多个独立问题的卡片；每个问题支持单选/多选项和可选的「其他」文本输入，全部完成后一次提交。提交按钮在未全部作答或提交中时不可用，普通消息发送会锁定。刷新会话后，问题卡从历史接口恢复；过期答案由服务端拒绝。卡片额外提供次要按钮「跳过，让 AI 自己决定」（批量卡片为「全部跳过，让 AI 自己决定」），提交 `{ type: "cancelled" }` 后由 Agent 自行收尾。`expires_at` 已过时禁用两个按钮并提示「发送新消息时会自动跳过」，真正的解锁由后端在收到新消息前代答取消完成。

## 6. 部署

生产部署时由 Nginx 或 Node 静态服务托管 `dist/`，并将 `/api` 反向代理到 FastAPI（**SSE 必须关闭缓冲**）。同站跨域直连时用 `VITE_API_BASE_URL` 指定后端地址，后端侧用 `MELONCLAW_ALLOWED_ORIGINS` 放行精确 Origin；CORS 和写请求共享该白名单。Cookie 保持 `SameSite=Strict`，跨站写请求仍拒绝，真正跨站部署必须使用同源 `/api` 反向代理。前后端使用相同协议，开发环境不要混用 localhost 和 127.0.0.1。

- 供应商「新增」入口仅管理员可见。管理员按供应商 enabled 分组，普通用户按 has_my_key 分组；共享供应商已启用不代表当前用户已配置 Key。普通用户填 Key 后可添加个人模型，仅可修改自己创建的模型，共享模型仍可直接用于聊天。

- 供应商卡片的启用绿点固定在标题行最右侧，直径 16px。信息区展示 Base URL，下方以 12px 单行列出已启用模型的显示名称，超长省略，悬停显示完整名称；没有启用模型时显示「暂无启用模型」。底部管理入口保留启用数量，不显示能力和 Key 来源。

- 技能添加或卸载成功后，更新按钮和可用状态但保留当前卡片顺序；手动刷新或重新进入页面时才重新按启用状态与名称排序。

- 已添加且可用的技能卡片主按钮显示「去试试」，点击进入聊天并选中该技能；未添加项管理员显示「对我启用」，普通用户显示「启用」。

- 技能菜单中的个人关闭操作：管理员显示「对我关闭」，普通用户显示「关闭」，均只影响当前用户。

- 供应商卡片的标识标签只显示 provider_key，不展示「共享/私有」；供应商目录的全局管理范围不能用来表示当前用户凭据的共享状态。

- 聊天模型下拉只列出 available 的模型，不展示停用供应商或缺少有效凭据的不可用项；展开宽度为 260px（窄屏限制在视口内），底部「添加自定义模型」为 14px，加号和文字靠左。

- 聊天模型选择器不展示接口调用模型 ID（如 deepseek-flash），选项展示供应商图标与模型显示名。

- 未启用供应商使用紧凑卡片网格：左侧 logo，右侧两行展示名称和灰色 provider_key（14px），不显示模型摘要和管理按钮；整张卡片点击或按 Enter/空格打开现有配置弹窗。

- 供应商编辑弹窗统一 14px，带标签双列字段，小屏单列；状态开关靠右，高级配置默认收起，点击后展开；底部删除（仅手动供应商）、取消、确定；确定按状态开关保存。请求头配置只写不回显，留空保留，`{}` 清空。

供应商信息区的 Base URL 与 Model 使用同宽标签对齐，行间距 4px；管理模型按钮靠左。

供应商编辑弹窗只提供「确定」保存按钮，启用状态完全由表单中的状态开关决定。

- 聊天模型下拉分组标题为 12px；模型行保持 14px，左侧 logo 与分组标题左对齐，取消分组选项额外缩进。

- 管理模型弹窗标题为 16px，操作按钮、搜索输入与占位文字为 14px；远端搜索框占工具栏约 72%（较原约 90% 缩短 20%），候选数量单行靠右。

- 模型下拉的「内置模型」包含系统种子及管理员配置的 global 模型，「自定义模型」只包含当前用户的 user 模型；不显示共享/我的标签。source 仍表示记录创建来源，不用于判定全局模型分组。

- 普通用户「我的 Key」弹窗标题为 16px，按钮、输入与占位提示为 14px；Base URL 独立一行，下方直接显示 Key 输入框，不展示共享 Key / 我的 Key 配置状态行。

- 远端候选模型的创建入口称为「添加」，已有模型显示「已添加」，成功提示使用「已添加」；模型自身的启停开关仍表示运行可用状态。

- 「我的 Key」弹窗每次打开均创建空白输入状态，关闭丢弃未保存草稿；字段声明 new-password 避免浏览器将其当作登录密码回填，已有密钥始终不回显。

普通用户配置个人 Key 后可独立添加和使用个人模型，不受供应商全局 enabled 开关影响；管理员开关仅控制内置模型。个人模型仅使用个人 Key，清除后不可用，不借用共享 Key。连接地址仍由管理员维护。

管理员停用供应商并保存时，会清除数据库共享 Key 和 API Key Env 引用；不会修改部署环境变量或各用户的个人 Key。重新启用需重新配置共享凭据。

无可用模型时保留模型配置入口，显示「请先配置模型」，发送按钮禁用；登录后添加模型即可开始聊天。

模型选择器不随聊天输入框的工作区准备状态禁用；没有可用模型时也可展开，通过底部「添加自定义模型」进入配置页。

模型管理列表提供「删除」按钮，管理员可删除全局模型（包括原种子模型），普通用户可删除自己的个人模型；删除后刷新列表与聊天模型目录。

默认模型按归属独立保存：全局一个、每个用户一个个人默认。可用的个人默认优先于管理员内置默认；个人默认不可用时使用内置默认，两者都不可用时优先首个可用内置模型，再选个人模型。配置刷新时聊天选择同步服务端默认，用户仍可在聊天中临时切换。

管理员（admin/owner）上传或远程安装 Skill 后存为共享资源，管理页新安装默认停用，需全员启用；普通用户安装的 Skill 仅自己可用。共享 Skill 可由各用户单独停用。安装范围由服务端读取数据库角色决定。

聊天上传支持 archive 类型的 ZIP，不等待文档解析。聊天安装使用现有审批面板，`SkillInstallApproval` 展示名称、来源、个人／共享范围和启用影响（14px）；只允许确认或拒绝。收到安装工具结果后刷新当前用户的 Skill 目录。模型列表为空时提供不依赖 AI 的静态配置指引。详见 [聊天安装设计](design-docs/chat-skill-install.md)。

聊天生成 Skill 沿用同一审批和目录刷新：工具目录新增「生成 Skill 预览」，审批来源显示「聊天生成」，管理卡片显示同一来源，详情将 source_ref 标为「来源会话」。完整内容由准备工具返回并在聊天预览，保存范围按服务端角色确定。详见 [聊天生成设计](design-docs/chat-skill-creation.md)。

### MCP 配置管理（2026-10-01）

McpManager 沿用 Skill 的系统共享/我的分组和菜单。管理员新建自动全局，普通用户自动个人；
停用全局项普通用户不可见。卡片按钮保留加号图标，按钮与菜单管理员显示「对我启用」，普通用户显示「启用」，开启个人使用；个人选择「关闭」（管理员显示「对我关闭」）后，可通过卡片按钮或「…」菜单重新添加。管理员独立全员启停。
McpEditor 提供 JSON 单向导入：解析并填充后仅编辑表单，多个服务先选择一个，重开不回显 JSON
和密钥。支持 HTTP/SSE，管理员额外支持 stdio。测试连接按钮在底部左侧，取消/重置/保存在右侧；默认新建停用。
接口集中在 api/mcp.ts，导入解析在 lib/mcpImport.ts；不写 localStorage，不把 JSON 交给模型。
系统状态工具目录按当前用户有效 MCP 列表刷新，工具具体名称仍运行时发现。

MCP 卡片仅展示配置的使用状态，不显示连接状态胶囊，列表加载、刷新及配置变化均不发起后台连接检测。
`McpToolDetails` 的工具项默认折叠，仅显示名称和白名单状态；点击名称展开描述。白名单状态使用 12px、4px 圆角标签：“已允许”为浅绿底、绿色文字及边框，“未允许”为灰色；各行状态统一在右侧、展开箭头前对齐并纵向居中，长工具名在剩余宽度内换行。详情标题、说明、统计和搜索固定在滚动列表上方，Footer 独立固定在底部；列表滚动槽常驻以避免宽度跳动，滚动条默认透明，悬停或键盘聚焦时弱化显示。详情支持搜索和重新检测；HTTP/SSE 在打开详情时发现工具，stdio 只在明确点击后启动。
McpEditor 保留已保存白名单，名称/说明变化不使目录失效；连接字段变化须重新发现，空白名单保存
需要确认。API Key 快捷框可替换已保存 Authorization，新建保存明确提示尚未使用。

### 聊天安装 MCP

聊天输入支持完整 MCP JSON 或一个 JSON 代码块。`lib/mcpChat.ts` 为乐观消息、侧栏摘要和失败回填生成脱敏占位；API 仅在本次消息请求发送原文，服务端提取持久草稿，历史正文只保留草稿编号和块外意图，不在前端持久存储配置。`McpInstallApproval` 使用既有 14px 审批样式，显示个人范围、脱敏地址、工具白名单、全局同名覆盖影响和启用选项；测试另行说明发送凭据，不支持编辑审批参数。管理页和工具目录重新打开会读取新配置。


## 6. 固定结果组件

`Markdown.tsx` 在既有 Markdown 渲染中识别明确的 `melon-result` JSON 围栏。`resultBlocks.ts` 校验数据，`ResultBlockView` 选择图片／文件、数据图表、结构化表格、差异或来源组件；解析失败保留原始文本，不执行 HTML／脚本／模型提供的图表 option。`ResultProvider` 提供页面身份和会话范围，`ResultCitationScope` 为每段 Markdown 生成来源锚点。附件 ID 走现有 API，成果虚拟路径仅从 `/outputs/` 经受控只读接口取得元信息与内容。

图表与默认折叠的数据表共用 rows；普通 Markdown 表格也支持复制 TSV／下载 CSV，导出处理公式文本、引号和换行。`TextDiff` 同时用于结果与审批预览；Mermaid 保持安全校验并支持源码切换、放大和 SVG 导出。图片加载失败可见并可重试，外部图片不自动加载。详细协议和验证见 [聊天结果组件](design-docs/chat-result-components.md)。

## 会话／项目文件浏览器

`ArtifactWorkspace` 在当前用户／会话范围内管理列表与预览，正文文件链接、`ResultAsset` 和回复末尾 `MessageArtifactCards` 进入同一面板。产物卡片只显示文件名、类型和大小，不显示内部路径；最终回答的 file 结果块由 `ResultCitationScope.fileCardsAtEnd` 抑制原位置重复卡片，消息正文原文不变；图片和图表保留正文展示。服务端 history／completed 返回派生引用，完整产物列表走 `/artifacts`，不依赖聊天最近 50 条消息。

顶部「文件」默认打开 `WorkspaceFileBrowser` 的「全部文件」，浏览当前会话实际所属的会话／项目工作区；项目名称来自当前会话归属，不使用侧栏展开状态。「本对话产物」保留完成回复的交付列表。默认根视图合并登记附件、outputs 直接子项和其他工作区根项，隐藏上传附件与 outputs 包装目录；附件／输出项行尾显示来源胶囊，同名项按实际引用分别保留。真实子目录按需原位展开，各来源独立支持 200 项分页；已加载项按文件夹优先、名称排序，不显示当前目录搜索和排序菜单。不提供根目录或祖先路径导航，左侧提供刷新，文件范围用右侧单选 segments。首屏可见时 5 秒轮询，翻页后可明确刷新；导航、身份改变和关闭取消旧请求。文件列表和单个当前文件使用平级标签，切换保留目录、分页和滚动；从消息卡片直接打开时，列表从根层级按需展开文件所在目录并定位到对应页。关闭面板后保留当前会话的选择，重开恢复；切换用户或会话由组件 key 清理。

`hooks/useWorkspaceFileListing.ts` 组织根目录、登记附件和 outputs 的独立分页、错误／重试、轮询与隐藏恢复；根目录和附件并行读取，确认 outputs 存在后读取其第一层，来源失败不遮蔽成功项。`lib/workspaceFileListing.ts` 映射来源行，以路径／附件 ID 合并并对已加载项排序，不合并同名文件或目录；目录来源标签不推断交付所属。

`lib/workspaceFiles.ts` 的浏览引用独立于模型 `AssetRef`：`workspace_path` 仅由只读目录接口产生，成果 JSON／Markdown 引用仍受 `/outputs/` 或真实附件 ID 约束。目录列表不推断交付来源；匹配本对话交付索引时才显示定位回复。没有编辑、删除或快照入口。

`ArtifactPreview` 懒读取内容，HTML 仅使用专门受限响应及 `sandbox="allow-scripts"` iframe，源码作为文本显示。切换源码时隐藏 iframe 而不卸载；后续交付只提示刷新。元信息在同一身份／交付批次内按引用合并，预览内容不跟随流式文本重读。关闭、切换和刷新释放 Blob URL 并中止请求。

`artifacts.css` 提供桌面宽度调整、1100px 以下覆盖布局、放大状态、14px 正文与窄屏 44px 控件。覆盖状态设置聊天区 inert 并管理可见按钮和范围 segments 的焦点；退出返回触发入口。定位旧回复时 `useChatStream.loadMessage` 分页补入历史，不覆盖已有流式消息或触发 Agent。详见 [文件浏览器设计](design-docs/workspace-file-browser.md)和[对话产物设计](design-docs/conversation-artifacts.md)。

## 聊天错误与附件反馈

`error` 和 `message_status` 事件的错误码保留到消息。模型异步调用边界标记 `model_execution_failed`，工具报告失败也可以从已保存的调用结果展示；其他执行错误保持通用分类。客户端断线标记 `network_disconnected`，显示待确认并保留部分回复。`reloadHistory` 只读取历史，不重发整轮；同会话查询失败不清空已有内容。`FailureNotice` 复用执行轨迹的工具摘要。

`Composer` 在发送前独立检查每个附件是否就绪和图片模型能力，文字不能绕过检查；解析状态查询失败持续轮询到上限。`AttachmentDialog` 保留上传失败文件供重试或移除，重试沿用上传幂等键。详细边界见[聊天错误恢复与发送前反馈](design-docs/chat-error-recovery.md)。

代码与 Mermaid 标题栏共用浅蓝选中态。Mermaid 不显示重复的内置工具栏，图形、源码、放大、导出 SVG 和复制代码集中在图表左下角，使用 12px / 28px 的次要文字按钮；触屏保留 44px 点击区域。


## 回复流畅性与思考显示（2026-10-03）

`assistant_text_delta.content_kind` 区分正文与思考，`assistant_steps.content_blocks` 保存交错顺序；动画帧批量归约只合并相邻同类片段。每段连续思考作为 14px 的独立条目按内容块及模型步骤顺序插入执行时间线，背景与外部一致、无边框，灰色文字不变；运行中直接显示，完成后每段独立折叠，没有可读思考时不显示空条目。最新无工具步骤的正文直接显示在聊天主体，工具调用出现后移入执行时间线；最终正文单独取服务端快照。完成/历史直接采用同一快照。

工具声明 queued 显示「待执行」，实际 running 事件到达才启动客户端等待计时；完成耗时优先用服务端单调时钟 duration_ms。run_activity 汇总在 display_metadata.timings；前端在 streaming 状态也归约活动事件，聊天正文下方显示当前请求/工具时长，执行头部保留运行总耗时；准备、选择、首段内容耗时保留在快照中用于诊断，不显示单独的明细入口。Agent 缓存校验所需的模型、Skill、MCP 快照并行读取。计时只驱动头部组件，不让 Markdown 跟随 tick 重渲染。目录新增「查找可用工具」，仅检索当前允许目录。

供应商弹窗在「高级配置」中按「请求头 JSON → 思考输出格式 → 扩展配置 JSON」排列。格式下拉框提供「标准 OpenAI（默认）」「独立思考字段（DeepSeek）」「正文 think 标签（MiniMax）」「思考详情字段（OpenRouter）」，与扩展 JSON 中的 `_melonclaw.reasoning_format` 双向同步；切换格式保留其余请求字段，JSON 无效时提示错误并保留草稿。控件与配置说明使用 14px。配置仍保存在供应商的 `extra_config`，作用于此供应商的全部模型；`_melonclaw` 不发给供应商，未知格式由服务端拒绝。详见 [回复流畅性与推理协议](design-docs/response-fluency.md)。

### 文件面板简化（2026-10-03）

常规状态仅保留标签行和上下文工具栏。文件范围使用右侧单选 segments；上传附件与 outputs 第一层内容直接进入统一根列表，并显示「上传／输出」胶囊；真实子文件夹点击后原位展开，列表移除来源包装目录和目录导航按钮，已加载项按文件夹优先、名称排序，不显示搜索框或排序菜单，并提供直接刷新。文件列表为 14px 单行，选中用浅灰底。HTML／Markdown 的预览工具栏用单选 segments 切换预览与源码，下载按钮使用 13px，并提供更多菜单；类型/大小、刷新与定位回复位于菜单内。放大且宽屏时可切换辅助文件导航。列表隐藏时中止请求并停止轮询，保留已加载页；预览与文件标签切换保留 iframe，关闭面板释放预览资源，重开读取当前文件。

## 回复末尾的 token 统计

`ChatView` 在已结束的助手回复末尾（正文、产物与状态提示之后，复制按钮之前）用 `MessageUsage` 显示一行输入／输出 token 合计，字号为 14px、使用次要文字色。`lib/modelUsage.ts` 按 call_id 合并开始/结束和历史恢复，汇总主模型、工具选择、摘要与子 Agent 的已报告数字；真实零值保留，完全未报告时不显示，统一显示为 `输入 xxxxx | 输出 xxxxx`，部分上报通过悬停提示说明仅汇总已报告用量。运行中不显示末尾统计。执行区过滤 `model_usage` 和 `context_usage`，不再显示“模型用量”展开区、请求次数、分类明细或上下文估算，也不因这两类事件生成空时间线。后台采集与历史事件保留，无额外轮询或定时刷新。

模型管理的手动创建表单支持上下文窗口（默认 1,000,000 tokens），远程添加也使用数据库默认值。`ModelContextWindowEditor` 允许按现有模型权限编辑正整数窗口并刷新目录；清空字段不能保存，不会把空值替换为默认值。

全局导航的品牌开关、组件生命周期、阅读位置及 TAB 记忆规则见 [常驻全局导航](design-docs/global-navigation.md)。


## 登录与系统管理

`AuthGate` 在工作区外校验 Cookie 会话，未登录显示 `LoginPage`；服务不可用显示重试。登录页复用品牌字标，主要字号 14px；非 RMS 页面按[MelonClaw 登录页](design-docs/melonclaw-login-page.md)展示浅蓝玻璃风格；登录表单关闭浏览器自动填充并用独立字段名，避免把同源页面保存的模型 URL/API Key 填成用户 ID 和密码。后端 `/api/auth/config` 返回 passwordless 布尔值，只有 `profile=dev` 显示“免密登录”，不带开发后缀或说明。

仅 `profile=dev` 时所有人显示 `UserPicker`，创建用户从原下拉菜单移到 admin 专属的 `AccountManagement`（用户管理／租户管理 Tab）。按当前身份决定管理入口。登录或切换由服务端决定身份；localStorage 不存认证 Token。`AuthGate` 刷新身份时卸载旧 SessionProvider，清除旧请求与 UI 状态，并通过 storage 事件通知其他标签页。X-Melonclaw-User 是过期页面断言，不是身份凭证。

API 使用 Cookie 和同源反代；原可选身份请求头不再支持。401 清理登录状态，身份断言不符的 409 重新同步。用户切换只断开前端流订阅，后台执行继续持久化。详情见[用户管理与登录设计](design-docs/user-management-login.md)。

密码输入由 `PasswordFields` 统一提供密码及再次确认字段；创建用户、管理页修改密码和头像菜单 `ChangePasswordDialog` 共用校验。无需旧密码，本人修改成功后刷新认证并返回登录页。

### RMS 登录页

`LoginPage` 复用既有品牌编译常量，仅 `brand` 去空格并忽略大小写后为 `rms` 时显示 RMS 分栏式登录页。其他品牌或空值使用 MelonClaw 浅蓝登录页：左侧字标、标题和表单，右侧本地玻璃 AI 环配图；900px 以下隐藏装饰图。RMS 主表单仍使用同一认证接口、错误状态与后端免密配置；14px 正文和标签、44px 登录控件使用共享 Token。配图为本地 WebP，不请求第三方资源；900px 以下只保留 Logo 和表单，短屏自然滚动。RMS 页面不显示「欢迎回来」「欢迎使用 RMS 投研助手」或「RMS · 投研助手」描述文案；右侧免密入口使用文字按钮，Logo 和表单背后使用品牌蓝径向渐变光晕，输入框保持白底。设计和验证见 [RMS 登录页](design-docs/rms-login-page.md)。

## 站点访问提示

`AccessNoticeGate` 在 `AuthGate` 外层，仅当 `brand` 不为 `rms` 时启用访问提示（沿用品牌开关，去除首尾空格并忽略大小写）；RMS 直接进入原认证流程。启用提示且未确认时不挂载认证与工作区，仅展示禁止关闭的风险提示弹窗；确认状态按当前浏览器同源 localStorage 记录。首页快捷卡片下方以 14px 展示完整合规声明。实现边界和验证见 [站点访问提示与合规声明](design-docs/compliance-notice.md)。
