# 长任务状态与停止反馈

状态：已实现。日期：2026-10-02。

## 背景与目标

执行区已经展示工具、状态与耗时，但笼统的「正在执行」无法表达当前工作；用户阅读历史时缺少新内容提示，停止后也难以分辨保留内容、已返回的工具结果和仍需核对的操作。

本次在既有执行区上补充真实阶段、明确任务清单进度、未读提示和停止说明。不新增数据库表、后端协议或 Agent 权限。

## 方案与关键选择

### 当前阶段

运行中的实际工具调用提供阶段：检索资料、读取文件、生成／修改文件、执行命令、计算、更新清单、安装或测试连接等。未知工具只显示正在调用的工具名，不根据模型文字或命令内容猜测用途。

根工具与子 Agent 实际工具都参与活动摘要；多个工具并行时说明调用数量，不把这个数量当任务总数。子 Agent 工具通过服务端 `call_key` 对账，参数分片不会重复计数；未收到完成事件的子 Agent 保持可观察的未结束状态。

没有活动工具时使用当前消息最后观测到的公开阶段；阶段数组保持有界并记录最近阶段顺序，支持分析、生成、工具处理之间反复切换。消息文本增量与工具事件更新所属消息，历史消息不会跟着另一条消息的全局运行状态变化。等待用户时区分确认与回答；终态和未订阅的 pending 历史不显示正在执行。

### 明确任务清单

只读取已经成功返回、没有错误的根 `write_todos` 调用的完整 JSON 参数，校验 `todos` 中每项都有非空正文和 `pending`／`in_progress`／`completed` 状态。摘要显示「任务清单已完成 2/4 项」，可以展开查看各项。

这是 Agent 已提交的计划状态，不是独立的成果验收。当前收到的工具数、过程消息数或执行耗时不能提供任务总数，不显示估算百分比。新计划失败或仍在执行时继续展示上一份已确认清单；最新成功清单为空、被截断或格式无效时停止显示旧分母，避免过期信息。计划调整后采用新清单的分母，不强行维持旧进度。

受现有参数预览长度限制，长清单可能无法完整解析，此时不显示清单总数。子 Agent 的各自计划不合并为主任务总数。

### 阅读历史时的新内容

保留现有接近底部时自动跟随的行为。用户离开底部后，文本增量、步骤／工具／子 Agent 更新、公开阶段变化或终态变化显示「有新内容 · 回到最新消息」。离开底部本身不产生未读；点击入口或回到底部清除标记。

标记只存在当前页面，用户或会话切换、历史加载与重新同步时清除。待处理问题／审批提醒与回到底部入口可以同时出现，避免待处理卡片遮住新内容入口。

### 停止后的说明

先冲刷已接收的文本，再中止当前会话订阅，沿用现有取消路径。已收到的回答、过程文本和工具结果继续显示。

取消消息旁说明具体保留的内容类别，并分别列出已收到完成结果、已报告失败和结果待确认的工具调用。列表保留友好工具名与脱敏参数摘要。同名重复调用分别记录，不按名称合并；子 Agent 的实际调用参与统计，不计合成父节点。

停止后未完成的根工具按展示状态标为 `unknown`，不继续转圈、不宣称成功／失败。未收到结束确认的子 Agent 也明确提示。结果待确认时提供重新同步入口。文案明确：停止生成不会撤销已执行的操作，未收到结果也不代表操作未执行。

## 数据与事件流

根步骤、工具与子 Agent 事件 → 既有消息归约 → `buildAgentRun` → `runActivity` 派生活动阶段、已确认清单与停止摘要 → 执行区和停止说明。

消息列表变更 + 当前阅读位置 + 用户／会话标识 → `useUnreadChat` → 底部新内容入口。取消仍由原 `stopCurrent` 路径执行，不新增取消 API 或自动重试。

终态 `completed` 快照与历史接口继续负责实际工具结果对账。没有历史公开阶段时，不伪造历史运行阶段；终态清单和停止摘要由保存的步骤／事件派生。

## 实现位置

- `frontend/src/lib/runActivity.ts`：活动阶段、确认清单、子 Agent 调用与停止摘要。
- `frontend/src/lib/agentRun.ts`：消息阶段和终态未完成工具的展示状态。
- `frontend/src/hooks/useChatStream.ts`：公开阶段的最近顺序，保留停止前增量。
- `frontend/src/hooks/useUnreadChat.ts`：按用户／会话隔离的临时未读提示。
- `frontend/src/components/AgentExecution.tsx`：阶段、清单计数与展开列表。
- `frontend/src/components/StoppedRunNotice.tsx`、`ChatView.tsx`：保留内容、结果分类、同步入口和新内容按钮。

## 失败与安全边界

展示只依赖服务端公开、脱敏的工具参数与事件，模型已返回的推理 content 与正文一起展示，不渲染任意 HTML、不执行清单正文。计划完成不等于文件、外部请求或业务成果已验证成功。

停止不能追回文件写入、Shell 或外部副作用，也不能保证未返回结果的工具已停止。重新同步只读取服务端状态，不自动重放未知结果的操作。服务端取消收尾与持久化完成前，立即刷新可能仍显示 pending；不把它当作运行成功。

开发模拟身份、LocalShellBackend 和既有 HITL／PTC 边界不变。

## 运行步骤与预期结果

使用 README 的现有启动命令，无需数据库初始化。发起多步骤任务后观察执行摘要；Agent 提交任务清单时查看明确进度。输出期间滚动到历史，收到新内容后点击回到底部；停止生成后核对保留内容和工具结果，必要时重新同步。

预期结果：当前活动有可解释的阶段；没有明确总数时无虚构进度；阅读历史不被新内容拉走；取消后能区分观察到的完成结果与未知结果。

## 验证记录

定向测试覆盖工具阶段与并发、根和子 Agent 对账、等待回答／确认、重复阶段、清单成功／失败／修订／截断、取消后的结果分类和文本保留、未读标记及上下文清除。聊天组件测试确认收到新内容时不调用滚动，点击后才回到底部。

完整 `scripts/check.sh` 通过：后端 compileall、pytest（含架构与文档链接）、Ruff、锁文件检查，前端 lint、类型检查与 Vitest。最终参数校验与任务清单友好名称调整后，前端全量检查再次通过。

固定数据的真实组件预览在桌面与 390px iframe 视口检查；展开任务清单无横向溢出，取消区域没有旋转图标。截图保存在本地 `note/screenshots/long-task-feedback.png` 与 `long-task-feedback-narrow.png`。这不是完整聊天端到端视觉验证；真实模型、数据库和外部 MCP 的端到端验证尚未进行。


## 回复流畅性扩展（2026-10-03）

同轮工具选择复用，选择失败有界降级；并行工具各自完成后立即反馈。有序思考块保留模型已返回的可读思考，未返回可读内容时继续显示真实阶段与当前请求时长；工具 queued、等待审批和 running 分开，不把审批计入执行耗时。提示词要求长操作前简短说明目的，不增加生成进度文案的模型请求。具体协议、记录与边界见 [回复流畅性与推理协议](response-fluency.md)。
