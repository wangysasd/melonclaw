# 安全审计日志

状态：已实现。日期：2026-11-26。

## 目标

留存用户账号、操作时间、操作类型、网络源地址和源端口、目标地址和目标端口，以及浏览器能提供的客户端特征。不新增表，不修改现有字段。用户发出的对话正文仍由现有消息记录保存。

## 记录位置

写请求结束时，`api/audit.py` 向审计目录追加一行 JSON。目录由 `core/config.py` 解析：设置 `MELONCLAW_AUDIT_DIR` 时用该目录，否则为数据根下的 `audit/`。默认数据根是 `~/.melonclaw/data/`。文件按本地日期命名为 `audit-YYYY-MM-DD.jsonl`，目录权限 `0700`，文件权限 `0600`。

应用每天首次审计写入时，删除日期早于当天往前 184 天的文件。边界当天的文件仍保留，覆盖任意连续六个自然月。变更后的策略从新版本运行起生效，已清理的历史文件不会自动恢复。这组文件不进入 `/var/log/melonclaw` 的 14 天轮转。当前只支持单 Web 进程，追加不做跨进程锁。

## 记什么

`POST`、`PUT`、`PATCH`、`DELETE` 各留一行。`GET`、`HEAD`、`OPTIONS` 不留。登录失败也留。一行包含时间、账号、目标账号、操作、路由、结果、状态码、源地址、源端口、目标地址、目标端口、User-Agent、设备标识和 `Sec-CH-UA-Platform`。

已知路由使用中文操作名，例如登录、短信登录、注册账号、发送短信验证码、绑定手机号、发送消息、创建用户、提交投诉、查询投诉、受理投诉和办结投诉。其余写操作保留方法和路由。不读取正文，因此口令、令牌、验证码、消息内容、投诉说明、查询码、联系方式和环境变量值不会进入审计文件。短信操作的目标账号只写手机尾号，例如 `尾号8000`，不写完整手机号。

浏览器首次访问得到 `melonclaw_device`。它是随机标识，HttpOnly，不代表登录状态，也不能代替访问令牌。浏览器不提供网卡地址，日志不写 MAC。

## 来源地址

Web 启动时关闭 Uvicorn 的代理头预处理，保留实际连接地址供审计判断反代是否可信。

应用只在直接连接来自本机回环地址时采信 `X-Real-IP`、`X-Real-Port`、`X-Forwarded-Host`、`X-Forwarded-Port` 和 `X-Forwarded-Proto`。生产站点由 `ops/nginx/melonclaw.conf` 传入这些头。未更新 Nginx 时，来源是 `127.0.0.1`。非本机直连的请求忽略这些头，防止调用方伪造来源。

## 边界

写入失败只记一条应用警告，不改变接口结果。日志不是内容审核，也不保存证件号、完整手机号、验证码或口令。短信相关写操作的目标只记「尾号」加 4 位数字。对话正文的留存仍取决于现有消息记录；审计行只说明发生了发送、修改或删除。

## 写入失败告警

目录无法创建、权限不足或磁盘写入失败时，仍只记应用警告，业务请求按原结果返回。告警在后台发送，并受 `MELONCLAW_AUDIT_ALERT_TIMEOUT_SECONDS` 限制，默认 2 秒，避免拖住用户请求。

仓库没有单独的运维推送通道。部署者把 `MELONCLAW_AUDIT_ALERT_WEBHOOK_URL` 配到自己的接收地址，由 `core/config.py` 读取。地址、凭据和请求正文不进入日志、页面或审计文件。告警只包含服务名 MelonClaw、时间、故障类别和一句排查建议，也不再写入审计文件。

未配置接收地址时，只有本地警告。配置之后，一次持续故障在通知成功后不再重复发送；通知本身失败时保留警告，并按 `MELONCLAW_AUDIT_ALERT_RETRY_SECONDS`（默认 300 秒）重试。审计写入恢复后，下一次故障可以重新告警。状态只保存在当前 Web 进程；重启后下一次故障会再通知。

演练时在本机启动一个只监听回环地址的测试接收端，把上面的变量指到该接收端，并把审计目录的上级路径临时改成一个普通文件，使目录创建失败。重启 Web 后做一次会写审计的操作，例如错误登录。确认接收端收到服务名、时间和故障类别，且没有口令或请求正文；立刻再操作一次，确认没有第二条。然后恢复审计目录、清空或改回正式接收地址并重启。不要把这次测试发到真实负责人的渠道。只有完成这样的送达确认后，才能认为负责人会收到通知。
