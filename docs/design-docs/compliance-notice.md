# 站点访问提示与合规声明

## 背景与目标

站点所有者要求首次访问主动确认个人学习用途、投资风险和禁止外传，并在首页下方展示其提供的完整声明。

## 方案与数据流

`components/ComplianceNotice.tsx` 提供 `AccessNoticeGate` 与 `ComplianceStatement`。前者位于 App 的认证入口之外，仅在 `brand` 不为 `rms` 时启用（沿用已有品牌常量，去除首尾空格并忽略大小写）；RMS 直接进入原认证流程。启用时：读取 `melonclaw.access_notice.v1`，未确认时仅挂载 Ant Design Modal，不挂载认证和工作区子树；点击「我已确认并进入」后写入 localStorage，再进入原认证流程。后者显示在首页研究服务快捷卡片之后。正文使用 14px，关键风险使用红色粗体。

## 设计选择与边界

弹窗无关闭按钮，禁止遮罩和 Escape 关闭，沿用组件库焦点管理。确认按同一浏览器、同源存储记录，不按账号记录；清除存储、更换浏览器或声明版本变化后重新确认。存储被禁用时，本次确认仍有效，下次刷新重新提示。

此机制用于前端阅读提示，不替代 Cookie 认证、服务端访问授权或法律效力判断，也不提供服务端签署证据。声明按所有者提供的文案展示，备案申请状态由所有者维护。本次无新增 API、数据库、Agent 工具或权限。

## 运行与验证

运行 `npm --prefix frontend run dev`，清除上述存储键后访问首页，预期仅显示访问提示；键盘 Escape、遮罩点击不能进入；主动确认后显示登录或工作区，刷新不重复提示。首页快捷卡片下方可滚动阅读四段完整声明。自动回归覆盖未确认不挂载内容、关闭绕过、确认与刷新记忆、存储失败和完整声明。

验证记录：`scripts/check.sh` 全部通过，包含后端编译／pytest／ruff／锁文件、前端 lint／类型检查／vitest、空白及文档链接检查。
