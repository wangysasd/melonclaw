# 定时任务的当前资源与执行保护

状态：已实现，2026-10-28。
日期：2026-10-28。

本文记录后台的当前资源使用、运行状态和两层执行保护。后台已支持只读 Skill、授权 MCP 和动态工具发现；调度与历史交付见[定时任务](task-center.md)。核实运行版本为项目锁定的 Deep Agents 0.7.5 / LangChain 1.3.14。

## 背景与目标

定时任务需要使用执行时按所属用户权限可获得的 Skill、MCP 和工具。资源可能在任务创建后更新、停用或删除；任务按实际可用情况执行，不保存旧资源供后续运行。

模型可能因缺少能力反复检索、猜测工具名称或委派子 Agent 继续寻找。采用“正常收尾规则 + 工程上限兜底”两层保护，减少无效尝试，并保证持续循环受到次数和时限约束。运行状态只表达工程执行情况，不增加业务目标是否完成的判定。

## 当前资源与结果语义

- 每次真正开始执行时，按任务所属用户的当前身份、租户和权限解析有效资源；排队和手动重新运行均按此次执行时的资源处理。
- 资源更新后使用当前版本，删除或停用后按不可用处理；任务不保存资源快照、不恢复旧内容，也不维护依赖表或解析 Prompt 建立依赖关系。
- 即使 Prompt 明确指定 A-Skill，执行时没有也直接不用。Agent 跳过相关环节，在结果中说明缺少的资源、跳过的工作和实际完成的内容。
- 能力缺失、工具不可用或结果不达预期，本身不构成运行失败。Agent 正常结束并返回有效正文即可记为 succeeded，正文可以只说明本次无法开展业务工作。
- 保留现有任务定义与历史来源留痕；它们用于确定本轮输入，不承担资源回放。过去的报告不能冒充本次查询或执行结果。
- 单次运行成功不代表有限目标已经完成，不据此自动暂停后续计划；complete_task 继续沿用既有的显式完成与版本校验边界。

## 第一层：正常收尾规则

后台主 Agent 和子 Agent 使用一致的收尾指引：

1. 仅使用当前实际可用且已授权的能力。工具发现只能在当前授权目录内查找，不能安装资源、扩大授权或恢复已删除的内容。
2. 确认某项资源不可用后，跳过依赖它的环节；不反复检索同一缺失能力、不猜测名称，也不通过子 Agent 重新寻找已经确认缺失的资源。
3. 仍有可执行的工作就继续；没有可继续的工作时，直接说明原因并结束本次运行，不等待用户补充或批准。
4. 结果如实区分已完成与跳过的工作，不编造工具执行、数据或业务成果。

例如，结果可以说明“已完成公开资料整理；当前没有可用的财务查询工具，跳过财务数据获取和估值计算”。本次正常收尾仍为 succeeded。

该层依靠模型遵循指引，不增加程序层面的业务完成判断或按资源分类的重试状态机，也不能单独保证模型及时停止。

## 第二层：工程上限兜底

沿用现有调用预算、工具发现额度、超时和取消机制：

- 主 Agent、子 Agent 共用本次运行的模型/工具总预算和停止标志；委派不能重置总预算。
- 工具发现次数有限。后台主/子 Agent 共用整次运行的发现额度，并行申请在同一控制对象内加锁预留。额度耗尽后不再执行实际选择请求，并返回“使用当前能力或说明能力不足”的明确提示；重复请求仍消耗运行预算，不能无限续期。
- 工具选择内部模型调用同样扣减共享模型预算，并受发现额度和选择超时限制；空目录不调用选择模型。历史准备、摘要、发现、构建和正式执行都受整次运行总时限约束，取消继续传播。
- 触达模型/工具调用上限或总时限时，由程序停止本次执行，不依赖模型主动结束。用户取消沿用停止标志和协程取消流程。
- 停止本次运行不暂停后续计划，不自动重新执行本次运行。

核对 `core/config.py` 的现有代码默认值如下；实际值仍由已有配置入口解析，本方案不调整数值或新增配置项：

| 控制项 | 代码默认值 | 边界 |
|---|---|---|
| 模型调用预算 | 1000 次 | 后台主/子 Agent 共享 TaskRunControl |
| 工具调用预算 | 5000 次 | 后台主/子 Agent 共享 TaskRunControl |
| 任务总时限 | 1800 秒 | 包含准备、Agent 构建和执行 |
| 工具发现额度 | 4 次请求 | 后台主/子 Agent 整次运行共享；普通聊天保持每消息上限 |
| 工具选择超时 | 10 秒 | 单次内部选择的时间约束 |

当前调用预算较宽，能够限制持续执行，但不能保证缺工具时很快收尾。是否收紧后台预算需结合任务规模另行决定。发现额度只限制实际检索，不保证模型不会重复请求；最终由总调用预算和总时限兜底。相关现有机制见[按需工具选择](on-demand-tool-pool.md)和[Agent 运行控制](agent-runtime-controls.md)，后台共享预算与普通聊天各 Agent 独立计数的语义应分别保持清晰。

## 数据与事件流

领取运行 → 校验所属用户身份与模型 → 解析当前有效资源 → 准备历史 → 构建后台 Agent → 在两层保护下执行 → 保存工程终态与脱敏结果。

| 执行情形 | 运行状态 |
|---|---|
| Agent 正常结束并返回结果，包括缺少资源、跳过环节或无法开展工作的说明 | succeeded |
| 持续循环导致调用预算耗尽，或整体运行超时 | failed，保留对应工程错误码 |
| 未恢复的模型/执行器异常、越权、上下文溢出或无有效结果等既有工程错误 | failed，沿用既有分类 |
| 用户取消并确认本地停止 | cancelled |

不新增“部分成功”“业务失败”等状态，也不增加用于判断业务目标完成的新失败回执。资源缺失后正常说明，与持续循环触发工程保护，是不同的运行结果。

## 装配与安全边界

`services/task_resources.py` 复用现有 Skill 有效状态、文件操作锁和 MCP 来源/凭据/启用/白名单规则，前后核对进程内资源版本并最多重试 3 次。`backend/task_skills.py` 仅映射有效的单个 Skill，逐层 O_NOFOLLOW、普通文件类型和 10 MiB 上限保护读取；只读目录与正文/引用资料，不暴露整个共享或个人目录，也不生成普通聊天所用的 Skill 派生副本。MCP 通过共用的 `tool/tools.py:build_mcp_tools` 复用发现、参数校验、命名隔离和错误脱敏，单个服务不可用不阻断其余能力。

后台资源装配经过 `core/agent.py` 的无人值守分支、`core/task_agent.py`、`core/task_policy.py` 和 `middleware/task_policy.py`，保留路径约束、主/子权限一致及共享停止保护。MCP 授权名称来自本次通过白名单的真实装配结果，不根据名称前缀放行。主/子私有工具池各自维护可见性，整次运行共用 TaskRunControl。未知工具与越权不能因为缺少资源而自动放行。模型、MCP、配置和业务数据继续经过现有固定入口，不新增持久化表或资源快照字段。

已启用且白名单允许的 MCP 沿用免逐次审批；安装、配置变更及其他需要人工审批的能力不自动放行，也不进入 PTC。运行中的工具实例不热替换，下一次执行重新解析资源；已读内容和已发出的请求无法撤回，远端写入超时或取消也不保证回滚，不自动重试结果未知的写操作。

本轮尚未确定 Shell、脚本执行和文件产物的扩展范围。读取 Skill 不自动赋予它所要求的额外权限；若后续开放 Shell，需单独明确执行环境、环境变量、工作目录和产物清理，当前 LocalShellBackend 不是安全沙箱。

## 运行与验证

更新代码后重启现有 Web 服务，无新增依赖、配置项或数据库结构，不需要执行数据库初始化/升级。运行前在资源管理中启用 Skill/MCP 并配置工具白名单，在定时任务要求中描述所需工作即可，无需另行绑定资源。未验证真实外部服务或生产部署。

预期结果与验收场景：

- A-Skill 删除、停用或更新后，下次执行按当前可用情况处理；覆盖排队期间变更与手动重新运行。
- 全部资源为空或 MCP 部分发现失败时，Agent 能如实说明并正常结束，运行状态为 succeeded，不因业务环节跳过而失败。
- 模型反复请求同一缺失能力时，发现额度耗尽后不再进行实际选择；持续循环最终触发模型/工具预算或总时限，状态为 failed。
- 子 Agent 与主 Agent 共同消耗总调用预算；委派和重复发现不能绕过停止标志或总时限，选择器内部调用也有界。
- 验证正常收尾与工程保护触发的状态区别、用户取消、后续计划继续运行，以及原有身份、白名单、路径和脱敏边界。

```bash
scripts/check.sh
```

真实 MCP/供应商验证需具备相应连接与凭据，只观察状态、次数、时限和脱敏结果，不输出凭据或远端原始异常。隔离 PostgreSQL 验收依赖 MELONCLAW_TEST_DATABASE_URL；未提供时对应测试跳过，不使用业务数据库替代。
