# 设计文档索引

设计文档记录“为什么这样设计”，而不是“代码怎么写的”。实现类细节请写进 `docs/ARCHITECTURE.md` 或对应模块的注释。

## 清单

| 文档 | 状态 | 说明 |
|---|---|---|
| 聊天附件上传技术设计 | 设计中，未实现 | 支持聊天上传图片、PDF、Office 文件，含附件表、API、解析器、沙箱边界。**仍在讨论中，按约定留在本地草稿目录（`note/上传附件技术设计.md`），未纳入版本控制**；主要设计决策已定稿，待实现后再搬入本目录 |

## 状态取值

| 状态 | 含义 |
|---|---|
| 设计中 | 方案仍在讨论，接口和数据模型可能变化 |
| 待实现 | 方案已确认，尚未编写代码 |
| 已实现 | 代码已合入，文档转为描述现状；若与代码不一致，以代码为准并修正文档 |
| 已废弃 | 方案被替代，保留用于追溯决策原因 |

## 存放约定

- **稳定的设计文档**放在本目录下，文件名用英文短横线风格，例如 `attachments.md`。
- **未定稿的讨论**留在本地草稿目录（`note/`），结论确认后搬进本目录，并在上表更新状态。
- 每份文档开头写明：状态、背景与目标、方案概览、关键取舍、失败与安全边界、验证方式。
- 文档中引用的上游框架行为（源码行号、版本号）要标明核实版本，框架升级后需要重新核实。
