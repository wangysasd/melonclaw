# JWT 登录

状态：已实现。日期：2026-11-23。

账户资料、权限和开发态入口见[用户管理与开发登录](user-management-login.md)。本文是当前登录凭证。

## 目标

用无状态 JWT 替换服务端会话。令牌只回答「是哪个用户、何时过期」；角色、租户和资源权限继续按当前用户重算。不新增表或字段。

## 令牌

算法 HS256。载荷只有 `sub` 和 `exp`。`sub` 是现有字符串 `user_id`。`exp` 是签发时刻加上配置的有效期。角色、租户、权限、密码和原登录人都不放入令牌。

签名密钥只放在服务端。签发时用密钥对头部和载荷计算 HMAC-SHA256。验证时用同一密钥重算并比较；不一致直接拒绝。比较通过后，用令牌里的 `exp` 和服务器当前时间判断是否过期，这一步不查数据库。

未过期时，用 `sub` 查询 `users`。该行存在且 `tenant_status` 为 `active` 才接受，并读出用户行上的 `tenant_id` 与 `tenant_role` 作为本次请求身份。用户已删除则拒绝。不因 `tenants.enabled` 拒绝令牌。界面若仍显示租户名称，可以另行读取，该读取不参与令牌是否有效的判断。

## 配置

两项都只经 `core/config.py` 读取。

| 变量 | 规则 |
|---|---|
| `MELONCLAW_JWT_SECRET` | 签名密钥。必须配置，至少 32 个字符。缺失、空白或更短则拒绝启动。不提供公开默认值 |
| `MELONCLAW_TOKEN_TTL_HOURS` | 有效期小时数。未设置或空白时为 1000。配置了则必须是不小于 1 的整数，否则拒绝启动 |

已发出的令牌继续使用它自己的 `exp`。修改环境变量只影响之后的签发。

## 登录、免密、切换与登出

密码登录校验用户 ID 和现有 scrypt 哈希。用户须为 `active`。成功响应返回 `access_token`，不再写 Cookie。前端把令牌放在 `localStorage` 的 `melonclaw.access-token`，之后受保护请求携带 `Authorization: Bearer`。

`profile=dev` 时保留免密登录。`POST /api/auth/passwordless` 仍匿名可用，确认 `admin` 为 `active` 后签发 `sub` 为 `admin` 的令牌。其他 profile 返回 403，登录页不显示入口。

`profile=dev` 时保留切换用户。`POST /api/auth/switch` 先验证当前令牌，再确认目标用户为 `active`，然后另签一张令牌。`exp` 从切换时刻重新计算。前端用新令牌替换本地保存的令牌，清除目标用户上次的项目和会话，并通知其他标签页。失败时保留当前令牌和页面。不读取目标用户的密码。切换前的令牌在自己的 `exp` 之前仍然代表切换前的用户。

登出由浏览器完成：删除本地令牌，通知其他标签页，卸掉工作区并回到登录页。服务端没有可删除的会话记录。别处仍持有同一串令牌时，在 `exp` 之前、且用户仍为 `active` 时继续有效。

收到 401 时，前端核对发送请求时使用的 Authorization。它仍对应当前本地令牌时，清理令牌并由 `AuthGate` 回到登录页。切换身份或重新登录后，旧请求的 401 只返回给原调用。请求中的 `user_id`、`actor_user_id` 和 `X-Melonclaw-User` 仍只用来发现页面身份与令牌不一致，不能改写令牌里的用户。

## 账户变化

删除用户把 `users.tenant_status` 改为 `deleted`。该用户已签发的令牌在下一次请求被拒绝。

修改密码只更新 `password_hash`。用户仍是 `active`，已签发的令牌继续有效，直到 `exp`。停用租户后，同一令牌仍可查询当前会话。业务接口（含聊天、附件、定时任务和语音）在共享账户锁内检查租户启用状态，停用时返回 403。重新启用后，同一未过期令牌可以继续访问。

## 前端携带

JSON 请求在统一客户端加上 `Authorization`。聊天流、语音、技能包上传与下载、知识库文档上传与原文、结果文件读取这些直接发起的请求同样带上该头。

图片地址和附件链接若直接用作 `<img src>` 或 `<a href>`，浏览器不能附加 `Authorization`。这些展示改为先带令牌取得内容，再交给页面。

跨域白名单放行 `Authorization`。匿名路径仍是 `/api/auth/config`、`/api/auth/login`、`/api/auth/passwordless`、`/api/ready`。

## 数据与边界

不修改 `users` 和 `tenants`。`auth_sessions` 不再读写，本次不删除该表，也不写升级脚本。

令牌放在 `localStorage`，页面脚本可以读到。签名密钥、密码和密码哈希都不进入令牌、消息、Checkpoint 或追踪。`profile=dev` 的免密登录和全员切换仍是开发便利，不是生产环境的用户隔离。

`auth_sessions` 仍留在库里，应用不再读写。历史执行记录里的 Cookie 会话描述的是当时实现，不代表当前凭证。
