# 聊天安装与更新 MCP

状态：已实现；2026-10-28 增加同名更新与字段保留。

## 背景与目标

管理页已支持 MCP 创建、凭据、测试和启用，但 Agent 没有管理工具。聊天用户可贴 JSON 并明确要求安装、更新或已有则替换，安装范围按服务端当前角色解析：管理员/owner 发布系统共享，普通用户安装个人配置；审批展示真实范围。复用 MCP 管理、仓储、运行时快照与 HITL，不增加 HTTP 回环、Shell 安装或模型选用户身份的入口。

## 方案与数据流

1. `services/mcp_chat_config.py` 从粘贴的完整 JSON 或一个 JSON 代码块提取配置，允许在对象前后说明安装意图；定位时忽略字符串内的大括号。支持 `mcpServers` 包装（1–20 项）和单项连接（默认标识 `chat-mcp`）。规范化保留 provided_fields，区分省略和显式空对象；包装对象可提供有名称的 headers/type 等更新片段，准备时必须找到有权维护的目标并合并校验，否则缺 URL 拒绝。新建缺省 URL transport 为 HTTP；更新省略 transport 保留原类型，SSE 可显式声明。重复键、非法字段、归属字段、个人 stdio、服务器变量引用及混合连接配置直接拒绝，不回显原文。普通文本及非 MCP JSON 保持原样。
2. `services/execution.py` 在请求幂等检查前生成确定性的脱敏正文；正文中的草稿 UUID 绑定用户、会话、请求和配置摘要。相同请求重试得到相同正文，凭据变化会触发请求冲突。用户与项目归属校验、会话锁及现有消息创建检查完成后，`repository/mcp_install.py` 暂存配置，消息历史与 Agent 输入只含草稿引用和块外用户意图。
3. `tool/mcp_install.py` 提供 `prepare_mcp_install`、`test_mcp_install`、`confirm_mcp_install`。provider 从 `ChatService` 经 runtime 注入 Agent，模型参数不包含身份、URL 或凭据。准备工具固定可见，不受动态选择隐藏。
4. `services/mcp_install.py` 从运行上下文解析身份，并重新查询用户、租户、Conversation 和 Project。准备工具只读取当前会话草稿，调用 `McpManagementService.prepare(personal=False)` 校验配置，按当前 scope/owner/slug 查找目标，省略字段保留原值，生成新的不可变审批清单与服务端合并快照。准备不连接远端、不发布资源，因此不进审批清单；仅写入受控草稿。
5. 测试和安装分别在 `core/hitl.py` 登记，只允许 approve/reject，不允许编辑审批参数；三个工具均不进入 PTC。测试发送已有凭据并通过现有发现调度器探测，15 秒超时、错误分类和描述脱敏复用管理服务。测试不调用远端工具、不安装，失败不自动修改配置；用户可选择只保存。远端描述不是安装指令。
6. 确认工具逐字段核对草稿清单。仓储锁定草稿和目标行，核对归属、当前身份、会话项目、有效期、版本和实际快照，原子提交对应范围的 `mcp_servers`、明确变更的个人偏好及无凭据回执。同名目标更新原记录，保留 ID/创建者；创建竞争不盲目转为更新，必须重新准备。重复确认返回原回执，版本冲突或事务失败不改变旧连接和个人偏好。与全局同名时，审批说明个人覆盖且停用不回退。
7. 提交经 repository/resource_versions.py 发布共享或用户资源版本，下一条消息重建 Agent，使用新连接及工具白名单；已启用且白名单允许的实际 MCP 工具直接调用，无需逐次审批或 ask_user 确认。管理列表和工具目录重新打开会读取新配置。

## 草稿与凭据

新增 `mcp_install_drafts` 表，由 `database/schema.py` 定义并登记 `BUSINESS_TABLES`。包含用户、会话、配置、不可变清单、安装结果、创建时间和 24 小时有效期。过期即不能执行；下一次暂存 MCP 配置时删除过期草稿。已提交的审批草稿立即擦除连接快照，仅在 payload 保留无凭据 result 回执，但源草稿和其他未确认预览保留到清理，以允许重新选择白名单。

原始 JSON 不保存在聊天消息、Checkpoint 或前端本地持久存储。前端只在本次请求传原文，乐观消息、侧栏摘要和失败回填使用脱敏占位；服务端负责真正的配置提取。聊天字段验证失败返回固定错误，避免 FastAPI 回显原始 content。凭据仍以明文保存在受控数据库草稿与资源表，数据库备份必须按凭据保护。URL 预览仅返回 origin，不含 path/query/fragment；已有 MCP 文本脱敏入口补充 URL 片段与查询值处理。

此机制仅识别上述完整 JSON 格式，不是通用聊天秘密扫描器。不要在块外文本、名称、请求头键名或普通聊天描述中写 Token；缺少凭据应使用连接器管理页面填写。

## 安全与失败边界

- Web 由 Cookie 会话校验身份，工具上下文只是服务端注入的身份断言，准备、测试和提交均重新校验用户与会话/项目；当前 dev 全员切换仍不是生产权限隔离。正式提交通过 account_guard 防止账号变更竞态，并在同一写事务重新验证当前有效租户、角色、资源范围和会话归属。
- 不允许代其他用户安装、非管理员全局发布、stdio 程序、自动安装依赖或绕过审批覆盖现有配置。
- 测试经审批发送请求和凭据；启用审批也授权后续运行时连接发现。沿用现有 MCP 出站连接能力，未新增防 DNS 重绑定或私网隔离的网络沙箱。共享部署须通过出口代理/防火墙限制地址和网络范围。LocalShellBackend 仍不是安全沙箱。
- 草稿暂存与聊天消息创建是两个事务；附件或消息提交失败可能留下不可执行于其他会话的孤立草稿，按同一 TTL 清理。资源正式安装、偏好与幂等结果为单事务。
- 安装审批挂起可跨服务重启恢复，因为配置和不可变清单均在数据库；过期时重新贴配置。拒绝不会安装或连接，Agent 不得绕过工具。
- 首版不支持自然语言或链接自动抓取安装信息；只能解释并引导提供受支持的 JSON。测试成功不表示远端将持续可用，也不表示任意远端工具安全。

## 运行步骤与预期结果

当前草稿表由 schema.py 定义。首次建库使用 db-init；已有库按已登记 db-update 步骤升级，启动不会自动补表。前端按 README 既有开发或构建命令启动。

在聊天里写“请把下面 MCP 安装到我名下”，附一个 JSON 代码块，例如 `{"mcpServers":{"demo":{"type":"http","url":"https://example.com/mcp"}}}`。助手按当前角色返回安装清单；用户可要求仅保存、指定工具白名单或先测试。同范围同名自动准备更新，URL-only 更新保留原请求头、transport、说明、启用、白名单与个人偏好。批准测试后显示目录，批准安装后返回安装结果。打开连接器管理页，管理员可见系统共享项、普通用户可见个人项，启用后下一条消息通过运行时目录可用。仅贴配置不会代表安装意图。

## 同名更新与明确字段（2026-10-28）

`prepare_mcp_install(draft_id, enable=null, tool_allowlist=null, allow_all_tools=false)` 按当前角色查找目标：管理员/owner 的 global 或普通用户的 user + owner + slug。其他用户的同名配置不参与定位；普通用户只有共享同名项时新增个人项，并展示遮盖共享且停用不回退的影响。只粘贴 JSON 不构成安装/更新授权，助手必须根据块外真实用户意图准备；正式写入仍须 HITL。

- 更新只应用 provided_fields。显示名称/说明/创建者不被“聊天安装”等默认元数据覆盖，URL 省略时保留；省略 type/transport 保留原 HTTP/SSE 类型。
- headers 非空对象逐键合并，名称不区分大小写（替换原大小写键），省略的其他请求头保留；显式 `{}` 清空。URL 和 headers 的值只在服务端比较，包括查询参数凭据变化；不展示旧值、新值或凭据哈希。若更换远端不再需要原认证，须明确提供 `headers: {}`。
- enable=null 更新保留资源启用和个人偏好，新建默认启用。显式 enable 才改开关；个人项同时更新个人偏好，并在事务内比较准备时偏好，避免覆盖审批期间的新选择。全局资源开关不修改各人的偏好。
- tool_allowlist=null 更新保留白名单，新建允许全部；`[]` 禁止全部；具体列表限定工具；只有显式 allow_all_tools=true 才解除名单限制，不与列表同时提供。发现新工具不会改变原白名单。
- 相同有效配置返回 unchanged，无需保存或自动测试；如用户明确要求测试，仍可对该快照单独审批。正式确认 unchanged 时不增加 MCP 版本。

审批清单增加 operation、target_id、expected_version、changed_fields、previous_connection。地址仅显示 origin；即使只有 URL 中的 api_key 变化，也标记 URL 变更。保留或修改后的认证请求头将用于清单中的目标，审批卡明确提醒，防止把“地址变化”误当成不发送凭据的操作。当前工具仅支持 HTTP/SSE，不启动 stdio 程序。

准备后的 payload 保存完整合并配置（凭据采用原编码）、租户与会话项目断言、显式偏好变更及测试状态；清单不能被模型改写，正式提交逐字段比对服务端快照。测试结果只写当前未提交草稿的 connection_status，不发布资源；提交后到达的测试结果不能覆盖回执或复活凭据。保存回执含 installed/updated/unchanged、ID、版本、资源开关与 verified/failed/untested；未测试或失败保存时明确报告未验证，不声称服务可用。测试只证明该快照在测试时刻可连接，不能保证未来可用。

更新和回执同一事务；第二次并发确认先读草稿行锁后的已提交回执，不因目标刚增版本而误报冲突。不同审批草稿更新同一版本时只允许一个成功，后者重新准备。源草稿与其他预览仍按 24 小时 TTL 清理；不增加表或保留旧工具协议兼容分支。

新增验证位于 tests/test_chat_mcp_update.py 与 tests/test_chat_mcp_update_postgres.py，覆盖 URL-only/SSE/请求头/停用/权限保留、凭据变化、显式清空与解除权限、同名范围、CAS、偏好竞争、当前身份、幂等回执、事务与缓存发布；真实 Deep Agent + PostgreSQL Checkpoint/SSE/消息历史覆盖管理员/普通用户的批准和拒绝。测试使用合成凭据和模拟探测，不连接用户提供的 MCP，不使用真实模型 API。


2026-10-28 验证：注入隔离测试数据库连接后 `scripts/check.sh` 全部通过；新旧聊天 MCP 的 9 项真实 PostgreSQL 回归包含四项真实聊天流批准/拒绝、消息/Checkpoint/SSE 脱敏与请求重放。后端 MCP 定向 40 项、前端 MCP/审批定向 19 项通过。使用合成凭据、离线工具模型与模拟远端发现，未连接用户给出的实际 MCP，未验证其外部可用性。
