# 聊天安装个人 MCP

状态：已实现（2026-10-01）

## 背景与目标

管理页已支持 MCP 创建、凭据、测试和启用，但 Agent 没有管理工具。聊天用户可贴 JSON 并明确要求安装，安装范围固定为当前用户，管理员也不发布共享服务。复用 MCP 管理、仓储、运行时快照与 HITL，不增加 HTTP 回环、Shell 安装或模型选用户身份的入口。

## 方案与数据流

1. `services/mcp_chat_config.py` 从粘贴的完整 JSON 或一个 JSON 代码块提取配置，允许在对象前后说明安装意图；定位时忽略字符串内的大括号。支持 `mcpServers` 包装（1–8 项）和单项连接（默认标识 `chat-mcp`）。缺省 URL transport 为 HTTP；SSE 必须显式声明。重复键、非法字段、归属字段、个人 stdio、服务器变量引用及混合连接配置直接拒绝，不回显原文。普通文本及非 MCP JSON 保持原样。
2. `services/execution.py` 在请求幂等检查前生成确定性的脱敏正文；正文中的草稿 UUID 绑定用户、会话、请求和配置摘要。相同请求重试得到相同正文，凭据变化会触发请求冲突。用户与项目归属校验、会话锁及现有消息创建检查完成后，`repository/mcp_install.py` 暂存配置，消息历史与 Agent 输入只含草稿引用和块外用户意图。
3. `tool/mcp_install.py` 提供 `prepare_mcp_install`、`test_mcp_install`、`confirm_mcp_install`。provider 从 `ChatService` 经 runtime 注入 Agent，模型参数不包含身份、URL 或凭据。准备工具固定可见，不受动态选择隐藏。
4. `services/mcp_install.py` 从运行上下文解析身份，并重新查询用户、租户、Conversation 和 Project。准备工具只读取当前会话草稿，调用 `McpManagementService.prepare(personal=True)` 校验配置，生成新的不可变审批清单。准备不连接远端、不发布资源，因此不进审批清单；仅写入受控草稿。
5. 测试和安装分别在 `core/hitl.py` 登记，只允许 approve/reject，不允许编辑审批参数；三个工具均不进入 PTC。测试发送已有凭据并通过现有发现调度器探测，15 秒超时、错误分类和描述脱敏复用管理服务。测试不调用远端工具、不安装，失败不自动修改配置；用户可选择只保存。远端描述不是安装指令。
6. 确认工具逐字段核对草稿清单。仓储行锁核对草稿、归属、有效期与实际连接，原子提交个人 `mcp_servers`、`mcp_user_preferences` 和草稿安装结果。重复确认返回原结果；同名个人项冲突不会覆盖，事务失败不改变个人偏好。与全局同名时，审批说明个人覆盖且停用不回退。
7. 下一条消息通过既有 `mcp_snapshot_revision` 重建 Agent，使用新连接及工具白名单；实际 MCP 工具调用继续进入动态审批。管理列表和工具目录重新打开会读取新配置。

## 草稿与凭据

新增 `mcp_install_drafts` 表，由 `database/schema.py` 定义并登记 `BUSINESS_TABLES`。包含用户、会话、配置、不可变清单、安装结果、创建时间和 24 小时有效期。过期即不能执行；下一次暂存 MCP 配置时删除过期草稿。已安装的审批草稿立即清空连接 payload，但源草稿和其他未确认预览保留到清理，以允许重新选择白名单。

原始 JSON 不保存在聊天消息、Checkpoint 或前端本地持久存储。前端只在本次请求传原文，乐观消息、侧栏摘要和失败回填使用脱敏占位；服务端负责真正的配置提取。聊天字段验证失败返回固定错误，避免 FastAPI 回显原始 content。凭据仍以明文保存在受控数据库草稿与资源表，数据库备份必须按凭据保护。URL 预览仅返回 origin，不含 path/query/fragment；已有 MCP 文本脱敏入口补充 URL 片段与查询值处理。

此机制仅识别上述完整 JSON 格式，不是通用聊天秘密扫描器。不要在块外文本、名称、请求头键名或普通聊天描述中写 Token；缺少凭据应使用连接器管理页面填写。

## 安全与失败边界

- 当前用户来自开发模拟身份，不能防止客户端冒用用户；共享部署仍需可信认证。
- 不允许代其他用户安装、全局发布、stdio 程序、自动安装依赖或自动覆盖已有个人配置。
- 测试经审批发送请求和凭据；启用审批也授权后续运行时连接发现。沿用现有 MCP 出站连接能力，未新增防 DNS 重绑定或私网隔离的网络沙箱。共享部署须通过出口代理/防火墙限制地址和网络范围。LocalShellBackend 仍不是安全沙箱。
- 草稿暂存与聊天消息创建是两个事务；附件或消息提交失败可能留下不可执行于其他会话的孤立草稿，按同一 TTL 清理。资源正式安装、偏好与幂等结果为单事务。
- 安装审批挂起可跨服务重启恢复，因为配置和不可变清单均在数据库；过期时重新贴配置。拒绝不会安装或连接，Agent 不得绕过工具。
- 首版不支持自然语言或链接自动抓取安装信息；只能解释并引导提供受支持的 JSON。测试成功不表示远端将持续可用，也不表示任意远端工具安全。

## 运行步骤与预期结果

新增表无需修改已有表列或清空数据库。执行 `uv run melonclaw-db-init`，再重启 Web 服务。前端按 README 既有开发或构建命令启动，无新依赖。

在聊天里写“请把下面 MCP 安装到我名下”，附一个 JSON 代码块，例如 `{"mcpServers":{"demo":{"type":"http","url":"https://example.com/mcp"}}}`。助手返回个人清单；用户可要求仅保存、指定工具白名单或先测试。批准测试后显示目录，批准安装后返回安装结果。打开连接器管理页可见个人项，启用后下一条消息通过运行时目录可用。仅贴配置不会代表安装意图。
