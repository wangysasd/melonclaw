# MCP 两层配置与 JSON 单向导入

状态：已实现
日期：2026-10-01

## 背景与目标

管理员发布系统共享 MCP，普通用户配置个人 MCP。连接凭据与个人使用偏好分开，支持同名个人
配置替代全局配置，并与 Skill 管理页保持一致的分组、添加和菜单行为。

## 数据结构与归属

- `mcp_servers`：id、slug、display_name、description、scope、owner_user_id、created_by、
  transport、url、command、args、headers、env、enabled、tool_allowlist、version 与时间字段。
- `mcp_user_preferences`：以 `(user_id, slug)` 为主键，保存 enabled 与时间字段。
- 管理员创建固定为 global（owner 为空），普通用户固定为 user（owner 为自己）；客户端不能
  提交 scope、owner 或 created_by。创建默认停用，slug 创建后不可修改。
- 全局 slug 唯一；个人按 owner + slug 唯一。按数据库 id 管理，修改、删除及启用操作校验 version。
- tool_allowlist 的 SQL NULL 表示全部允许，空数组表示全部禁止，非空数组使用 MCP 原始工具名。
- 「仅允许指定工具」通过连接测试发现的原始工具名复选；切换后默认全选，保存当前勾选项。
- 全局停用项对普通用户的列表、详情和派生字段不可见；管理员保留管理入口。

来源选择先按 slug 取个人记录（包括未启用项），没有个人记录才取全局记录，再同时检查配置
enabled 和个人偏好。无偏好记录默认允许使用，与当前 Skill 的全局默认偏好一致。
个人停用或连接失败都不回退全局。删除个人记录才恢复全局来源，保留原有个人偏好。
管理员全员停用只影响全局配置，不影响其他用户的个人配置。

## 用户交互

“系统共享 / 我的”卡片使用 14px 字号。个人通过“添加到我的服务”启用，菜单“我不使用”仅
更新个人偏好，不删除配置。管理员菜单提供独立的“全员启用/停用”。只有未启用的服务显示添加或
状态按钮；服务已启用时不显示“已添加”状态胶囊。卡片正文用于打开工具详情。

添加个人项时，配置 enabled 与个人偏好在同一事务写入；不展示两套个人开关。编辑只修改
配置，保留使用状态。删除有确认框；存在可见全局同名项时明确提示恢复全局及保留偏好。

### 配置弹窗

1. 可直接填表，也可展开“从 JSON 导入”，粘贴后点击“解析并填充”。
2. 支持单个连接对象与 mcpServers 包装；多个服务先选择一个。未知字段、重复键、错误类型
   和越权 stdio 拒绝；JSON 上限 64 KiB，最大嵌套 16 层。
3. type/transport 归一为 http/sse/stdio；有 command 可识别 stdio，仅有 URL 时需选择 HTTP/SSE。
4. 解析后收起并清空原文，表单成为唯一编辑状态。重新导入需确认覆盖，失败保持原表单。
5. 回显仅表单，不生成 JSON。原始 JSON 不落库、不写日志、不进入模型或浏览器持久化存储。
6. HTTP/SSE 填地址、可选 API Key、其他请求头；stdio 填程序、逐行参数、环境变量。
   API Key 快捷项表示 Authorization: Bearer，可替换已保存的同名头；与同时填写的新请求头冲突时拒绝；导入鉴权头保持原语义。
7. 高级配置可限制工具：选择“仅允许指定工具”后测试连接获取名称，复选框默认全选；全部取消
   表示禁止所有工具，保存前确认。已保存的白名单无需测试即可查看；只修改名称/说明不使目录失效。
   白名单搜索保留不可见选项，测试后标记缺失项。测试不保存白名单或配置，保存时才提交当前勾选项。
8. 底部左侧为测试连接，右侧为取消、重置、保存。测试不保存；成功时显示工具数量和名称列表，供核对及白名单选择；保存不启用。新建默认停用并提示尚未使用，管理员卡片提供全员启用入口。

### 卡片工具详情

点击卡片正文打开工具详情。HTTP/SSE 服务立即通过受限发现接口加载工具名；stdio 配置先显示
会启动本地程序的提示，用户点击按钮后才开始发现。详情按白名单标出可用与未启用工具，并显示
启用数量；菜单和卡片启停按钮不触发发现。发现只读取 MCP 工具目录，不调用工具，也不回显凭据。
允许状态以绿色胶囊显示，未允许状态为灰色胶囊；各行胶囊统一在右侧、展开箭头前对齐，工具名较长时换行，便于扫描白名单权限。
详情标题的绿点只表示本次工具发现成功，不再用配置启用状态代替连接状态。

卡片仅显示使用状态，不展示连接状态胶囊；列表加载、刷新及配置变化不触发连接检测。
首次加载、刷新按 effective_enabled 和名称排序。打开 HTTP/SSE 工具详情时发现目录；stdio 由明确点击启动。
发现成功不保证后续业务调用持续成功。
工具详情支持名称/用途搜索，描述按配置凭据脱敏并限制到 2000 字符，只按文本展示，不调用工具。

### 统一工具选择与探测调度

`core/mcp_config.py` 的 `select_mcp_tool_names` 供管理发现与 Agent 装配共用：
NULL 不限制，空名单禁止全部，其余取目录交集。缺失项通过 missing_allowed_tools 返回，
既不扩大授权，也不阻断其他允许工具。未知目录不推断缺失项。

前端没有后台健康检测。`McpToolDetails` 负责主动打开的目录展示，管理组件负责配置与使用操作；
关闭详情或卸载会取消请求，迟到响应不会覆盖当前详情。
`ChatRuntime.mcp_discovery` 持有进程内协调器（`services/mcp_discovery.py`）：
最多四个管理发现连接，手动请求优先于已排队后台请求，不抢占正在连接的任务。
排队最多 5 秒，超时返回 error_code=busy；实际连接最长 15 秒，连接超时返回 timeout。
请求复用同一 id/version 的 HTTP/SSE 任务，单个订阅者取消不影响其他订阅者；最后订阅者取消才关闭任务。
仅成功的已保存 HTTP/SSE 脱敏目录缓存 30 秒，上限 128 项；不缓存草稿、stdio、连接配置或凭据。
每次读缓存前仍校验当前用户权限、可见性和版本；refresh 绕过旧缓存，并与进行中的同版本发现合并。
配置修改由 version 自然使缓存失效，运行时 Agent 仍自行发现，不从管理目录缓存构建工具。

## 凭据与失败边界

headers/env 的字面值以明文保存在数据库 JSON 字段中；全局完整 `${ENV_NAME}` 引用标记为
reference，运行时再展开。管理 API 不回传凭据值，编辑只返回键名与配置状态。数据库查询、
转储和备份均可读到字面凭据，因此应作为含有凭据的数据保护。

API 的凭据更新为 `{set, remove, clear}`：未提供保持，set 替换指定键，remove 显式删除，
clear 清空且不能同时 set/remove。用户配置不能引用服务端环境变量；个人覆盖不继承全局凭据。
改变 URL 时界面提示保留凭据的发送目标变化。Token 应放入请求头或环境变量，不放在 URL、
命令参数、名称或描述中。普通用户看不到共享项连接详情，管理员管理详情仅供可信管理者。

连接测试排队最多 5 秒、实际连接最多 15 秒，每个进程最多 4 个管理测试/发现同时连接；
只进行工具发现，不调用业务工具。stdio 草稿/已保存测试仅管理员可执行；可见共享 stdio 的
工具详情仍需用户明确启动。请求断开取消当前订阅，最后订阅者取消时关闭资源。
测试结果返回工具数量、原始名称列表及分类诊断，不回显第三方原始错误；工具名称按文本显示，
测试成功不代表持续健康。

运行时单服务配置解析、连接或工具定义失败不会阻止其他服务，也不会改变来源；失败构建不缓存，
下一轮可重试。空白名单不暴露任何工具。发现和调用错误向模型返回安全摘要，取消保持取消语义。

所有 MCP 工具通过 `core/hitl.py` 动态登记审批，不信任远端 readOnlyHint；PTC 仍只含已明确
允许的只读工具。MCP 工具名称加入服务命名空间与连接指纹，防止服务同名工具互相覆盖，
并阻止审批期间地址/凭据改变后，旧工具调用直接使用新连接。新配置需要新的工具调用和审批。

当前正在执行的 Agent 保持已构建配置；后续新消息按最新配置构建。审批恢复若需要重新构建
且配置已变化，不承诺恢复旧连接：旧指纹工具无法调用，需要重新发起并确认。没有保存旧凭据
版本来绕过管理员变更。此处是实现明确的恢复边界，不能描述成跨重启的旧配置持久化快照。

开发 user_id 仍是模拟身份，LocalShellBackend 不是安全沙箱；本功能不构成生产多用户密钥隔离。

## 数据与事件流

用户表单 → API schema → McpManagementService（用户/角色/版本/配置校验）→ repository/mcp.py
事务写入 → 下一轮读取当前用户配置和偏好的一致 SELECT 快照 → 选择来源 → 解析凭据与变量展开 →
MultiServerMCPClient 工具发现 → 命名空间、错误脱敏和 HITL → Agent。

缓存标识为同一快照 `(id, version, user_enabled)` 的稳定摘要，覆盖增加、修改、删除及个人偏好
变化；不含凭据。依赖环境变量的凭据变化通过重启进程生效。工具目录和 Skill 依赖检查采用
当前用户实际启用项，不把停用或被覆盖配置当作可用服务。

## mcp.json 与初始化

仅 `uv run melonclaw-db-init` 读取种子。按 global slug 缺失补录，新导入的系统 MCP 默认全员启用，
用户没有个人停用偏好时会显示“已添加”；已存在行跳过，不覆盖管理员修改或个人偏好。
不创建个人配置和偏好。文件为空/缺失时正常运行；存在但格式错误明确失败。
删除种子对应行后再次初始化会补录并默认全员启用；日常撤下使用全员停用，永久移除需同时移除文件条目。
运行时只读数据库。种子使用环境变量引用，不写明文凭据。

表结构由 schema.py 定义，没有迁移。旧开发库需要显式清空后初始化，启动不会自动建表或修补。

## API

| 路径 | 用途 |
|---|---|
| GET /api/mcp | 按当前用户和角色返回列表 |
| POST /api/mcp | 按角色创建，默认停用 |
| GET/PATCH/DELETE /api/mcp/{id} | 管理者详情、版本化修改和删除 |
| PUT /api/mcp/{id}/global-state | 管理员全员启停 |
| POST /api/mcp/{id}/add | 添加确切记录 |
| PUT /api/mcp/preferences/{slug} | 个人使用偏好 |
| POST /api/mcp/{id}/test | 管理者测试已保存配置，返回发现的工具名称 |
| POST /api/mcp/{id}/tools | 可见配置的工具名称/用途、白名单允许状态与缺失项；按 id/version 校验，支持 background/refresh 和取消 |
| POST /api/mcp/test | 测试未保存草稿，可引用有管理权限的 base_id/version 保留凭据；返回发现的工具名称 |

服务端拒绝非法输入并隐藏请求中的秘密；不可见记录返回 404，越权管理返回 403，版本/唯一性
冲突返回 409。连接失败是结构化测试结果，不是原始第三方异常。

## 运行与验证

```bash
uv sync
uv run melonclaw-db-init  # 仅对已清空或首次创建的开发库运行
scripts/check.sh
```

字面凭据以明文存入数据库。部署者应限制数据库账号、访问权限、转储和备份的读取范围；
应用 API 不回传凭据值。环境变量引用仍只允许全局配置，个人配置不能读取服务器环境变量。

- 单元/API 回归：角色归属、可见性、覆盖、不回退、版本冲突、明文存储但 API 不回显、编辑保留、导入/保存分离；白名单交集、缺失项与描述脱敏，队列优先级、合并、缓存版本/有效期及共享取消。
- PostgreSQL：`tests/test_mcp_postgres.py` 使用随机独立 schema，验证索引、事务及偏好保留，完成后清理。
  需通过环境变量 MELONCLAW_TEST_DATABASE_URL 提供测试连接，不使用公开示例凭据。
- stdio：临时本地 FastMCP 验证工具发现成功且测试不调用业务工具。
- 前端：导入/凭据不回显；快捷密钥替换、白名单保留/搜索/空名单确认，列表加载/刷新不探测、主动详情发现与取消，稳定排序、管理员启用入口，详情用途与搜索。

完整工具级可视化管理、统计审计、批量导入、生产身份与沙箱不在本期范围。
