# 环境变量与聊天准备缓存

状态：已实现；数据库升级、服务切换由部署者执行。

## 背景与行为

用户上传 Skill 后可自行维护脚本需要的环境变量。拓展页在技能后提供“环境变量”表格：管理员管理系统共享，普通用户仅管理个人项；共享记录不出现在普通用户的列表。启用的个人同名值覆盖共享值，个人停用、删除或不存在时，自动使用启用共享值。没有个人偏好或阻断回退占位。MCP 的来源、偏好、停用不回退、工具白名单与审批规则保持原样。

创建默认启用；名称固定，改名须新增再删除。值仅返回后端生成的脱敏预览：超过 8 字符显示前后各 4 字符及中间三个星号，不超过 8 字符全部遮盖，空字符串也显示 11 个星号；编辑默认保留旧值，编辑表单填写新值才提交，留空保留旧值；新增或 API 可设置空字符串。启用的个人空字符串也覆盖共享。名称最多 128 字符，说明 500 字符，值 8192 UTF-8 字节；值和说明须为有效 UTF-8 文本且不能含 NUL。每个作用域最多 200 项，启用项名称和值合计最多 64 KiB。删除和所有更新校验 expected_version。

HOME、LANG、TZ、LC_* 和运行时构造的 PATH 自动提供，不能在资源管理或聊天覆盖。未设置的 HOME 使用进程用户目录，LANG 默认 C.UTF-8，TZ 默认 UTC。平台配置／凭据、动态链接、Python 和 Shell 控制变量禁止注入；供应商 api_key_env 指定的名字也不能作为业务变量注入。

业务变量唯一来源为数据库，不再从部署环境默认凭据名单或 MELONCLAW_SHELL_ENV_ALLOWLIST 透传。模型、数据库、监控和现有共享 MCP 的 `${VAR}` 机制继续使用各自配置入口；环境变量资源不成为模型或 MCP 凭据来源。

## 数据与入口

- `database/schema.py` 定义 environment_variables 与 environment_operations；增量步骤为 `20261017_environment`。
- `repository/environment.py` 处理唯一约束、范围内数量／大小限制、版本 CAS、暂存过期和原子幂等提交。
- `services/environment.py` 处理服务端角色范围、保留名及脱敏元数据；管理接口不能指定 scope 或 owner。
- `services/environment_chat.py` 先提取真实输入并替换为不含值的草稿引用；`tool/environment.py` 只接受引用和脱敏清单。
- 管理 API 为 GET/POST `/api/environment`、PATCH/DELETE `/api/environment/{id}`。更新／删除使用 expected_version；只返回元数据或操作回执，不返回真实值。
- 主 Agent 在构建 Backend 时接收合并结果，子 Agent 复用同一 Backend；不修改 os.environ，不扩大无人值守 Agent 或 PTC 能力。

数据库中的资源值和未决操作值采用与现有 MCP 凭据一致的明文存储保护级别；数据库、转储和备份包含凭据，必须控制读取权限。管理接口不支持读取旧值或复制。LocalShellBackend 没有安全沙箱；能执行脚本的人能使用注入的共享值，本功能不提供宿主进程或文件的强隔离。

## 聊天和 HITL

第一版每条消息维护一项。明确维护指令必须在消息开头，可带“请／帮我／请帮我／麻烦”；新增／替换使用 `设置环境变量 KEY=value`，也支持指令后独立赋值行或 env 代码块。首个等号分隔名称和值；整行首尾空白去掉，引号不去除、变量不展开、命令不执行。需要保留首尾空格或多行值时使用管理页。示例说明、附件和工具响应不被当作用户授权。

启停和删除使用“停用环境变量 KEY”“启用环境变量 KEY”“删除环境变量 KEY”；说明可用“修改环境变量 KEY 的说明：新的说明”。缺值、非法名、多个赋值和超限输入拒绝且不回显原值。

输入先脱敏再进入消息、标题、Checkpoint、模型和追踪；前端的乐观消息、失败回填和提交后的输入框不保留受支持指令的原值。模型只看到当前消息绑定的草稿编号。inspect_environment 只读名称和状态；prepare_environment_change 固定服务端范围、目标版本及变更清单；confirm_environment_change 必须 HITL approve/reject，审批卡不填写值。管理员创建 global 共享项，普通用户创建 user 个人项；管理员也须审批。工具仅主聊天 Agent 可见，不进入子 Agent 或 Interpreter/PTC。

确认时重新校验用户、租户、会话、项目、原始 request_id、角色范围、清单与目标版本，账户共享锁覆盖确认与提交。资源变更与脱敏回执在同一事务提交，重复恢复返回既有回执，不重复写入。角色或目标版本改变则拒绝旧审批。未决操作有效期 24 小时，拒绝／取消清空敏感暂存，过期由访问清理和 Web 每分钟周期清理；已提交操作立即清空 payload。回执保留 30 天，之后清空回执但保留拒重记录，旧请求不能重新执行。清理失败记录固定安全警告并等待下次清理，不输出配置。

## 六因子 Agent 缓存

缓存已组装实例，Checkpoint 和消息仍独立持久化。键包含工作区（含用户）、租户、模型选择、客户端能力、全局资源整数版本、当前用户整数版本。默认选择使用与模型 ID 不同的类型标记；历史消息恢复另带选择策略标记，保持模型删除后的既有默认回放行为。

`repository/resource_versions.py` 提供单进程提交／发布边界，所有模型、供应商、Key、Skill、MCP、偏好及环境变量有效写入显式登记。共享变更推进全局版本，个人变更只推进本人版本；失败可以保守失效，不改变 MCP 业务选择规则。

写操作持内存锁完成事务和版本发布，已进入提交边界的操作受 shield 保护，调用方取消仍完成提交／发布后传播取消。发布同步执行，无中间 await；发布故障会阻止后续缓存读取。查找只短暂获取同一内存锁，不访问数据库。构建锁等待后及构建完成后再核对版本，最多重试三次；旧配置不发布到新版本键。现有 LRU 容量（默认 32）、同键单次构建、MCP 失败不缓存保留。

预热命中直接返回 Agent、实际 ResolvedModel 与 Skill 引用，不解析完整模型、不查询资源版本、不扫描 Skill、不发现 MCP、不加载环境值。选定 Skill 和执行前提示都使用该 Agent 的固定引用，不再逐轮扫描文件。未命中才读取配置并创建快照。当前运行持有原实例，保存成功后的新准备请求使用新版本；审批和问答恢复重新准备，读取当前可用配置。

仅支持单 Web 进程；重启后从数据库重建。手工 SQL、离线文件修改和部署环境变化需停服维护后重启，不支持多进程失效传播、在线文件监听或进程外修改自动检测。

## 请求准备与权限

Cookie 会话、当前用户／租户、原登录用户／租户通过一次联查实时验证。API 传服务端领域 UserContext；prepare_context 再联查会话和项目并复用结果，不再单独读取项目。常规消息、审批恢复、问答恢复及同次过期问题收尾复用该准备上下文，不跨请求缓存身份。服务层不导入 Request，不接受客户端“已验证”标记。

这是两次主要身份／归属读取，不是整条请求只有两次数据库往返。账户锁、会话锁、幂等检查、待交互账本、消息及附件事务、Checkpoint 和工具仍有必要 IO；副作用提交中的实时权限和 CAS 不删除。终态回放及抢锁失败不构建 Agent。准备耗时从认证依赖入口计时，包含账户锁等待和认证，不只计算路由函数内时间。

## 升级与运行

先结束活动运行、停止 Web 并备份。保留历史数据执行 `uv sync --locked` 和 `uv run melonclaw-db-update`，首次空库才运行 `uv run melonclaw-db-init`。服务启动不自动升级。

新版本移除了旧透传。升级后先仅开放管理员管理入口，在“拓展 → 环境变量”受控录入此前 Skill 实际需要的共享变量，核对启用状态后再开放聊天；不自动导入整个 .env，不在终端、日志或迁移文件里打印／写入真实值。路径按字面值填写，不使用 `${HOME}` 插值。未录入变量不会从旧环境兜底。

### 本机业务配置迁移记录

2026-10-18 已通过现有管理 API 将九项业务变量录入为已启用的系统共享项，并验证重复录入不会覆盖已有值或更改启停状态。随后只读核对数据库值与源配置一致且实际生效，再从本机 `.env` 删除对应九项业务配置及废弃的 Shell 透传白名单；其他部署配置保留，全程不输出值。

一次性导入工具及其专用代码、测试和操作说明已按用户要求移除。后续通过“拓展 → 环境变量”或聊天 HITL 维护配置，运行时不读取 `.env` 业务配置作为兜底。已启动的宿主进程可能仍持有此前环境，验证清理后的启动环境需重启后端。

清理后在显式去除继承业务变量的子进程验证：宿主环境无上述九项，数据库仍提供全部九项非空有效配置；`scripts/check.sh` 后端及前端完整检查通过。
