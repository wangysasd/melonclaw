# 聊天确认与问题卡

状态：已实现。日期：2026-10-02。

## 背景与目标

审批原有暖黄色大背景、棕色文字和多层边框与轻量聊天执行区不协调，原始 JSON 默认展开使用户难以先辨认授权对象。问题回答与工具授权也需要明确区分。

本次实现聊天交互建议的第 1、4 项：统一卡片样式、优化授权信息与提交路径，并明确问题与授权语义。特殊结果组件、长任务状态和全面错误恢复属于后续工作。

## 方案与关键选择

- 卡片共享页面中性背景、边框、圆角和 14px 正文。选项与底部按钮统一桌面 32px 高、8px 圆角；窄屏最小高度 44px。尺寸由卡片局部变量统一维护。授权使用「需要你允许这项操作」与「等待确认 · 仅限本次」，问题使用「需要你补充信息」与「等待回答」。
- 文件操作展示目标、写入内容或修改前后文本；删除标明影响；Shell 展示完整命令，工作目录来自参数或明确标为当前会话工作区。内容与参数只读展示，不执行代码。
- 安装 Skill/MCP 复用既有清单。能够明确展示对象的操作默认收起原始参数；未知操作或参数无法解析时默认展开，避免摘要缺失。
- 单项允许／拒绝直接提交，拒绝可先补充原因；编辑参数和提供结果仍需显式填写并提交，工具名保持固定。多项逐项选择后按原 interrupt 分组提交，无默认批准。
- 问题卡继续支持单选、多选、自定义回答和跳过。跳过只提交问答取消，不作为工具授权。等待期间可编辑下一条草稿，但发送锁定，输入区与发送按钮明确区分等待回答／等待确认。输入区以当前有效问题／审批为等待依据，过期问题不被遗留的 waiting 状态继续锁定。
- 决定记录只在服务端确认恢复后显示，不用点击或 HTTP 请求开始推断接收成功。它与工具执行结果分开表达。

## 数据与事件流

历史接口或 SSE 提供待处理审批／问题 → 前端展示同一协议下的卡片 → 用户明确决定 → 现有绑定审批接口或问答接口 → 服务端校验并恢复 Checkpoint。

审批恢复收到对应消息的 `message_started` 且 `resuming=true` 后，前端按批次去重，在助手消息内保存工具名与决定类型的简短记录。记录不保存参数或拒绝正文，也不宣称执行成功；后续结果沿用执行区。

此记录是当前页面会话缓存状态，不是持久审计。刷新或重新同步历史后仍以服务端工具历史为准。本次不扩展数据库、历史协议或 Agent 权限。

## 实现位置

- `frontend/src/components/ApprovalPanel.tsx`：单项直接提交、多项选择、编辑／返回结果校验和失败反馈。
- `frontend/src/components/ApprovalActionSummary.tsx`：服务端脱敏参数的只读摘要与文件预览。
- `frontend/src/components/UserQuestionPanel.tsx`：问题语义和统一卡片外壳。
- `frontend/src/components/ChatView.tsx`、`Composer.tsx`：输入锁定原因、等待状态和决定记录展示。
- `frontend/src/hooks/useChatStream.ts`：服务端恢复确认后的页面内决定记录。
- `frontend/src/styles/chat.css`：共用样式与窄屏布局。

## 失败与安全边界

沿用服务端批次、消息与会话归属校验；直接按钮不扩大 allowed_decisions。JSON 编辑只接受对象，不能更换工具名。提交期间禁用交互，并用 ref 阻止重复提交。提交失败显示可恢复错误，状态不明时先重新同步，不能自动重放带副作用操作。

问题过期仍由服务端拒绝并在新消息前代答取消。卡片视觉统一不改变问题跳过、HITL 或 PTC 边界。预览只显示服务端已脱敏内容，不能提供生产用户隔离；开发模拟身份和 LocalShellBackend 的既有部署限制不变。

## 运行与预期结果

沿用 README 的后端与前端启动方式；本次无需数据库初始化。聊天触发文件写入／修改、命令执行或安装时，检查授权对象与影响并提交；触发 `ask_user` 时回答或跳过。

预期：单项批准／拒绝一次点击即可提交；多项仍明确逐项选择；编辑与手工结果有独立输入验证；等待原因在输入区可见；仅服务端确认恢复后出现决定接收记录。

## 验证记录

验证覆盖单项直接批准与拒绝、可选拒绝原因、未知操作完整参数、命令和修改预览、多项 interrupt 分组、JSON 编辑、提供结果、失败重试、服务端确认前后记录，以及既有问题回答与过期规则。完整 `scripts/check.sh` 通过：后端编译、pytest（含架构和文档链接）、Ruff、锁文件校验，前端 lint、类型检查和 Vitest。固定测试数据的组件预览在桌面和 390px iframe 视口检查，无横向溢出，正文 14px，窄屏操作按钮 44px。历史截图对应首次优化时的样式；后续按钮尺寸调整为桌面 32px 高、8px 圆角，当前视觉状态以代码和最新验证为准。底部跳转入口聚焦卡片本身，避免误触直接授权。

视觉验证只覆盖独立组件预览，未连接真实模型、数据库或 MCP，也未验证完整聊天布局的端到端运行。页面内决定记录不跨刷新持久保存。
