# 定时任务

状态：已实现，2026-10-15 完成任务可靠性、交互与通知后端收尾。
验证范围与可重复证据见[定时任务验收](task-center-acceptance.md)。

## 背景与目标

定时任务围绕“保存任务要求与计划 → 后台执行 → 查看结果、取消或重新运行 → 会话追问”工作。任务不绑定项目/Skill，每个任务有一个属于当前用户的固定普通会话，关闭浏览器不会停止后台执行，Web 停止则中断任务。同一任务的后台执行与用户追问共享业务历史，分别管理运行状态和权限；对话与表单共用任务保存服务。

## 定义与状态

TaskDefinition 仅包含 name（1–120 字符）、instruction（1–12000 字符）、明确的数据库 model_id（custom: 前缀）和 schedule。创建/编辑请求在定义外携带 enabled，持久化只以 tasks.status 的 enabled/paused/archived 为准，不重复保存 enabled。

TaskRun 保存独立 UUID/thread、排队时的定义与任务版本、模型展示名、手动/计划来源、排队/开始/结束时间、结果和错误。状态只有 queued/running/succeeded/failed/cancelled。历史配置用于解释本次结果；“重新运行”通过同一个运行接口使用任务当前配置，不重放旧快照。模型执行前从数据库重新解析当前可用模型和凭据，并在同一事务同步运行快照与助手消息的模型展示名；排队时尚未解析的自动运行可能暂显示模型 ID。不保存 Key、地址、请求头或权限摘要。

## 计划规则

所有计划使用北京时间（固定 UTC+08:00），支持 manual、once、daily、weekly。一次性时间必须带时区并精确到分钟；新建或改变一次性计划时必须是未来时间。每天/每周只保存时分，每周 0=周一、6=周日。前端日期和结果时间也统一显示北京时间。

Web 内置 APScheduler 默认每 2 秒检查到期计划，固定允许 60 秒正常轮询延迟。超过此时间视为错过，直接推进到未来；上一轮仍排队/运行则跳过本周期。跳过只记录脱敏日志，不创建 TaskRun，不补跑停机期间的历史周期。入队与计划推进在同一事务中完成。

暂停只停止后续调度，已有运行继续，也可手动运行。恢复循环计划从未来开始，过期一次性计划直接结束。归档保留历史、取消排队记录，已开始的运行继续完成；归档后不能编辑或运行。

## 组装与执行边界

`core/agent.py` 的 unattended 分支仍组装 MelonClaw 统一助手，主/子 Agent 共用调用预算和停止标志。允许文字生成、已授权的公开搜索、write_todos、当前任务历史读取和受限子任务；子 Agent 不能继续委派或结束主任务。主 Agent 可在明确的有限目标全部完成时调用 complete_task；它只设置本轮内存标志，成功交付且版本未变时由执行器暂停未来计划。

`middleware/task_policy.py` 过滤模型工具目录、预检整批调用并在工具入口再次校验，未知工具默认拒绝。`backend/task_readonly.py` 不挂载任何主机/项目文件或长期 Store，文件、Shell、MCP、Interpreter、人工输入、安装和任务管理能力均不开放。不自动批准工具或恢复 interrupt。权限受限是服务端边界，不依赖提示词自律。

本轮实际执行时间和计划时间以北京时间加入提示词，给“今日/本周”任务明确日期依据。模型与工具预算由 Settings 控制；完整运行默认 1800 秒，包含模型解析、历史摘要、Agent 构建与执行，文字最多 200000 字符。仅提取主 Agent 正文并脱敏，不公开 reasoning、子 Agent 正文、工具参数或原始返回。不持久化工具过程事件；执行中仅在正文变化时按轮询间隔提交有界部分结果，状态/取消检查继续进行，终态始终原子落库。超时、越权、上下文溢出、空答案或意外中断均明确失败，部分内容不标完整成功。

后台 Agent 复用 Web 的数据库和 Checkpointer，读取本任务固定会话的已结束的公开消息，不启用其他聊天或 Memory；每次执行通过普通会话消息交付状态和正文。Agent 的 task-run 上下文与用户追问的 Conversation Checkpoint 独立。Checkpoint 使用精确 `task-run:<UUID>`；默认每小时清理完成超过 30 天的任务 Checkpoint，保留任务、结果和聊天。

## 数据与事务

仅三张任务表：

- tasks：定义、唯一状态、版本、下一次计划与 conversation_id；所有者复合外键保证会话归属，一任务一会话。
- task_runs：队列、执行状态、结果与快照。
- task_operations：用户/租户/幂等键和请求摘要、可过期的已提交响应。

独立任务通知接口、已读字段和通知索引已删除，结果通过固定会话与运行记录读取。列表和历史查询只取摘要，任务会话读取完整结果，定时任务只展示配置和运行摘要。

列表字段固定为任务名称、任务模型、执行计划（频率、星期、运行时间）、状态、最近一次运行、下一次运行。最近运行显示实际开始时间（未领取时为入队时间）及状态；下一次运行独立展示北京时间或暂停、归档、计划结束、手动运行。查看会话、运行、编辑、归档、暂停/恢复五个操作保留，归档后的写操作仍禁用。

任务名称直接打开固定会话；最近一次运行的状态/时间打开运行记录抽屉，不再有独立详情页。抽屉保留全部历史、执行快照、计划/实际时间、失败诊断与取消当次运行。关闭后列表筛选和页码不变，保存留在列表，运行/保存并运行打开会话。历史分页重置选择，同页刷新不替换手动选中的旧记录；切换任务重置抽屉，历史列表与单次结果均校验所属任务。取消不等于暂停后续计划，提交请求后仍等待后台确认终态。

管理写入、领取、取消、归档、计划推进和终态共用短事务锁。部分唯一索引保证一个 Task 只有一个 queued/running；任务加计划时间唯一键防重复调度。单实例锁限定执行器，短事务保证配额，模型执行不持有数据库事务。管理中的模型读取复用事务连接，防止等待全局锁的请求耗尽连接池。

Web 生命周期在运行时初始化完成后启动 TaskScheduler，关闭时先停止扫描和任务，再关闭共享数据库/Checkpoint。APScheduler 只注册一个内存 interval job（max_instances=1、coalesce=true），不为每个业务任务创建 APScheduler job/store。扫描处理过期队列、计划、定向清理和按空余名额领取；异步任务集合负责并发生命周期。扫描函数的 max_instances 不替代执行并发限制。

默认全局并发 2、每用户 1、每 2 秒扫描/按变化保存进度/检查取消、排队上限 24 小时。执行器在独占数据库连接持有会话 advisory lock；第二个实例拒绝启动且不能收敛现有运行。领取、进度、状态检查、终态和重启收敛都复用该持锁连接，并串行短事务；只读状态检查不取任务全局排他锁，继续验证同一 backend PID，写事务仍取得配额/账户保护锁。连接失效或后端会话变化则禁止旧执行写入，暂停调度、停止任务，需重启 Web。无逐任务领取令牌/续租，无独立心跳表。

正常 Web 停止时，运行失败并标 service_shutdown；强制退出残留 running 在新执行器取得单实例锁后标 service_restarted，部分结果保留，不自动重跑，queued 继续排队。执行中取消先写请求，后台停止并等待本地协程退出后更新终态；远端已发出的请求可能仍在处理。`/api/ready` 同时要求 Web 和执行器就绪，状态 API 从进程内读取。

此方案只支持单实例 Web，不支持多个进程、滚动重叠启动和 PostgreSQL 事务池代理；任务与 Web 共享资源并随其启停。不是可迁移或自动恢复执行的分布式队列。

Cookie 当前用户和有效租户决定所有读写权限，管理员也不能读取他人的任务。账户换租户/停用/删除仍检查活动运行并自动暂停旧任务。任务与 Project 无关联，删除项目不再影响任务。

## 会话交付与追问

表单创建任务时同事务创建固定会话和一条用户设置摘要；首次绑定默认“新会话”或任务改名时标题自动同步，已有自定义标题保留；表单修改定义时记录实际设置变更。对话创建直接绑定当前普通会话，创建/修改以本轮真实用户消息为来源，不额外插入用户设置摘要。每次运行入队只追加一条助手占位，不伪造用户触发消息。领取、进度、成功/失败/取消、排队超时、停服/重启收敛与该消息同事务更新。run UUID 派生稳定消息 ID/request ID；会话行锁分配 seq，与用户追问并发追加不会撞序号。自动消息不作为普通聊天请求消息对回放。

后台入队时把已结束的公开消息的 ID、seq 和来源 SHA-256 固定在 task_runs.config_snapshot.history；用户新追问在消息事务中复核并把 task_history 固定到 display_metadata。新结果、进行中的占位和未来补充不会改掉本轮来源，重试/审批恢复沿用已绑定历史。完整成功的后台结果才计入 completed_runs，普通问答、失败/取消和部分结果不计完成；模型结合正文判断实际章节或业务进度。

core/task_history.py 统一将数据库历史投影为带编号/日期/来源的 user/assistant 文本；middleware/task_context.py 只在模型请求副本中合并相邻同角色普通文本。数据库消息和 Checkpoint 不合并。本轮用户消息及其工具调用/返回、多模态和推理协议保持；本轮选定 Skill 的系统提示保持。较早工具调用不重放，历史使用公开回答文本，后台与普通聊天不共用 Agent 状态。

历史按 UTF-8 字节保守预留模型窗口的一半。过长时 services/task_history.py 用当前数据库模型增量整理早期摘要，保留近期原文和初始任务设置；原文不删除。摘要固定到本轮来源中，后续执行在来源未变时复用，避免反复总结全文。历史准备默认总计 60 秒，摘要默认最多 4 次，且至少为正式回答留一次模型调用；先校验 UTF-8 切块数量再请求模型。追问的时限包含来源读取，超时或请求取消释放会话锁；后台摘要计入主/子 Agent 共享模型预算，追问摘要单独有界，普通聊天 Agent 继续使用自身调用预算。摘要失败、过大或超过调用上限明确失败；不无声截断或编造缺失内容。摘要可能损失细节，依靠只读原文工具补充。

read_task_history 只读取当前身份、本任务、本轮固定来源，支持 seq 范围和 offset 分页，一次至多 8000 字符；不能指定用户/租户/任意会话或访问外部服务，不进 HITL/PTC。读取时重新验证当前身份、任务归属和来源摘要，跨租户或来源变化拒绝。工具返回的有界摘录会作为本轮工具结果进入执行 Checkpoint；完整历史正文只在请求副本中投影，不自动写入长期 Memory。

任务报告只公开脱敏主 Agent 正文，未完成内容标部分结果。普通聊天的 incomplete/latest assistant 和启动收尾排除 task_run 消息，避免把后台占位当成审批或失联聊天。有限目标的 complete_task 只在最终正文成功、任务仍启用且版本与入队时一致时暂停本任务（goal_completed）；失败/取消和执行中用户更新目标均不停止新配置。目标是否完成由模型根据明确要求判断；普通循环任务不能因单轮完成而结束。

固定任务会话直接追问读取累计历史，无需引用操作；用户可指明日期、章节或具体内容，模型可按需查询已绑定原文。显式报告引用的 API、请求字段、草稿与恢复分支已删除，不为旧协议增加兼容路径，已有消息和正文保留。

会话列表/get/history 同时检查关联任务当前用户及租户，不能通过普通聊天旁路读取旧租户任务报告。固定会话不能移入项目；任务归档且无活动运行后才允许删除会话，避免未来结果投到被删除会话。任务归档保留会话与历史。

## 对话配置

普通聊天主 Agent 常驻 configure_task，不需要工具发现或另一次专用配置提取模型调用。action=inspect 读取本会话实际任务（没有时 version=0）、版本、可用数据库模型、当前北京时间和四类计划；action=save 提交 changes 与读取版本。模型根据本轮用户明确要求提取名称、完整执行要求、计划、模型、启用状态；讨论、追问报告、历史资料或工具结果中的命令不能作为配置授权。缺少时间/要求或频率不支持时先提问，不猜测为其他计划。

新建必须给出名称、要求和完整计划，模型省略时使用管理员设置的系统默认模型（scope=global 且 is_default=true），enabled 默认 true。系统默认未设置、停用或当前用户凭据不可用时明确提示配置或显式选择其他模型，不退回聊天模型、个人默认或任意可用模型；新建时解析并保存明确 model_id，管理员以后切换默认不自动改写既有任务。inspect 返回可用的系统 default_model_id，保存时在事务内重新解析；幂等请求只包含用户参数，默认切换不影响已提交调用的重放。通过 ask_user 选择执行模型时，选项 id 原样使用 available_models 的完整 custom: ID，label 使用 name；回答前不保存任务，回答后仍按当前用户可见模型与有效凭据重新校验。已有任务只合并非空变更字段；未提供或 null 表示保留，instruction 为保留原要求后的完整新正文，schedule 为完整计划。工具不能指定任务、用户、租户或会话 ID；身份、当前会话、真实用户消息、request_id 与工具调用 ID 从 ToolRuntime 注入。服务端在同一任务事务中复核有效租户、会话归属、非项目、消息来源和 pending 聊天轮次。一个会话只绑定一个任务，归档任务只读，跨租户旧会话拒绝。

services/task_configuration.py 复用 TaskService.save_definition 及 repository/tasks.py 保存逻辑，模型读取复用持有事务的连接；启用与定义变更必须验证模型，单纯暂停不依赖失效模型。expected_version 防止覆盖表单或其他轮次的新配置；幂等键由用户消息 UUID 和真实工具调用 ID 派生，task_operations 保存请求摘要与回执。同一调用重放只返回原回执，不重复创建或升版本；参数改变拒绝，已结束轮次不能以新调用写入。成功结果返回实际配置与北京时间的下次有效执行时间，暂停和手动任务无下次自动时间。

configure_task 是限定当前用户、当前普通会话的受控写入，不另加 HITL 确认卡；输入禁止多余字段，错误使用稳定业务信息，未知数据库异常不回传原文，返回不含模型凭据。主 Agent 可见，子 Agent、后台 Agent 和 Interpreter/PTC 均无配置能力；后台仍不能扩大自己的权限或修改计划。聊天保存不立即运行，入队/运行中的快照保持，后续入队使用新定义。任务表数量和 schema 不变，不清理历史。

配置意图、自然语言要素提取及完整 instruction 的合并依赖模型判断；服务端保证结构、授权范围、版本、幂等和保存结果，不能机械保证模型完全理解所有表述。专项使用离线实际 Agent 验证工具链，真实供应商的自然语言效果需结合实际模型观察。

## API 与页面

- GET /api/tasks/status：executor 就绪、运行数、最近扫描时间、错误、计划种类与搜索能力。
- GET /api/tasks：名称/状态筛选与分页；GET /api/tasks/{id}：当前配置。
- POST /api/tasks、PATCH /api/tasks/{id}：definition、enabled，可附 run_now=true 原子保存并运行。
- POST /api/tasks/{id}/runs：当前配置新建运行；POST /api/tasks/{id}/enabled：暂停/恢复；POST /api/tasks/{id}/archive：归档。
- GET /api/tasks/{id}/runs、GET /api/task-runs/{id}：历史和结果；POST /api/task-runs/{id}/cancel：取消。
- GET /api/tasks/{id}/messages：after_seq 与 pending_message_ids 增量读取新消息/非终态任务消息（最多 100 条），复核归属，不构建聊天 Agent。
- GET /api/conversations：可选 task_only=true 只返回关联任务的会话摘要，未指定或为 false 时保留通用查询语义。筛选在数据库排序和 limit/cursor 分页前执行，沿用当前用户/租户和有效会话/项目可见性，不限制任务运行状态；暂停、归档但未删除的任务会话保留。

任务管理写入带 idempotency_key，编辑/运行/归档/启停带 expected_version。保留期内相同键相同请求返回已提交响应，不同请求拒绝；完整回执默认保留 30 天，过期请求返回 idempotency_expired（409），不再次执行。每小时最多清空 100 条过期 response，永久保留原键、请求摘要与时间；即使以后延长保留期，已清空的键也不能再用。拒重标记行数仍随用户操作增长，当前不提供删除标记或重用旧键的路径。保存并运行遇到活动运行整笔回滚。没有旧快照 retry 或 events API。

定时任务只管理配置与运行摘要。任务名称、运行和查看会话直接打开固定会话；完整正文不在运行记录抽屉显示。全局通知铃铛、弹出列表及前端通知轮询已移除，后端通知 API、已读字段和相关索引也已删除。侧栏每 30 秒只查任务会话，合并第一页最多 100 条摘要，不遍历全部分页；刷新与加载更多按会话 ID 去重，继续按置顶/更新时间排序，并保留服务端分页游标。当前可见任务会话每 3 秒同步新增消息和未完成消息，保留正常聊天的活流和阅读位置。任务列表 10 秒、打开的运行记录抽屉 3 秒轮询，隐藏页签暂停并取消请求，切换任务/用户或卸载撤下旧数据。任务结果使用普通 AI 消息组件，显示 AI 正文、普通头像/名称与复制操作，不显示任务名、触发/计划信息、任务状态卡或配置/引用按钮；生成中、失败/取消的反馈与普通回复一致。详细运行状态、取消与表单配置保留在定时任务。保存显示加载态，保存和取消在提交时禁用；列表按任务和动作显示加载，同任务串行，不同任务可并发，完成一项不清除其他任务的状态。正文和按钮以 14px 为主。

聊天创建完成后的会话列表刷新带回 task_id，useChatStream 更新绑定并开启后台消息增量同步；不重载历史或替换当前活流，无需用户刷新。

## 升级和运行

全新库执行 db-init。已有应用首次接入运行 db-update，一次创建当前完整三表。数据库变更前先取消或等待活动任务结束，再停止 Web；服务不自动建表或升级。

已有任务中心数据库必须先停 Web，再运行 db-update 应用 20261015_task_reliability；该升级删除通知字段/索引、允许回执响应为空并增加清理索引，保留任务、运行、聊天及幂等键。新库直接创建当前 schema，不清库。

```bash
scripts/shutdown.sh
uv sync --locked
uv run melonclaw-db-update
scripts/start.sh
curl -f http://127.0.0.1:8000/api/ready
scripts/check.sh
```

`20261010_task_center` 只创建并校验当前完整结构，不迁移未发布的旧开发结构，也不回填历史报告。任务创建和运行交付始终走同一条当前路径。已登记的任务中心结构由后续 20261015_task_reliability 保留数据升级；未发布且未登记的旧结构须停服后显式重建任务相关表，保留账户、模型和普通聊天。清空记录不会改变表结构，db-init 也不会自动清库。开发记录若含已删除协议的操作回执，备份后仅清除对应 task_operations 记录，不为其增加兼容分支。

当前后台不交付文件成果，不执行不可信代码；LocalShellBackend 的普通聊天边界不因定时任务改变。Linux Web 服务运维见[部署说明](../deployment.md#定时任务上线与运维)。

任务列表中，普通用户仅能看到自己创建且属于当前有效租户的任务；当前身份为 system/admin 时可查看全部任务，搜索、状态筛选和分页总数使用相同权限范围。此权限仅用于列表概览，不授予他人任务的编辑、运行、运行记录或固定会话访问权限。
