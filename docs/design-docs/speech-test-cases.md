# 语音识别与合成测试用例

适用范围为 MelonClaw 聊天输入框的麦克风和助手消息的朗读操作。自动化测试使用合成音频、测试账号和模拟供应商。真实供应商和设备单独联调。

## 接口清单

| 功能 | MelonClaw 接口 | 请求 | 成功响应 |
|---|---|---|---|
| 语音识别 ASR | `POST /api/speech/transcribe` | `multipart/form-data` 的 `file` 字段，16-bit PCM WAV | `200 application/json`，包含字符串 `text` 和非负整数 `duration_ms` |
| 语音合成 TTS | `POST /api/speech/synthesize` | JSON，包含 `conversation_id`、`message_id` 两个 UUID，以及可选的 `voice_id`（默认 `stella`，也支持 `tide`） | 首个音频块到达后返回 `200 application/octet-stream`，输出 24 kHz、16-bit、单声道 PCM 流。响应设置 `Cache-Control: no-store` |

两条路由都要求有效 Cookie。存在 `X-Melonclaw-User` 或查询参数 `user_id` 时，必须与 Cookie 身份一致。TTS 只读取用户可见会话中已保存的助手正文。ASR 上传文件上限为 8 MiB，multipart 请求体总上限为 8 MiB 加 64 KiB，录音最长 120 秒。TTS 正文上限为 10,000 个计费字符，汉字计两个，序列化请求体上限为 64 KiB。

| 功能 | DeepSeek 上游接口 | 请求与响应 |
|---|---|---|
| ASR | `POST https://api.deepseek.com/v1/tools/asr` | Bearer 鉴权。整段音频放在 multipart 的 `file` 字段，返回 `request_id`、`text`、`duration_ms`。MelonClaw 转发 WAV 并只保留后两项。 [DeepSeek ASR 文档](https://api-docs.deepseek.com/zh-cn/guides/asr/) |
| TTS | `POST https://api.deepseek.com/v1/tools/tts` | Bearer 鉴权。发送已保存的 `text`、`voice_id`、`format: "pcm"`、`filter_markdown: true`。输出 PCM 流。 [DeepSeek TTS 文档](https://api-docs.deepseek.com/guides/tts/) |

## 自动化用例

后端直接调用 FastAPI ASGI 应用或语音服务，替换语音供应商和仓储。前端在 Vitest 中验证请求、输入框状态和 PCM 排程。表中的编号对应测试场景，可用一组参数化用例覆盖。

| 编号 | 输入或步骤 | 预期结果 |
|---|---|---|
| COMMON-01 | 两条路由缺少 Cookie，或用有效 Cookie 发送跨站写请求 | 分别返回 401 和 403，供应商调用次数为零 |
| COMMON-02 | Cookie 用户与请求头、查询参数或 ASR 表单身份不一致 | 返回 409，不使用请求指定的用户 |
| COMMON-03 | 供应商返回 401，或应用 Cookie 过期 | 供应商 401 映射为 503，浏览器保持会话。应用 401 触发会话过期事件 |
| COMMON-04 | 让上游等待，并检查身份共享锁 | 上游请求前锁已释放。TTS 的消息归属校验在锁内完成 |
| COMMON-05 | 上游拒绝、客户端取消或网络不可用 | 返回固定中文错误或以取消收尾，响应不包含上游诊断或凭据 |
| ASR-01 | 上传 7 个允许采样率（8、16、22.05、24、32、44.1、48 kHz）的单声道或双声道 16 位 PCM WAV | 14 种组合均通过本地校验，WAV 原样转发 |
| ASR-02 | 上传错误 RIFF、非 PCM、8 位、采样率不支持或三声道音频 | 返回 400，上游不接收音频 |
| ASR-03 | 分别上传 120 秒和 121 秒有效 WAV | 上限值允许。超限返回 400，不访问上游 |
| ASR-04 | 分别上传恰好 8 MiB 和多 1 字节的文件，整个请求均在 multipart 总上限内 | 第一份允许。第二份返回 413 |
| ASR-05 | 声明的请求体超限，或不声明长度并持续分块上传至超限 | 两种情况都返回 413。前者无需读取请求体，后者到达总上限时停止解析 |
| ASR-06 | 错误 Content-Type、无 multipart 边界、缺少 file、file 是文本或提供两个文件 | 返回 400 或 422，不访问上游 |
| ASR-07 | 上游返回转写及 request_id，或返回空文本 | 应用只返回 `text` 和 `duration_ms`。空文本不向草稿插入内容 |
| ASR-08 | 上游 HTTP 200 但响应非 JSON、字段缺失、类型错误或时长为负 | 后端返回 503，前端不插入转写 |
| ASR-09 | 缺少 Key，上游返回 400/401/408/413/429/500/503/504，或连接失败 | 缺 Key 不发请求。映射后的状态和固定错误符合约定 |
| ASR-10 | 同一用户并发发起两个识别，另一个用户同时识别。打断首个请求，或模拟达到 180 秒总时限 | 同用户第二个返回 429，其他用户可执行。取消和超时后首个用户名额可重用 |
| TTS-01 | 对可见的已完成、失败、取消或中断的助手消息请求朗读，正文非空 | 按终态规则允许朗读。上游收到正文、指定音色、PCM 参数和 Markdown 过滤配置 |
| TTS-02 | 请求不存在或不可见的会话、其他会话的消息，或用户消息 | 返回 404，供应商不接收正文 |
| TTS-03 | 请求生成中的助手消息或空正文 | 返回 400，供应商调用次数为零 |
| TTS-04 | 省略音色、传 `tide`、传未知音色，或提供非法 UUID、错误类型、额外 `text`／`user_id` | 默认 `stella`，显式 `tide` 生效。未知音色返回 400，JSON 模式错误返回 422 |
| TTS-05 | 发送 10,000 个 ASCII 字符、5,000 个汉字、超限文本，或在缩小 JSON 字节阈值后提交超限 JSON | 两个计费上限值允许。超过任一限制返回 400，供应商不接收正文 |
| TTS-06 | 成功收到多段 PCM、上游 200 但没有音频、上游 401/429/504 且错误体挂起 | 正常转发 PCM 并返回音频响应头。没有首包的失败返回 JSON，上游错误体挂起不拖延响应 |
| TTS-07 | 首包后上游读流失败 | 下游 HTTP 音频流未正常完成，前端展示播放失败。关闭上游连接并释放用户名额 |
| TTS-08 | 等待响应头、等待首块、等待后续块、发送受阻时断开 | 取消当前流并清理。断开清理后，同一用户下一次可以朗读 |
| TTS-09 | 同一用户并发请求，达到进程内全局并发上限，或模拟 TTS 总时限 | 并发拒绝返回 429。首包前总超时返回 504，并释放已占名额 |
| WEB-01 | 录音结束后上传 WAV，收到有文本的识别结果 | 使用 Cookie 和身份头，上传一个 file 字段。文字插入原选区，用户可继续编辑，消息不自动发送 |
| WEB-02 | 等待麦克风授权时取消，录音达到 120 秒，或离开会话和聊天页 | 迟到的麦克风授权释放。达到上限仅上传一次。离开后停止录音或取消转写 |
| WEB-03 | 非安全上下文打开聊天页 | 麦克风入口禁用 |
| WEB-04 | 两条助手消息轮流点朗读，改变音色，再停止 | 同一时刻只有一条。停止时中止请求，改变音色对下次播放生效 |
| WEB-05 | PCM 在样本中间分块，网络晚于播放，或末段先播完再收到网络结束 | 跨块补齐样本，慢块从当前时间恢复排程，播放结束与网络结束均完成后恢复空闲 |
| WEB-06 | 客户端遇到网络异常、取消、转写成功响应字段异常或合成响应缺少流 | 网络失败归一化，取消信号保留。错误响应不写入草稿或开始播放 |

## 浏览器与供应商手工验收

使用隔离的测试账号和简短的无敏感信息语句。网站部署使用 HTTPS，本地可使用 localhost。按场景记录浏览器版本、供应商调用结果、响应码和 UI 状态。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| LIVE-01 | Chromium 与 Safari（含 iOS）分别拒绝、允许麦克风，录制一句中文或英文。保留原草稿和选区 | 拒绝时提示权限问题。允许后仅将识别结果插入选区，麦克风在停止后释放 |
| LIVE-02 | 对包含标题、正文和代码块的短回复分别切换海星和暗潮，播放并停止 | 能听到两种音色。朗读可中止，正常读完恢复空闲。观察上游 Markdown 过滤后的听感 |
| LIVE-03 | 在录音和转写阶段离开聊天。在朗读加载和播放阶段断网或切到另一会话 | 麦克风释放，旧识别不写入，旧朗读停止。恢复网络后可重新操作 |
| LIVE-04 | 在隔离 PostgreSQL 建立两个用户、各自会话和所属项目，用用户 A Cookie 请求用户 B 的会话或消息。再测试已经撤销的 Cookie | 跨归属返回 404，已撤销 Cookie 返回 401。无上游语音请求 |
| LIVE-05 | 通过真实 DeepSeek 将合成测试短句的 PCM 包装为 WAV，再请求识别 | 两个接口均返回 200。PCM 可按响应参数解码，转写与原短句比对。记录时长与格式，凭据留在服务端 |

## 2026-11-16 执行记录

- 语音专项检查通过后端 99 项与前端 27 项，Luna 独立复跑得到相同结果。额外实测非数字 `Content-Length` 时，应用返回 400。
- Luna 使用真实 Chromium、虚拟麦克风和模拟 HTTP 响应运行前端源码模块。采集的 WAV 为 8,236 字节，multipart 文件名、RIFF/WAVE 文件头和 16 kHz 采样率符合约定。实际 Web Audio 上下文按 PCM 采样播放，朗读状态经历空闲、加载、播放、空闲，完成后关闭上下文。本次验证的是语音模块，完整聊天页和设备验收见上表。
- 真实供应商首次联调返回鉴权失败。联调进程继承了与根 `.env` 不同的 `DEEPSEEK_API_KEY`，而 dotenv 默认保留已有环境变量。对同一个 DeepSeek 账户查询接口分别验证，继承的 Key 返回 401，根 `.env` 的 Key 返回 200。
- 在独立进程移除环境变量覆盖后，使用根 `.env` 重新通过两条 ASGI 路由联调。TTS 返回 200 和 105,600 字节的 24 kHz PCM。将这段音频包装成 WAV 后请求 ASR，返回 200，音频时长为 2,200 毫秒，忽略标点与大小写后转写和英文测试短句一致。
- 异常 PCM 已复现。让 `playPcmStream` 收到一个完整的 16 位采样和一个额外字节，例如 `[0, 64, 255]`，并立即正常结束流。等待已排程的采样播放完毕。预期报告不完整的 PCM 样本，实际返回 `done` 并丢弃最后一个字节。HTTP 读流抛错的场景已有单独用例。
