# 聊天错误恢复与发送前反馈

状态：已实现。

## 背景与目标

断线只说明客户端没有收到完整结果，不能据此认定工具没有执行。附件上传和解析也是不同阶段；输入文字不能绕过附件就绪校验。

## 方案与数据流

模型适配器在异步生成、流式生成边界标记 `ModelInvocationError`。执行服务保存 `model_execution_failed`、`tool_execution_failed` 或通用 `agent_execution_failed`，并随 error SSE 发送；历史读取保留相同错误码。取消不转换成模型失败。

浏览器连接失败、读流断开和缺少结束事件标记 `network_disconnected`，保留已接收内容与未确认消息。消息显示结果待确认；同步按钮仅 GET 历史，不重发消息、审批或工具。相同会话同步失败时保留现有内容。模型失败提供模型配置入口；工具失败展示失败项和已完成项，即使助手最终回答成功，也保留工具失败提示。

附件分上传、解析、模型支持三个门槛。上传失败可重试，沿用上传幂等键；有失败项时不能静默丢弃它并确认其余附件。解析失败／超时提供重新解析或移除操作；短暂查询失败继续查询并展示连接提示。图片必须有模型明确声明的 image 能力。任一附件未就绪或不支持时，即使有文字也禁止发送；归档附件无需解析。

## 失败与安全边界

不会自动重跑整轮，也不会把断线当成服务端失败或撤销。所有已尝试工具都可能已经产生副作用，用户先核对历史，再用新消息说明剩余任务。一般内部异常不能伪装成模型异常。前端门槛不替代后端附件归属、类型与模型能力校验。不新增数据库字段或迁移。

## 运行与验证

正常启动后，断开连接并同步会话；观察原内容保留且没有第二次执行 POST。对不可用模型观察模型错误和配置入口；对失败工具观察已完成与失败列表。上传失败后重试观察同一 client_request_id；带文字的未解析附件和不支持的图片应仍禁止发送。

自动化覆盖断线保留和同步不重发、发送前附件门槛、上传重试幂等、模型失败归属及取消传播；完整验证使用 `scripts/check.sh`。外部模型真实失败未在自动化中调用。
