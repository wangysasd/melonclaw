# 聊天语音输入

状态：已实现。

## 背景与目标

聊天输入需要一次说完再转成文字。交互对齐 [DeepSeek chat-demo](https://github.com/deepseek-ai/chat-demo) 的语音输入：点击开始、再次点击结束、转写中可取消、最长 120 秒。识别使用 [DeepSeek 语音识别](https://api-docs.deepseek.com/zh-cn/guides/asr) 的整段上传接口，不使用流式识别。朗读见[朗读助手回复](speech-read-aloud.md)。

## 方案

浏览器采集单声道音频，编码为 16 kHz、16-bit PCM WAV，通过 `POST /api/speech/transcribe` 交给后端。后端校验后转发到 `https://api.deepseek.com/v1/tools/asr`，只把 `text` 和 `duration_ms` 返回页面。文字插入输入框当前光标处，由用户修改后再发送。

凭据只使用 `core/config.py` 从环境读取的 `DEEPSEEK_API_KEY`，与联网搜索、网页读取相同。未配置时聊天仍可用，语音识别返回「语音识别尚未配置。」。不读取当前聊天模型或 `provider_user_keys` 的 Key，Key 不下发到浏览器。

## 数据流

1. 安全上下文中，输入框右下角的麦克风调用 `getUserMedia`（单声道、回声消除、噪声抑制）。
2. `AudioContext` 以 16 kHz 采集 PCM。满 120 秒自动结束。
3. 页面把样本编码成 WAV，用 Cookie 会话和 `X-Melonclaw-User` 上传 `file` 字段。
4. 服务端先校验请求来源与 Cookie 会话并释放身份共享锁，再流式解析 multipart。整个请求最多 8 MiB 加 64 KiB，按收到的字节数执行。单个音频文件最多 8 MiB，只接受允许采样率的 16-bit PCM。
5. 每个用户同时只放行一个识别请求。`httpx` 转发整段音频，建连最多 10 秒，外部调用总时限 180 秒。页面断开或用户取消时取消上游请求。
6. 转写文本去掉首尾空白后插入按下麦克风前的选区。切换用户、项目或会话，以及离开聊天页时，取消当前录音或转写并忽略迟到结果。

## 设计选择

- 录音和编码留在浏览器。MediaRecorder 常见输出不是接口要求的 WAV 或 Ogg Opus，因此沿用 chat-demo 的 PCM WAV。
- 代理放在 `services/speech.py` 和 `api/routes/speech.py`。它不是 Agent 工具，不进审批或代码解释器，也不写入附件、消息、Checkpoint 或追踪。
- 上游 401 映射为 503「语音识别鉴权失败。」。浏览器把 HTTP 401 视为登录失效，不能把供应商鉴权失败原样返回。
- 请求体或文件超限时返回 413。录音长于 120 秒时返回 400。上游 413、408、429、503、504 分别对应文件过大、上传超时、请求过多、服务繁忙和识别超时。
- 768px 及以下录音时隐藏读秒，输入框保持挂载但文字不可见，上面显示 100–4000 Hz 的频谱。系统要求减少动效时，光圈不呼吸，频谱不逐帧更新。

## 失败与边界

非 HTTPS 且非 localhost 时按钮置灰，提示需要安全页面。拒绝麦克风或没有设备时给出对应说明。空转写不插入文字。录音或转写期间不能发送或加入队列。回复生成中的停止按钮仍可用。音频不持久保存。multipart 解析可使用系统临时文件，读完或中断时关闭。单个 Web 进程内，同一用户的第二个并发请求返回 429，结束后释放名额。

## 验证

接口清单、自动化用例和真机验收步骤见[语音测试用例](speech-test-cases.md)。

后端用例覆盖 WAV 校验、身份校验先于读取、分块上传超限时返回 413、总超时、上游状态映射、同用户并发拒绝和断开后再次请求。前端用例覆盖 WAV 头、在光标处插入、离开聊天或切换会话时取消，以及非安全上下文禁用。真实麦克风和真实识别取决于浏览器权限与 `DEEPSEEK_API_KEY`，自动化检查使用模拟上游。
