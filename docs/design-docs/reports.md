# 投诉举报与反馈

状态：已实现。日期：2026-11-26。

## 目标

访客与登录用户通过「意见反馈」提交问题、建议、投诉或举报。访客凭工单编号和查询码查进度，登录用户查看自己提交的工单。管理员在系统管理受理、备注、反馈和办结。办结必须留下给用户看的结果，且不会因为办结本身删除消息、封禁账号或下架文档。

## 入口

| 谁 | 从哪里进入 |
|---|---|
| 未登录访客 | MelonClaw 与 RMS 登录页的「意见反馈」。不需要登录 |
| 登录用户 | 头像菜单「意见反馈」 → 「提交反馈」。同页查询本人提交的工单 |
| 管理员 | 系统管理的「投诉举报」。服务端按当前 `admin` / `system` 逐请求检查 |

「意见反馈」列表下方提供「个人信息申请」文字链接，打开公开隐私说明的申请区。

匿名提交成功后，页面只展示一次工单编号和查询码。登录用户提交后得到工单编号，并可以从成功提示进入「意见反馈」。

访客和登录用户复用同一表单，必填原因和说明，联系方式可选。可按违法不良信息、有害或不当内容、侵权、侵犯隐私等原因提交。涉及回复、文档或账号时，由用户在说明中提供文档名、账号名称、发生时间或必要的内容片段。通用表单只提交用户填写的内容，工单详情不会自动读取或关联私聊原文。账号名称和昵称类问题由值守人员按[人工处置流程](security-assessment-operations.md#账号名称和昵称的举报处置)核查与办结。

## 带对象工单的接口与版本

Web 的新反馈使用通用工单。带对象的提交接口仍按权限校验，已保存的带对象工单继续按保存时的对象和版本处理。

`chat_messages` 没有独立版本字段。助手回复的正文只在 `pending` 或 `interrupted` 推进到终态时写入；已经 `completed` 的回复不会被后续执行改写。因此只接受已完成的助手回复，工单保存会话 ID、消息 ID、序号、创建时间、正文摘要的 SHA-256、字符数，以及最多 160 字的折叠摘要。摘要用于消息后来被删掉时仍能核对，不保存整段会话。

共享文档保存知识库、文档和用户提交时指定的已发布修订。修订行在新版本发布后仍保留，工单继续指向当时的 `revision_id`，不跟随新的当前版本。同样只留修订号、原件哈希、字符数和最多 160 字摘要，不复制整份文档，也不提供从工单下载原文的接口。

这些 ID 在提交时按当前用户权限核对。助手回复沿用会话详情的会话、项目和任务归属规则；文档沿用知识库可见性，并限制为已发布修订。无权引用时统一返回 404。工单不设到消息或文档的外键，删除原内容不会连带删除工单。

## 状态与权限

状态只有待受理、处理中、已办结。受理记录受理人和时间；内部备注、给用户的反馈和办结措施分列保存。用户查询只返回自己的说明、状态、更新时间和公开反馈。内部备注和措施不返回。

匿名工单的查询码由 18 字节随机数生成，持久层只存 SHA-256。只有编号、查询码错误，或用别人的查询码，都返回同一句「编号或查询码不正确」。「意见反馈」按输入的编号筛选最近 100 条工单。输入完整编号后按回车，可以查询自己的任意工单。管理员可以按编号和状态查看留存摘要及原对象状态。核查助手回复时，管理员可显式读取该工单关联的单条完成回复。服务端重验内容摘要，仅返回与举报时一致的正文，核查记录进入原安全审计。

办结必须同时填写公开反馈和实际措施。数据库对同一工单的办结事件有部分唯一索引，服务端在行锁内检查状态。重复或并发办结只保留一次。暂停共享可通过知识库管理的「停用」处理，原因可选「接到举报，暂停核查」。该操作沿用知识库确认、权限和审计流程，管理员在工单记录实际措施。办结只写工单和历史记录。

## 联系渠道与限流

`MELONCLAW_REPORT_CONTACT_EMAIL`、`MELONCLAW_REPORT_CONTACT_NAME`、`MELONCLAW_REPORT_RESPONSE_HOURS` 由 `core/config.py` 读取。只有邮箱格式有效时才展示邮箱；姓名和响应时限也只在邮箱有效时展示。未配置或配置无效时，页面仍可使用站内表单，不显示虚构地址。同一邮箱也是隐私说明里的个人信息申请地址，见[隐私说明](privacy-notice.md)。联系人姓名不是运营主体；主体名称用 `MELONCLAW_OPERATOR_NAME`。

匿名提交默认每个来源地址每小时 5 次，相同内容 10 分钟内不重复建单。匿名查询默认每 15 分钟 20 次，同一窗口内有 8 次失败后暂时拒绝。登录用户提交和按编号查询也有各自的每小时或每 15 分钟上限。限流与去重在单个 Web 进程内存中计数，定期清理过期记录，重启后重新计数。来源地址沿用审计日志的规则：只有直连来自本机时才采信反代传入的地址。

应用日志只记动作名称。安全审计不读取正文，因此查询码、联系方式、投诉说明和被举报内容不会进入审计文件。
