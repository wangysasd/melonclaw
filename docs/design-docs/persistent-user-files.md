# 用户持久文件与代码升级

## 背景与目标
替换代码目录不能影响用户 Skill、上传附件和生成文件。

## 方案与数据流
配置入口 `core/config.py` 默认使用 `~/.melonclaw/data` 和 `~/.melonclaw/workspaces`。Skill 导入服务写入前者，Agent 和附件服务写入后者；数据库仍保存相对路径、归属、Memory 和 Checkpoint。仓库仅分发内置 Skill 模板。

## 取舍与失败边界
不新增数据库结构、不自动扫描旧路径、不在启动时搬迁或覆盖用户文件。迁移需停服并完整复制原目录，冲突先解决；保留原目录直到验证。外部目录不是 Shell 安全沙箱，不改变现有审批和权限。环境变量覆盖仍受支持，配置入口拒绝当前代码目录内的根路径。服务器使用明确的 /var/lib 路径与持久卷，部署者需保证它也不在其他代码目录下。

## 运行与预期结果
首次安装和迁移步骤见 [README](../../README.md#基础配置)。升级保留数据根、工作区和 PostgreSQL；重启后原 Skill 列表、会话文件、附件和记忆可用。已有数据库不需要 db-init 或 schema 更新。

## 验证记录
默认路径、环境覆盖由配置回归测试覆盖；`scripts/check.sh` 全量通过（后端测试、lint、锁文件、前端 lint/类型检查/测试及文档链接）。本机原资源已完整复制到外部数据根并逐字节核对，原目录保留；服务已停止迁移后恢复，公开就绪检查通过；22 条 Skill 索引正文均存在，路径均为相对路径，无需改数据库。仓库旧运行文件 66 个已在校验后删除，保留版本化模板和占位文件。Linux systemd/Nginx 尚待目标服务器验收。真实业务观察点为重启后 Skill 列表、历史会话文件下载和 Memory 读取。

部署入口、权限与安全：`melonclaw-resources --service-stopped` 是运维 CLI，不注入 Agent，不进入 HITL 或 PTC；操作者以文件系统权限授权，输入拒绝重叠目录、链接和特殊文件，全部冲突预检，失败不回显底层异常或文件内容。迁移不修改数据库；重启后的真实会话文件和 Memory 仍需按部署验收清单验证。详见 [部署步骤](../deployment.md)。
