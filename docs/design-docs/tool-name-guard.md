# 空工具名快速失败

状态：已实现（2026-09-28）。

## 背景与目标

完整模型响应的工具名为空时，框架会把未知工具错误交回模型，可能形成无效循环。
本地 langchain-core 1.5.3 的 v3 流式桥接器曾将后续空名称片段覆盖到已有名称上；
护栏不依赖具体供应商，目标是及时结束无效运行，不猜测工具名称。

## 方案与事件流

`core/agent.py` 注册 `middleware/tool_name_guard.py` 的模型响应包装中间件。
模型返回完整响应后，检查所有 AIMessage 的 tool_calls 和 invalid_tool_calls；
名称缺失、非字符串或仅含空白时抛出固定文案的 EmptyToolNameError。
异常发生在模型响应提交到图状态之前，整个批次不会进入工具节点，
也不会生成可供模型自动纠错的 ToolMessage。
现有 execution 失败处理将本轮保存为 failed，并向浏览器发送 error 事件。

## 失败与安全边界

只检查完整响应，不把流式片段暂时没有名称当作错误；不修改名称或参数。
错误文本不含参数、文件路径或凭据。没有新增工具、权限或审批入口。
当前注册于主 Agent，不覆盖独立子 Agent 内部运行；此前已完成的操作不回滚。
这不是底层流式协议修复，也不是通用调用预算或重复失败熔断。

## 运行与验证

重启 Web 服务加载护栏，无依赖或数据库结构变化，不需重新初始化数据库。
`uv run pytest -q tests/test_tool_name_guard.py` 使用离线假模型驱动真实 Agent 图，
覆盖同步、异步、v3 和应用事件投影路径：空名混合批次零工具执行、仅一次模型请求；
正常批次与纯文本响应通过；非法参数调用缺少名称时同样拒绝且不泄露参数。
全量检查使用 `scripts/check.sh`。

验证记录（2026-09-28）：护栏 12 个回归用例通过。全量检查后端 286 通过、1 失败；
失败为既有种子数据与 `test_seed_data_is_system_tenant_and_admin_only` 预期不一致，
与护栏无关。编译、ruff、锁文件检查及前端 lint、类型检查、测试均通过。
