# MelonClaw

MelonClaw 是基于 Deep Agents 的通用 AI 助手，把对话、工具、文件和多步骤任务放在同一个 Web 界面中。你可以用它研究资料、撰写报告、处理文件，也可以通过 Skill 和 MCP 接入自己的工作方法与外部服务。

## 功能与特色

- **多步骤任务**：围绕目标规划和执行，调用工具或子 Agent，并在聊天中查看进展、工具结果和生成文件。
- **资料与文件处理**：上传附件供助手分析，生成可预览、下载的文件；文件栏用“产物”标记生成文件、“上传”标记附件；项目下的多个会话共享工作区。
- **Skill 与 MCP 扩展**：用 Skill 复用工作流程，用 MCP 连接外部数据和服务，支持系统共享与个人配置。
- **模型自主配置**：在页面管理供应商、模型和凭据，支持全局内置模型与个人模型。
- **长期记忆**：按系统、租户和用户范围保留信息，帮助跨会话延续工作。
- **定时任务**：通过对话或表单设置一次性、每天、每周任务，结果持续写入固定会话，可继续追问。
- **过程可观察**：展示执行过程，对需要审批的操作进行确认；可选接入 Langfuse 查看调用链、用量和异常。

首页提供权益、固收研究提示词，点击后可补充研究对象和日期再发送。具体取数能力取决于已安装的 Skill、启用的 MCP 和数据订阅权限。

联网搜索使用内置 `internet_search`，网页读取使用 `web_fetch`；它们在普通聊天主/子 Agent 中常驻，无需发现且不占动态工具池名额，也不在 MCP 服务清单中。其他工具不足时，Agent 通过 `find_tools` 在本次请求内补充能力并继续执行，无需再发一条消息。已从目录获得真实工具名称时，可用 `tool_names` 精确加载，跳过选择模型；最终回执会说明已加载、无匹配或选择失败，加载后仍需实际调用工具才能验证数据服务。搜索所需配置见[配置说明](docs/configuration.md)。

## 本地快速启动

### 准备环境

- Python 3.11+（低于 4.0）与 [uv](https://docs.astral.sh/uv/)。
- Node.js 20+ 与 npm。
- 已启动的 PostgreSQL 14+，以及可连接数据库、创建表的应用账号。
- macOS / Linux；Windows 可使用 WSL。一键启动脚本需要 Bash、`curl`、`lsof`。

以下命令均在项目根目录执行。

### 安装依赖

```bash
uv sync --locked
npm --prefix frontend ci

# 仅在没有 .env 时复制，保留已有配置
if [ ! -f .env ]; then cp .env.example .env; fi
```

### 配置数据库

提前创建 PostgreSQL 数据库，并在 `.env` 中填写连接信息：

```dotenv
DATABASE_URL=postgresql+asyncpg://<用户>:<密码>@<主机>:<端口>/<数据库名>
```

首次启动唯一必填配置是 `DATABASE_URL`，其他项可保持模板值。用户名或密码中的 URL 特殊字符需要百分号编码；不要提交 `.env` 或公开实际连接串。

模型在启动后的页面配置，无需提前填写模型 Key。持久资源与工作区默认保存在 `~/.melonclaw/` 下，不要将它们配置到代码目录内。更多选项见[配置说明](docs/configuration.md)。

### 安装内置资源并初始化

仅在首次使用的数据库上执行：

```bash
uv run melonclaw-resources --service-stopped install-builtins --source .data/skills/shared
uv run melonclaw-db-init
```

资源命令只安装缺失的内置 Skill，不覆盖已有同名资源。初始化创建当前数据库结构、基础配置和管理员 `admin`，初始密码为 `admin`；不会自动清库，也不会创建可用模型。

已有部署请按下方[更新项目](#更新项目)操作。服务启动不会自动建表或升级。

### 启动服务

```bash
scripts/start.sh
```

打开 [http://127.0.0.1:8001](http://127.0.0.1:8001)。后端默认地址为 [http://127.0.0.1:8000](http://127.0.0.1:8000)。

一键脚本默认使用 `dev`、读取 `.env`，并开启开发身份切换，仅用于本机开发。需要分别启动前后端时，见[手动启动](docs/configuration.md#手动启动)；服务器部署见[Linux 部署说明](docs/deployment.md)。

### 配置模型，发送第一条消息

1. 使用 `admin` / `admin` 登录，并修改初始密码。
2. 打开「拓展 → 模型」，配置供应商地址和 API Key，启用供应商，再添加并启用支持工具调用的模型。
3. 新建对话，选择模型，发送“介绍一下你能做什么”。收到回复后，基本链路即已打通。
4. 尝试上传一份资料，发送“总结这份资料，并生成一份 Markdown 文件供我下载”。

没有可用模型时可以管理配置，但不能聊天。初始化不会从环境变量生成模型或选择默认模型。

## 按需扩展

| 想做什么 | 如何配置 |
|---|---|
| 搜索公开网页、读取网页正文 | 在 `.env` 设置 `DEEPSEEK_API_KEY` 后重启；该工具的 Key 独立于聊天模型配置 |
| 使用专业工作流程 | 在「拓展 → 技能」管理 Skill；脚本依赖与外部客户端需另行准备 |
| 连接外部数据或服务 | 在「拓展 → 连接器」配置 MCP，启用服务并限制工具白名单 |
| 给 Skill 脚本提供业务凭据 | 在「拓展 → 环境变量」配置，管理员维护共享项，普通用户维护个人项 |
| 定期执行任务 | 在「定时任务」创建，或在普通会话直接描述执行要求与时间 |
| 查看模型调用与用量 | 按[Langfuse 配置](docs/configuration.md#langfuse-追踪)开启监控 |

启用的个人环境变量覆盖同名共享值；个人停用或删除后回退共享值，保存后下一轮消息生效。业务变量只从数据库注入 Skill/Shell，不再使用 `.env` 的旧默认凭据名单或 `MELONCLAW_SHELL_ENV_ALLOWLIST`。全局 MCP 配置中的 `${VAR}` 仍从服务进程环境解析，数据库环境变量资源不参与该替换；也可直接在 MCP 配置中保存连接凭据。详见[配置说明](docs/configuration.md)与[环境变量设计](docs/design-docs/environment-and-preparation.md)。

定时任务支持手动、指定时间一次、每天或每周，统一使用北京时间。聊天新建任务未指定模型时，使用管理员设置的系统默认模型；需要先确保默认模型可用。任务在固定普通会话中累计结果，关闭页面后仍会执行，但 Web 服务必须保持运行。错过计划不补跑，上一轮未结束时跳过本次；暂停只停止后续计划。

后台任务每次开始执行时，按任务所属用户的当前权限使用有效 Skill、已启用且白名单允许的 MCP，以及公开搜索、本任务历史和受限子任务。Skill 仅支持读取指引和引用资料，不执行配套脚本，不访问项目、Memory、Shell 或交付文件成果。资源更新、删除或停用会影响后续执行，不保存旧资源快照；例如指定的 Skill 被删除，本次结果会说明缺失及跳过的环节。正常生成说明并结束仍记为运行成功，成功状态不保证业务目标达成。

缺少能力时要求 Agent 及时说明并收尾；工具发现最多 4 次（后台主/子 Agent 共用，沿用现有配置），模型/工具调用预算和总运行时限提供强制停止保护，耗尽预算或超时记为工程失败。MCP 外部写入可能已生效，取消或超时不保证撤回。此次能力无需数据库升级，更新代码后重启 Web 即可；详见[任务中心设计](docs/design-docs/task-center.md)和[当前资源与执行保护](docs/design-docs/task-resources-and-execution-guards.md)。

### 聊天安装 Skill 与内置教程

可以在聊天中上传 ZIP 或提供 GitHub/公网 HTTPS 下载地址，明确要求安装、更新或批量同步。单次最多 32 个地址，`skills/` 下的子 ZIP 合集会自动展开，最多 64 个技能；下载地址不必以 `.zip` 结尾，允许查询参数。先查看逐项预览，再允许审批：同范围同名更新且保留启用状态，相同内容跳过；批内同名不同内容会提示冲突，需要明确选择来源。安装失败项可单独重试，已经成功的项无需重装。不会执行包内安装脚本、自动安装依赖或创建定时任务，启用的技能下一轮可用。

同一条安装请求也可附加“并配置以下永久环境变量（已有则替换）”，随后逐行提供 `KEY=value`，最多 32 项。值先由服务端提取、脱敏，环境变量单独审批，整批在同一数据库事务保存；任一项失败全部回滚。管理员保存共享变量，普通用户保存个人变量，重启后仍保留；更新已有项保留其启用状态。技能与变量分别提交，请根据各自回执核实结果。多行值或需要保留首尾空格时使用拓展页。公开下载仅支持 HTTPS/443，拒绝内网、带账号密码的地址，不使用服务进程代理或登录凭据。

询问使用方法时，助手可读取已启用的 `melonclaw-tutorial`；安装能力不依赖该教程。详见[聊天安装设计](docs/design-docs/chat-skill-install.md)。本次增强没有数据库结构或依赖变更，更新代码并重启服务即可。

### 聊天安装和更新 MCP

可以在聊天中粘贴 `mcpServers` JSON，并明确要求“安装”“更新”或“已有则替换”。同范围同名配置更新原记录，不存在则新增；管理员维护系统共享，普通用户维护个人项。仅粘贴配置不会代表授权，先查看新增/更新、目标版本、变更字段和脱敏地址，再批准保存；需要测试时另行审批，测试会向目标发送凭据。保存未测试或测试失败的配置时会明确报告“未验证连接”。

只提供 URL 时，保留已有 HTTP/SSE 类型、请求头、说明、启用状态、个人使用偏好和工具白名单。请求头对象非空按键更新，显式 `headers: {}` 清空，省略不改；有名称的 headers 更新片段可省略 URL，仅能更新已经存在的配置。更换地址时请确认原认证是否仍应发送到新目标。变更启用状态或白名单需要明确说明，“允许全部工具”会解除原白名单限制。相同配置跳过；审批期间目标版本变化则拒绝覆盖并要求重新准备。多个同名服务按所属范围处理，个人项遮盖共享时会提示。

URL 路径/查询参数和请求头中的凭据由服务端隔离，不进入模型、聊天消息或审批正文；不要在 JSON 块外重复粘贴凭据。更新成功后，下一轮按资源开关、个人偏好与来源优先级生效。仅支持 HTTP/SSE，不通过聊天启动 stdio 程序。详见[聊天 MCP 设计](docs/design-docs/chat-mcp-install.md)。本次增强无数据库结构或依赖变更，更新代码并重启服务即可。

## 停止与更新

停止或重启本地一键脚本启动的服务：

```bash
scripts/shutdown.sh
scripts/restart.sh
```

### 更新项目

先等待活动任务结束，停止服务并备份数据库、数据目录、工作区和配置，再更新代码与依赖：

```bash
scripts/shutdown.sh
git pull --ff-only
uv sync --locked
npm --prefix frontend ci
uv run melonclaw-db-update
scripts/start.sh
```

`melonclaw-db-update` 保留业务数据，只执行尚未完成的升级步骤；不要用 `melonclaw-db-init` 代替升级。手工修改数据库或 Skill 文件后需要重启 Web。Linux 标准部署使用外部配置文件、前端构建和 systemd 服务，按[部署文档](docs/deployment.md)执行。

## 常见问题与使用边界

- **数据库连接失败**：确认 PostgreSQL 已启动、数据库已创建、账号有建表权限，检查 `DATABASE_URL` 格式及特殊字符编码。
- **页面提示没有模型**：到「拓展 → 模型」检查供应商与模型是否启用、Key 是否有效、模型是否支持工具调用。
- **网页搜索或取数失败**：检查相应工具凭据、连接器启用状态、白名单和订阅权限；缺少某项扩展不影响基本聊天。
- **服务未就绪**：查看启动日志与 `/api/ready`。仅支持单实例、单 Web 进程；不能增加多个 workers 或重叠启动新旧服务，定时任务执行器会拒绝第二个实例。
- **执行权限**：当前 `LocalShellBackend` 不是安全沙箱，适合本机开发与受信任使用。文件写入、编辑、删除及 Shell 不逐次审批；已启用且白名单允许的 MCP 工具直接调用。Skill 安装、MCP 测试与安装等操作仍需审批。不要向不可信用户开放宿主机执行能力。
- **凭据与数据**：数据库及备份可能包含业务凭据，请妥善保护。开启 Langfuse 内容采集会发送脱敏后的对话与工具文本，启用前确认业务内容允许外发；可关闭内容采集或整个监控。

`dev` 的身份切换是开发功能，不能作为生产认证与用户隔离方案。部署限制、安全边界和排障细节见[配置说明](docs/configuration.md)及[部署说明](docs/deployment.md)。

前端沿用 14px 正文、中性色与系统蓝：拓展、定时任务与系统管理采用统一紧凑顶栏；定时任务顶栏右侧返回聊天，搜索工具栏右侧新建任务；资源长名称可换行，项目/会话删除采用与技能/连接器一致的居中确认框，技能与连接器采用分区底栏，任务与管理页统一留白及表格样式；窄屏工具栏换行，宽表格在区域内滚动。视觉维护规则见[前端视觉一致性](docs/design-docs/ui-consistency.md)。

### 助手显示名称

后端环境变量 `MELONCLAW_NAME` 设置聊天作者名、头像替代文本和定时任务表单中的执行助手名，未设置或空值默认 `MelonClaw`。名称通过 `GET /api/auth/config` 的 `assistant_name` 公开字段下发，不包含凭据。修改后重启后端并刷新浏览器即可，无需重新构建前端；品牌 Logo 与浏览器标题仍由 `brand` 控制。

聊天工作区采用浅蓝灰会话侧栏、透明底品牌字标/助手头像、彩色玻璃导航图标和一体化白色圆角面板：会话侧栏、会话标题、消息和输入区位于同一外层容器，文件抽屉以同风格的完整圆角面板打开，Header 与内容融合，通过浅蓝留白与聊天区区分；侧栏在面板内部采用纯浅蓝灰底，通过明度差区分白色会话区。桌面与手机自动调整外侧留白。面板顶部使用向下淡出的冰蓝柔光，输入框采用淡蓝白表面与轻高光阴影。用户消息使用浅冰蓝气泡与深蓝灰文字，引用及工具详情使用淡蓝灰底。

文件栏的“全部文件”和“本对话产物”视图均可手动刷新，刷新内容与当前视图一致，产物数量随列表更新。

欢迎页保留个股与公司研究、行业与策略研究、专家观点、研究资料与报告、业绩与市场复盘、债券与信用、宏观/资金/多资产七个分类，采用无说明、无外框的轻量标签，选中时显示浅蓝底；每个标签左侧配 16px 同色线性图标，复用现有 Icon 资源，卡片保持纯文字。保留原引导词卡片的标题、说明、提示词及网格布局，移除卡片装饰图片，每类至少八张，桌面四列、默认展示八张（两行），其余通过“更多问题”展开；窄屏卡片单列。点击仅填入可编辑草稿，不自动发送。顶部保留精简标题与较小 Logo，不重复展示分类标题和操作说明。
